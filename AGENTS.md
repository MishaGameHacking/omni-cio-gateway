## Android

- Минимальная поддерживаемая версия устройства: **Android 15 / API 35** — новое указание OWNER 17.10.2026 заменяет прежнее ограничение API 36.
- Android 14 / API 34 и более старые версии не поддерживаются.
- `minSdk = 35`, `compileSdk = 36`, `targetSdk = 36`. Повышение целевой версии не должно лишать поддержки Android 15 без нового решения OWNER.
- Использовать стабильные публичные API Android 15+. Новые API проверять по версии ОС, если они недоступны на API 35.
- Deprecated, legacy и non-SDK API не использовать, когда в Android 16+ есть актуальная публичная альтернатива.
- Edge-to-edge считать обязательным: системные панели прозрачны, а контент учитывает `safeDrawing`/IME-insets без двойных отступов.
- Навигацию «Назад» строить на современном predictive-back контракте Activity/Compose; не перехватывать `KEYCODE_BACK` и не возвращать старый `onBackPressed()`-код.
- Интерфейс проектировать адаптивно: не полагаться на принудительную ориентацию, фиксированное соотношение сторон или один размер телефона; проверять узкий экран, крупный шрифт, split-screen и большие дисплеи.
- Анимационное состояние читать в draw/graphics-layer фазе, когда возможно, чтобы не пересобирать весь экран на каждом кадре.
- Для длительных пользовательских операций, которые действительно продолжаются вне экрана, применять актуальные API Android 16, включая progress-centric notification, только при наличии реального фонового процесса.
- Матрица опубликованного 0.10.0: чистая установка и запуск preview на API 35 и 36, UI в отдельном debug fixture; обновление с 0.9.0 / 33 на API 36 (исходный APK не устанавливался на API 35). Для следующего функционального выпуска базовый APK — опубликованный 0.10.0 / 34, уже поддерживающий оба API. Не выдавать чистую установку за обновление, а ADB-проверку — за самостоятельную установку через UI updater.
- Основной стек Android: Kotlin, Jetpack Compose, Gradle Kotlin DSL. Другие языки и технологии использовать, когда они действительно нужны задаче.

## Как понимать запросы OWNER

- OWNER описывает, что он хочет получить в приложении; реализация должна следовать этому запросу.
- Не придумывать новые продуктовые требования, экраны, функции, бизнес-правила, интеграции или архитектуру, о которых OWNER не просил.
- Если запрос существенно неоднозначен и выбор повлияет на поведение приложения, UX, данные, архитектуру, безопасность, расходы или внешние интеграции — задать OWNER короткий уточняющий вопрос до реализации.
- После ответа OWNER продолжить работу с учётом уточнения.
- Для мелких технических деталей, не меняющих смысл функции, выбирать наиболее простой, современный и безопасный вариант без лишних вопросов.

## Данные портфеля

- Финансовые суммы, доходности, счета, позиции и структура портфеля не должны подменяться демо-данными, fixtures или выдуманными значениями в рабочем приложении.
- Источник пользовательских инвестиционных данных — T‑Invest API пользователя.
- Для портфеля и аналитики использовать минимальные права: read-only token. Утверждённый план не требует торговых прав и не выставляет поручения от имени пользователя.
- Для получения портфеля ориентироваться на официальные методы T‑Invest API: GetAccounts, GetPortfolio и GetPositions; дополнительные методы подключать только под конкретную функцию.
- Пользовательский T‑Invest API token не коммитить в GitHub и не встраивать в APK как статический секрет.
- Пользователь сам вставляет токен через «Профиль → Аккаунт → Подключение T‑API».
- Пользователь входит в Analyst AI через официальный Telegram OIDC; Telegram ID является стабильным идентификатором аккаунта Analyst AI.
- Проверку T‑Invest токена выполнять read-only запросом GetAccounts; не требовать торговых прав.
- После проверки T‑Invest token хранится только на backend Analyst AI в зашифрованном виде и привязывается к Telegram-аккаунту пользователя; токен не возвращать приложению после сохранения.

## Серверная часть

- Backend Analyst AI размещается на Timeweb и обслуживает Telegram-авторизацию, пользовательские сессии и защищённое хранение пользовательского T‑Invest token.
- Не восстанавливать старый backend, PostgreSQL, web-сайт или прежнюю архитектуру из Git history без прямого запроса OWNER.
- Использовать только необходимые этому приложению серверные ресурсы с минимальными достаточными параметрами и измеряемым запасом на пики пяти пользователей. Запас производительности не увеличивает лимит аккаунтов и не разрешает покупку ресурсов без отдельного согласования.
- Существующие GitHub/Timeweb secrets не раскрывать, не удалять и не менять без явного запроса OWNER.
- Secrets могут оставаться сохранёнными до момента, когда конкретная новая функция действительно начнёт их использовать.

## Закрытая личная установка

- Analyst AI — непубличное приложение максимум для пяти приглашённых уникальных Telegram-аккаунтов. Требуется закрытый список допуска; одного счётчика зарегистрированных пользователей недостаточно. Неприглашённый и шестой новый аккаунт должны отклоняться сервером; разрешённые существующие аккаунты не теряют данные после заполнения лимита. При внедрении сохранить действующих пользователей владельца.
- Лимит относится к пользователям/аккаунтам, а не к числу сессий или серверных процессов. Не создавать отдельный backend-процесс на каждого пользователя: один общий процесс обслуживает от одного до пяти аккаунтов.
- Планировать вычисления, фоновые задания, хранилище и сетевую нагрузку только на 1–5 пользователей/устройств. Не добавлять реплики, автоскейлинг или запас для сотен пользователей без нового прямого запроса OWNER.
- В приложении не будет оплат, подписок, покупок, платных планов, paywall, Billing SDK или платёжных провайдеров. Слово `premium` во внутренней AI-политике обозначает только уровень модели, а не платную подписку пользователя.
- Минимизировать постоянную стоимость обслуживания, но не экономить за счёт авторизации, шифрования, резервного копирования, целостности обновлений и обязательных проверок. Не заказывать платные ресурсы и не совершать оплаты без прямого отдельного разрешения OWNER.

## Работа с репозиторием

- Ветка `main` должна оставаться полностью зелёной: не сливать изменения, пока все применимые проверки последнего SHA не завершились успешно.
- Не считать успешную Android-сборку достаточной, если другая применимая проверка (например Sonar/quality/security) красная.
- Если после merge внешний сервис всё же сообщает ошибку на `main`, считать это инцидентом: остановить дальнейшие изменения и исправить причину в первую очередь.
- Не отключать, не ослаблять и не обходить проверку только ради зелёного статуса; исправлять реальную причину либо документированно подтверждать ложное срабатывание.
- Использовать любые необходимые языки, библиотеки и инструменты, если они действительно нужны для запрошенной функции.
- Сохранять репозиторий минимальным: не возвращать старые файлы и не создавать дублирующие правила/архитектуры.
- После изменений выполнять применимые проверки и исправлять реальные ошибки сборки.
- Не маскировать ошибки фиктивно зелёными проверками.
- Если функция требует решения OWNER, сначала уточнить, а не угадывать.

## AI orchestration

- The approved plan includes a full conversational assistant with allowlisted tools for portfolio explanations and settings. Implement it separately from proactive structured analysis; important strategy changes require confirmation. Track the unimplemented chat in F16 rather than treating the former no-free-prompt rule as a permanent restriction.
- Routine data collection, calculations, caching and risk thresholds must run without LLMs.
- For proactive investment analysis, use the balanced `fast` / `standard` / `premium` gate in `backend/ai_policy.py`; no material change means no background model call. Explicit chat tasks use their own permissions and budget; this background gate must not prevent normal conversation.
- Timeweb AI Gateway model IDs and API keys are server configuration, never APK constants.
- Portfolio display currency uses an explicit RUB / USD / EUR picker; request that currency from T-Invest rather than inventing local FX conversion.

## Spectrum design canon — актуальное направление 0.11.0

- Уточнение OWNER 17.10.2026: не показывать на главной демонстрационную панель «Живые возможности» и каталог технических возможностей («Живые графики», «Анимированные индикаторы» и подобное). После быстрых переходов идёт полезное содержимое портфеля. Нативные иконки, реальные графики и умеренная анимация остаются в функциональных элементах; отдельная витрина их реализации не нужна. Это уточнение заменяет прежнее требование показывать каталог.
- Визуальное направление новой линии Workspace развивает Spectrum: чёрно-синий фон, настоящая объёмная геометрия карточек и иконок, материалы и свет Filament, акценты cyan/blue/violet/rose и понятные подписи.
- Главная вкладка является самостоятельным аналитическим дашбордом с брендом Analyst AI, реальным балансом, быстрыми переходами, объяснением Analyst AI и структурой портфеля.
- Девять обязательных семейств живых элементов: **графики, индикаторы, объёмные элементы управления, материалы и свет, ИИ-ассистент, уведомления, персональные рекомендации, контроль рисков, мировые рынки**.
- Иконки и персонаж — версионированные GLB в APK с общим Filament renderer. Нативные текст, ввод, семантика и фокус сохраняются; геометрия не подменяется плоскими изображениями.
- Каждое семейство имеет собственную осмысленную анимацию: график меняет точки/столбцы, индикатор двигает шкалу, пространственный объект меняет глубину, RGB-элемент переливается, ассистент моргает и реагирует на состояние, уведомление покачивается, рекомендация пульсирует к цели, щит сканирует риск, глобус показывает движение рынка.
- Повторяющаяся анимация разрешена, пока соответствующий элемент видим и Activity находится в состоянии STARTED; при уходе с экрана цикл должен отменяться. Уважать пользовательский переключатель движения и системное отключение аниматоров.
- Не декодировать GIF и не запускать отдельный тяжёлый таймер для каждого кадра. Движение обновлять общим кадровым планировщиком; ограничивать число видимых моделей и не запускать сеть или ИИ из кадровых callback.
- Экран обязательного обновления использует отдельный нативный анимированный фон и большой анимированный предупреждающий знак; движение не должно скрывать текст, прогресс, ошибки или системные действия установки.
- RGB используется как фирменный декоративный и интерактивный язык, но не как единственный индикатор прибыли, убытка, надёжности, рейтинга или уверенности ИИ. Финансовый смысл всегда подписывать текстом и числом.
