# Analyst AI — текущие правила работы

Этот файл хранит только актуальные договорённости OWNER для будущей разработки проекта и заменяет старые правила, планы и архитектурные инструкции из прежней версии проекта.

## Продукт

- Название приложения: **Analyst AI**.
- Текущий package/applicationId: `ru.omnicio.app`; не менять его без прямого запроса OWNER, чтобы не ломать совместимость установленного приложения.
- Основная навигация соответствует продукту Analyst AI: **«Главная», «Портфель», «Риски», «Обучение», «Профиль»**.
- «Рекомендации» и «Сообщения» — внутренние разделы, открываемые с «Главной»; они не должны подменять основные пять вкладок.
- Не использовать в пользовательском интерфейсе названия и композицию экранов, имитирующие приложение брокера. Интеграция T‑Invest является источником данных, а не визуальным брендом Analyst AI.

## Android

- Минимальная поддерживаемая версия устройства: Android 13 / API 33.
- Приложение проектируется для Android 13 и новее.
- `compileSdk` и `targetSdk` поддерживать современными и обновлять по мере развития Android/toolchain.
- Использовать актуальные стабильные публичные Android API.
- Если API устарел и существует современная поддерживаемая альтернатива, использовать современную альтернативу.
- Не использовать deprecated/legacy/non-SDK подход только ради совместимости со старыми Android, если на Android 13+ существует нормальный современный способ.
- Основной стек Android: Kotlin, Jetpack Compose, Gradle Kotlin DSL. Другие языки и технологии использовать, когда они действительно нужны задаче.

## Как понимать запросы OWNER

- OWNER описывает, что он хочет получить в приложении; реализация должна следовать этому запросу.
- Не придумывать новые продуктовые требования, экраны, функции, бизнес-правила, интеграции или архитектуру, о которых OWNER не просил.
- Если запрос существенно неоднозначен и выбор повлияет на поведение приложения, UX, данные, архитектуру, безопасность, расходы или внешние интеграции — задать OWNER короткий уточняющий вопрос до реализации.
- После ответа OWNER продолжить работу с учётом уточнения.
- Для мелких технических деталей, не меняющих смысл функции, выбирать наиболее простой, современный и безопасный вариант без лишних вопросов.

## Данные портфеля

- Финансовые суммы, доходности, счета, позиции и структура портфеля не должны подменяться демо-данными, fixtures или выдуманными значениями в рабочем приложении.
- Источник пользовательских инвестиционных данных — T‑Invest API пользователя.
- Для экранов чтения портфеля использовать минимально необходимые права API; read-only token предпочтителен, пока функция не требует действий с торговыми поручениями.
- Для получения портфеля ориентироваться на официальные методы T‑Invest API: GetAccounts, GetPortfolio и GetPositions; дополнительные методы подключать только под конкретную функцию.
- Пользовательский T‑Invest API token не коммитить в GitHub и не встраивать в APK как статический секрет.
- Пользователь сам вставляет токен через «Профиль → Аккаунт → Подключение T‑API».
- Пользователь входит в Analyst AI через официальный Telegram OIDC; Telegram ID является стабильным идентификатором аккаунта Analyst AI.
- Проверку T‑Invest токена выполнять read-only запросом GetAccounts; не требовать торговых прав.
- После проверки T‑Invest token хранится только на backend Analyst AI в зашифрованном виде и привязывается к Telegram-аккаунту пользователя; токен не возвращать приложению после сохранения.

## Серверная часть

- Backend Analyst AI размещается на Timeweb и обслуживает Telegram-авторизацию, пользовательские сессии и защищённое хранение пользовательского T‑Invest token.
- Не восстанавливать старый backend, PostgreSQL, web-сайт или прежнюю архитектуру из Git history без прямого запроса OWNER.
- Создавать только необходимые этому приложению серверные ресурсы и выбирать минимальные достаточные параметры без запаса мощности.
- Существующие GitHub/Timeweb secrets не раскрывать, не удалять и не менять без явного запроса OWNER.
- Secrets могут оставаться сохранёнными до момента, когда конкретная новая функция действительно начнёт их использовать.

## Приватность экрана

- Скриншоты и запись экрана по умолчанию разрешены.
- В «Профиль → Настройки» пользователь может включить «Запретить снимки экрана»; только тогда приложение включает Android FLAG_SECURE.
- Не включать запрет снимков экрана принудительно на отдельных экранах, если OWNER прямо не попросил обратное.

## Работа с репозиторием

- Ветка `main` должна оставаться полностью зелёной: не сливать изменения, пока все применимые проверки последнего SHA не завершились успешно.
- Не считать успешную Android-сборку достаточной, если другая применимая проверка (например Sonar/quality/security) красная.
- Если после merge внешний сервис всё же сообщает ошибку на `main`, считать это инцидентом: остановить дальнейшие изменения и исправить причину в первую очередь.
- Не отключать, не ослаблять и не обходить проверку только ради зелёного статуса; исправлять реальную причину либо документированно подтверждать ложное срабатывание.
- Использовать любые необходимые языки, библиотеки и инструменты, если они действительно нужны для запрошенной функции.
- Сохранять репозиторий минимальным: не возвращать старые файлы и не создавать дублирующие правила/архитектуры.
- После изменений выполнять применимые проверки и исправлять реальные ошибки сборки.
- Не маскировать ошибки фиктивно зелёными проверками.
- Если функция требует решения OWNER, сначала уточнить, а не угадывать.

## Поэтапные выпуски — договорённость OWNER 15.10.2026

- Выпускать законченные проверенные блоки приложения по мере готовности, не ждать всего проекта или всех декоративных деталей дизайна.
- Перед выпуском устранять реальные ошибки и проходить применимые проверки текущего SHA; промежуточный выпуск не означает обход тестов.
- Для каждого выпуска сообщать версию, рабочий способ обновления, что уже доступно и где это увидеть, что разработано, но не выпущено, что ещё не разработано и известные ограничения.
- Публикацию APK, доступность этого же файла в канале обновления и установку на телефоне различать; не объявлять одно доказательством другого.
- Сохранять подпись, данные и идентификатор установленной preview-линейки `ru.omnicio.app.debug`; повышать versionCode для новых опубликованных байтов. Не выдавать старый APK за новый результат.
- Замечания OWNER по установленной версии использовать для следующих небольших исправлений; не накапливать готовые независимые изменения ради большого релиза.

Этот файл должен оставаться коротким и актуальным. Новые постоянные договорённости OWNER добавлять сюда, а устаревшие — заменять или удалять.

## AI orchestration

- Users do not directly prompt the investment AI. It emits proactive, structured insights.
- Routine data collection, calculations, caching and risk thresholds must run without LLMs.
- Use the balanced `fast` / `standard` / `premium` gate in `backend/ai_policy.py`; no material change means no model call.
- Timeweb AI Gateway model IDs and API keys are server configuration, never APK constants.
- Portfolio display currency cycles RUB -> USD -> EUR by tapping the total; request that currency from T-Invest rather than inventing local FX conversion.

## Spectrum design canon

- Эталон визуального языка — одобренный OWNER 13.10.2026 макет Analyst AI Spectrum: глубокий чёрно-синий фон, стеклянные карточки, RGB-градиенты cyan/blue/violet/rose, яркие 2D-иконки, мягкое свечение и простые понятные подписи.
- Главная вкладка является самостоятельным аналитическим дашбордом с брендом Analyst AI, реальным балансом, быстрыми переходами, объяснением Analyst AI и структурой портфеля.
- RGB используется как фирменный декоративный и интерактивный язык, но не как единственный индикатор прибыли, убытка, надёжности, рейтинга или уверенности ИИ. Финансовый смысл всегда подписывать текстом и числом.
- Интерфейс остаётся 2D и читаемым. Пространственная глубина допускается в фонах, свечении, иконках и карточках; диаграммы не искажать декоративной перспективой.
- Живые эффекты должны быть короткими, конечными и отключаемыми пользователем; уважать системное отключение анимаций и жизненный цикл Activity. Не запускать десятки бесконечных GIF в списках.
- Размеры: сетка 4dp, поля экрана 20dp, радиус основных карточек 24dp, минимальная интерактивная зона 48dp, основной текст не меньше 16sp. Проверять узкие экраны и увеличенный системный шрифт.
- Фирменные компоненты и токены размещать в `ui/spectrum`; новые экраны строить из них, а не создавать локальные несовместимые палитры.
- Обучение объясняет механику и риск простым языком, с официальными источниками и без обещаний доходности. Источники не копировать целиком; хранить собственный текст и ссылки для углубления.
- Рабочее приложение никогда не показывает синтетические балансы, рейтинги, доходности или «лучшие активы» без явной маркировки. Макеты и preview обязаны отличаться от реальных пользовательских данных.
