# Импорт проверенных исследовательских сведений

`research_import` — операторская команда для существующей установки Analyst AI.
Она проверяет подготовленный файл из закрытого операторского каталога и вносит
новые версии сведений в действующую SQLite. В Android нет метода, позволяющего объявить клиентский текст проверенным
фактом. Команда не скачивает веб-страницы, не использует ИИ и не меняет секреты.

## Подготовка файла

Оператор предварительно проверяет первичный документ, право его использования,
объект, дату и существенные числа. `review_id` обозначает запись этой проверки;
сама строка `review_id` не является доказательством правдивости документа.
Не помещайте в файл брокерские токены, данные авторизации или другие секреты.

Корневой объект UTF-8 JSON содержит только `schema_version: 1` и `records`.
Каждая запись содержит ровно `kind`, `subject`, `payload`. Максимум — 1000 записей
и 8 MiB на файл. Повторяющиеся JSON-ключи и нечисловые NaN/Infinity отклоняются.

| kind | subject | Обязательное содержание payload |
| --- | --- | --- |
| `issuer_identity` | Подтверждённый UID инструмента | `instrument_uid`, `issuer_id`, `source`; при наличии доказательства — `issuer_name`, `group_id`, `group_name`. |
| `rating` | ID эмитента или UID выпуска | `agency`, `scale`, `grade`, `subject_kind`, `subject_id`, `status`, `outlook`, `source`. Сохраняется собственная национальная шкала каждого агентства. |
| `statement` | Подтверждённый ID эмитента | `issuer_id`, `sector`, `standard`, `currency`, `period_start`, `period_end`, `values`, `audited`, `source` — поля существующего `Statement` из `credit_evidence.py`. |
| `news_event` | Точный брокерский ID публикации | `broker_news_id`, `event_id`, `news_sha256`, `publication_role`, `primary_source`, `source`. Для primary/repost нужен проверенный первичный источник. |
| `total_returns` | UID инструмента | `instrument_uid`, `basis: "total_return"`, `currency`, `values`, `source`; история должна пройти существующую проверку выровненных доходностей. |

Каждый `source` и `primary_source` содержит `id`, HTTPS `url`, `published_at`,
`checked_at`, `expires_at`, `review_id`. Время должно включать часовой пояс;
действующий источник удовлетворяет `published_at ≤ checked_at ≤ сейчас < expires_at`.
Нельзя продлевать срок актуальности, меняя время получения без новой проверки.
Проверяются начало и конец отчётного периода, публикация после его окончания,
форма валютного кода, названия показателей и конечные числовые значения. Отрицательные
результаты не заменяются нулём. Старый подлинный отчёт может храниться в истории,
но существующие правила актуальности не позволяют считать его текущей оценкой.
Существующая схема `Statement` не хранит отдельный признак консолидации или
масштаб денежной единицы. Оператор должен проверить сопоставимость показателей
и их приведение к одной денежной единице до импорта; команда не заменяет эту
проверку. Полный автоматический разбор отчётности не входит в возможности CLI.

Для новости `news_sha256` получают функцией
`volume_news.observation_fingerprint` от точной брокерской записи. Она связывает
ID, источник, заголовок, содержание, краткое изложение, время и UID инструментов.
Одинаковый заголовок или наиболее ранняя дата не доказывают первоисточник.
Для роли `primary` URL публикации должен совпадать с URL первичного документа.
Записи одного проверенного события используют общий `event_id`.

## Проверка и применение

Оператор помещает уже проверенный пакет в **`reviewed_imports` рядом с действующим
`research_import.py`** — обычно `backend/reviewed_imports` в каталоге установки.
Путь вычисляется от самого модуля и не зависит от рабочего каталога. Параметры CLI
и переменные окружения не могут выбрать другой каталог. Команда сама его не
создаёт. На Linux каталог должен принадлежать пользователю, запускающему импорт,
и иметь права `0700`; для файлов используйте `0600`. На Windows ограничьте ACL
каталога учётной записью оператора. Не коммитьте рабочие пакеты в репозиторий:
это входные данные установки, а не исходный код.

Из корня установки на Linux подготовка **выбранного оператором** пакета выглядит так:

```sh
install -d -m 700 backend/reviewed_imports
install -m 600 /operator/checked/reviewed-evidence.json backend/reviewed_imports/reviewed-evidence.json
```

`--file` принимает только **имя файла**, например `reviewed-evidence.json`: от
1 до 120 латинских букв, цифр, `_` или `-` перед `.json`, первый символ — буква
или цифра. Абсолютные пути, `..`, разделители каталогов, Windows device names,
дополнительные потоки, символические и жёсткие ссылки отклоняются. Нужен обычный
файл; подмена проверенного объекта до открытия отклоняется до чтения. Каталог
также не может быть ссылкой или Windows reparse point. Старое использование
`--file /path/to/file.json` намеренно больше не поддерживается.

В окружении backend запустите проверку пакета из этого каталога; подключение
к БД и сетевые запросы для этого не нужны:

```sh
python -m backend.research_import --file reviewed-evidence.json
```

Успех возвращает JSON с хешем файла, количеством записей, их типами и digest.
Проверка не добавляет факты и не запускает сервер или планировщик. Содержимое
источников и настройки установки в диагностический вывод не включаются.

Примените **тот же** файл к существующей БД штатного backend, передав точный
хеш из результата проверки:

```sh
python -m backend.research_import --file reviewed-evidence.json --apply --database /var/lib/analyst-ai/backend.db --expected-sha256 HASH_FROM_VALIDATION
```

Путь **БД** необходимо сверить с действующим `DATABASE_PATH` установки. Это явный
операторский выбор уже существующей базы для записи, а не каталог входных файлов. Команда не
создаёт новую БД и требует существующую таблицу пользователей. Все записи
проверяются до записи; новый пакет применяется одной транзакцией. Идентичный
повтор не меняет факт, его первое время импорта или версию кэша. Ошибка записи
откатывает весь пакет. Пользователи, портфель и старые факты сохраняются.

После импорта версия evidence инвалидирует кэш досье и исследований; вложенный
брокерский кэш новостей обновляется в пределах своего срока 300 секунд. Обновление
workspace связывает текущие позиции с проверенными эмитентами/группами; очередная
действительная проверка мониторинга учитывает новые рейтинги. История прошлого
анализа не переписывается задним числом. Наличие команды не подтверждает наличие
лицензии на источник, полноту покрытия рынка или факт загрузки конкретных документов.
