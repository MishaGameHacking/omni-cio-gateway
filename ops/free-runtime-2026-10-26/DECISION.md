# Бесплатный runtime для Analyst AI — решение от 26.10.2026

Выбран кандидат **Oracle Cloud Always Free, Ampere A1**. Это дополнительная
площадка до проверки восстановления и работы с реальными внешними сервисами.
Рабочий Timeweb9417611 продолжает обслуживать приложение. OCI не создан,
данные не перенесены, стоимость существующего сервера этим решением не изменена.
Подключённого OCI-аккаунта в доступных интеграциях нет; поиск подходящего плагина
его не обнаружил. Для создания VM нужен доступ к верифицированному аккаунту.

## Как применить к существующему приложению

Начальный профиль: **одна A1, 1 OCPU, 4 ГБ RAM, 50 ГБ boot volume**, Ubuntu 24.04
ARM64 из официального образа. В месяце из 31 дня это 744 OCPU·ч и 2976 ГБ·ч.
Учитывается совокупное потребление всего аккаунта, включая другие VM и тома.
Масштабирование допустимо только после проверки доступного бесплатного остатка.
Создание платного ресурса при отсутствии A1, переход на платный аккаунт,
GPU и Marketplace-образы не входят в этот профиль. Предупреждения бюджета
сами по себе не являются жёстким ограничителем расходов.

Приложение уже использует переносимую схему: Caddy → 127.0.0.1:8080 → один
Uvicorn worker (`owner_app:create_app`) → SQLite на постоянном диске.
Сохраняются systemd restart, отдельный пользователь и приватные каталоги.
Одного процесса достаточно для начальной проверки; несколько независимых
планировщиков с одной базой без блокировки запускать нельзя. Платные модели
и реальные торговые поручения остаются отключены.

Нужна отдельная проверка ARM64 для точных закреплённых Python-зависимостей.
Windows/WSL проверки x86_64 подтверждают существующую сборку, но не ARM64 runtime.
Компиляция Android и разработка остаются на LAPTOP-NPSGA016/WSL; новый сервер
предназначен для работы backend, а не Android CI.

### Выявленные реальные препятствия переносу

1. `deploy/install_owner_backend.py:check_address` требует публичный IPv4 на
   локальном сетевом интерфейсе. В OCI публичный IP сопоставляется private-IP
   объекта VNIC. Проверку нельзя просто удалить: требуется отдельный OCI-путь,
   связывающий подтверждённые instance OCID, VNIC OCID, private/public IP,
   регион, DNS и SSH host key. Текущий установщик пока не готов к OCI.
2. Этот установщик рассчитан на пустую VM и создаёт новый Fernet key. При
   переносе существующей базы новый ключ потеряет доступ к зашифрованным данным.
   Нужен отдельный мигратор с точным сохранением ключа и owner/session binding.
3. Android `BackendConfig.HOST`, callback Telegram, update-policy и адрес APK
   привязаны к действующему hostname. Переносимость технического `.twc1.net`
   имени за пределы Timeweb не доказана. Нужен контролируемый hostname либо
   проверенный переходный proxy; нельзя молча заменить URL в клиенте.
4. Постоянная VM обеспечивает работу без телефона/ноутбука, но не реализует
   ещё не завершённые модули N01–N11. N00 остаётся открытым, N10 требует 30
   фактических торговых сессий.

Первичные документы о сети:
[OCI Public IP](https://docs.oracle.com/en-us/iaas/Content/Network/Tasks/managingpublicIPs.htm),
[IMDSv2](https://docs.oracle.com/en-us/iaas/Content/Compute/Tasks/gettingmetadata.htm).

## Последовательность безопасного ввода

1. В аккаунте проверить home region, доступность A1, остатки бесплатных квот,
   точный образ, условия региона и итоговую стоимость всех выбранных ресурсов.
   Выдать отдельный SSH-ключ; закрыть SSH по списку адресов, открыть HTTPS и
   необходимый ACME HTTP. База и Uvicorn остаются только на loopback.
2. Поднять изолированный runtime с синтетическими данными; проверить ARM64,
   HTTPS, анонимный отказ `/workspace`, Telegram, обновление APK, перезапуск и
   восстановление после рестарта VM. Реальные токены на этой стадии не копировать.
3. Подготовить согласованную SQLite backup через штатный backup API. Вместе
   с зашифрованным архивом сохранить возможность восстановления существующего
   Fernet key; ключ не класть открытым рядом с архивом. Копия должна переживать
   потерю обоих серверов и отказ OCI-аккаунта. Проверить восстановление.
4. Во время переключения остановить все записи и фоновые задания на старом
   узле, снять финальную согласованную копию, сверить контрольные суммы, ключ,
   owner binding и миграцию схемы. Только один узел получает право на запись.
5. Переключить подтверждённый hostname/маршрут. Проверить реальные HTTPS,
   вход владельца, чтение портфеля, автосохранение, full APK hash и повторный
   запуск. При ошибке после новых записей сначала вернуть актуальную базу:
   простой возврат DNS к старой копии приведёт к потере изменений.
6. После подтверждённой работы и восстановления решить судьбу Timeweb.
   Само создание бесплатной VM не прекращает его оплату. Не удалять текущий
   сервер, адрес, ключи или резервные копии в рамках подготовки.

**Фактический статус:** исследование и профиль подготовлены; provisioning,
NAT-адаптер, мигратор, ARM64 runtime, перенос DNS и восстановление в OCI
не выполнены. Бесплатная инфраструктура не даёт гарантии бесперебойности.
