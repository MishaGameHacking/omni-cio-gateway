# 11 — BROKER REPORT ASYNC INTEGRITY

Назначение: обязательные правила для Omni-CIO при вызове `getBrokerReportReconciliation` в runtime v3.9.1 и новее.

## 1. Метод и безопасность

`getBrokerReportReconciliation` — read-only Action. Он:

- запускает формирование официального брокерского отчёта T-Invest;
- получает готовые страницы отчёта;
- сопоставляет сделки отчёта с историей операций;
- сверяет покупки, продажи и комиссии отдельно по валютам;
- не создаёт, не отправляет, не заменяет и не отменяет заявки.

Другие Action-методы не вызывать, если пользователь явно запросил только этот метод.

## 2. Ограничение периода

Параметр `days` должен быть целым числом от `1` до `31` включительно.

Не пытаться обходить ограничение одним запросом. Для большего периода использовать несколько последовательных интервалов на уровне будущей оркестрации, сохраняя каждый результат отдельно и не допуская двойного учёта пересекающихся дат.

## 3. Первый вызов

Рекомендуемый первый вызов:

```text
getBrokerReportReconciliation(days=31, wait_seconds=0)
```

`task_id` не передавать.

Ожидаемый ответ, если отчёт не готов мгновенно:

- `status=pending`;
- `version=3.9.1` или новее;
- `report_generation.status=pending`;
- `report_generation.task_id` — непустая строка;
- `complete=false`.

`task_id` нужно сохранить без изменения.

## 4. Повторный вызов

Повторный вызов выполняется с тем же `task_id`:

```text
getBrokerReportReconciliation(
  days=31,
  wait_seconds=0,
  task_id="<полученный task_id>"
)
```

Нельзя запускать новую задачу вместо проверки существующей, если валидный `task_id` уже получен для этого периода.

## 5. Значение ошибки T-Invest 30058

Код `30058`, а также эквивалентное сообщение `task not completed yet`, означает, что асинхронная задача ещё выполняется.

Для этого состояния:

- вернуть `pending`, а не `error`;
- сохранить тот же `task_id`;
- не объявлять компонент сломанным;
- `complete=false`;
- разрешить последующий повторный вызов.

Только подтверждённый код `30058` или его точный семантический эквивалент можно преобразовывать в `pending`. Другие исключения нельзя скрывать.

## 6. Когда отчёт готов

После получения отчёта:

- загрузить все страницы до фактического конца;
- показать `pagination`;
- проверить `pagination.truncated`;
- удалить точные дубли;
- сопоставить сделки по `trade_id`, используя безопасный fallback только при необходимости;
- считать покупки, продажи и комиссии отдельно по каждой валюте;
- не складывать брокерскую, биржевую и клиринговую комиссии повторно;
- показать reconciliation, quality, component_errors и warnings.

`complete=true` допустим только при полном наборе обязательных компонентов и успешных проверках.

## 7. Статусы

### pending

Отчёт ещё формируется. Это штатное состояние, а не финансовый результат.

### partial

Полезная часть отчёта получена, но есть неполнота, ошибка страницы, пагинации, сопоставления или контроля качества. Нельзя делать окончательные выводы.

### ok

Обязательные компоненты загружены и проверки качества пройдены. Статус `ok` сам по себе не заменяет проверку `complete`.

## 8. Формат ответа пользователю

Если пользователь не ограничил поля, показывать:

1. `status`, `version`, `retrieved_at`;
2. маскированный счёт;
3. период;
4. `report_generation.status` и `task_id`;
5. `pagination`;
6. покупки и продажи по валютам;
7. комиссии по видам и валютам;
8. сопоставление отчёта и операций;
9. `quality`;
10. `complete`;
11. `component_errors`;
12. `warnings`;
13. `trading_methods`.

Если пользователь запросил конкретный список полей, выводить только его.

## 9. Запрещённые выводы

Пока `pending` или `complete=false`, нельзя:

- утверждать, что отчёт пуст;
- утверждать, что операций не было;
- рассчитывать окончательную прибыль или доходность;
- считать отсутствие строк подтверждённым нулём;
- давать инвестиционную рекомендацию на основании незавершённого отчёта.

## 10. Проверка после релиза

После merge и production deploy:

1. Вызвать `gatewayHealth`.
2. Подтвердить актуальную версию и capability `broker_report_async_integrity`.
3. Выполнить первый вызов без `task_id` и с `wait_seconds=0`.
4. Подтвердить непустой `task_id`.
5. Повторить вызов с этим `task_id`.
6. Убедиться, что `30058` остаётся `pending`.
7. После готовности проверить пагинацию, reconciliation, quality и `complete`.

## 11. Секреты

Не выводить и не сохранять:

- полный ID счёта;
- T-Invest token;
- Gateway API key;
- Authorization header;
- необработанные персональные данные отчёта.
