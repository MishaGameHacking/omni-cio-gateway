14 — REPRODUCIBLE CI AND SECURITY BASELINE

Purpose
-------
Define the current fail-closed CI/security contract for the Omni-CIO Custom GPT + read-only Gateway repository.

Runtime invariants
------------------
- Render entrypoint: `app:app`.
- User-facing Gateway Actions: exactly 14 GET operations.
- `trading_methods=false`.
- No order create/submit/replace/cancel/stop-order methods.
- No withdrawal/transfer methods.
- Account identifiers are masked.
- Tests do not call real T-Invest or production Render endpoints.

Dependency supply chain
-----------------------
- Human-edited direct constraints: `requirements.in`, `requirements-dev.in`.
- Generated locks: `requirements.txt`, `requirements-dev.txt`.
- Locks pin exact direct/transitive versions and SHA-256 hashes.
- Production/CI install with `--require-hashes`.
- Generated locks are never edited manually.
- Dependency upgrades use a dedicated compatibility PR, regenerated locks and full Regression Shield.
- The private `t-tech-investments` package must resolve from the configured T-Bank package index; an unrelated public package is not a substitute.
- Windows dependency CI uses an ephemeral pip CA bundle: pip's vendored certifi roots plus the source-controlled Russian Trusted Root CA after exact DER SHA-256 pin verification.
- The bundle is published only through `PIP_CERT`; certificate and hostname verification remain enabled and ordinary public certifi roots remain present.
- CI does not require or mutate `LocalMachine` certificate stores. The reviewed OWNER/Administrator provisioner remains an optional system-trust recovery boundary for non-pip consumers.
- Every self-hosted Windows job that installs `windows-requirements-dev.txt` must run the read-only T-Bank CA trust preflight in that same job before pip dependency installation; `GITHUB_ENV` state from another job is not reusable authority.
- Certificate/hostname verification and package-source substitution are forbidden recovery shortcuts.

GitHub Actions supply chain
---------------------------
- External Actions pin full 40-character commit SHA.
- Workflow/tag upgrades require a dedicated compatibility check.
- A historical green workflow run does not replace exact-head validation after the branch changes.

Quality gates
-------------
Regression Shield must include blocking checks for:

- repository layout/read-only contract;
- compile;
- Ruff correctness baseline;
- formatting baseline;
- mypy baseline;
- pytest;
- branch-inclusive coverage >=60%;
- dependency audit;
- Bandit medium/high SAST findings;
- secret scan;
- stable `app:app` and 14-GET OpenAPI contract.

Checks must fail closed. Broad `continue-on-error` is not accepted for merge-critical quality/security gates.

Repository layout guard
-----------------------
`scripts/check_repository_layout.py` verifies:

- required current bot/runtime/configuration files;
- `app:app`;
- read-only marker;
- absence of obsolete one-time workflows;
- absence of forbidden broker write surfaces in runtime Python;
- absence of retired duplicate final-review scenario publisher paths.

The layout guard intentionally focuses on current product invariants rather than preserving historical integrations.

Money/data integrity
--------------------
- Exact decimal representation for money.
- Currencies remain separate without verified FX + timestamp.
- No duplicate counting of top-level payment, nested commission, child operations or embedded trades.
- Partial/truncated/stale/contradictory data fail closed.
- last price is not an executable guarantee.

Accepted narrow code-loading exception
--------------------------------------
`broker_report_reconciliation/__init__.py` loads only checked-in `.pyfrag` files from a fixed package directory. Bandit B102 is narrowly documented on that fixed loader. External request/document/environment values must never control loader path or source text.

Treat changes in `_parts/*.pyfrag` as runtime-code changes. A future refactor may remove the dynamic loader, but until then it remains part of the tested production runtime.

Self-hosted Windows runner
--------------------------
Regression Shield currently depends on the trusted repository runner labels:

`[self-hosted, Windows, X64, omni-cio-ci]`

Operational requirements:

- runner is persistent/non-ephemeral;
- exact runner identity is checked;
- diagnostics are read-only;
- diagnostics do not emit credentials, registration tokens, raw `.runner` content, local paths or secret values;
- diagnostic failures are distinct from code-test failures;
- a queued job is not successful validation;
- merge remains blocked until the complete exact-head Regression Shield finishes.

Administrative recovery is documented in `docs/operations/SELF_HOSTED_WINDOWS_RUNNER_SERVICE.md`.

Secret boundary
---------------
Never commit:

- `TINVEST_TOKEN`;
- value of `GATEWAY_API_KEY`;
- Authorization headers;
- full account IDs;
- private broker reports/positions/operations as configuration data;
- runner credentials/registration tokens.

Failure policy
--------------
Timeouts, dependency resolution failures, audit findings, secret findings, test failures or coverage regression block merge. They do not authorize weakening the safety contract or bypassing checks.

Production boundary
-------------------
Green CI validates repository state, not the external production environment. After relevant backend/OpenAPI changes separately verify Render health/auth/route behavior and GPT Preview according to `docs/operations/RELEASE_CHECKLIST.md` and `gpt/SETUP_INDEX.md`.
