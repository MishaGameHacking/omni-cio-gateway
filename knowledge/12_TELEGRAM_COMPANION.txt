12 — TELEGRAM COMPANION v4.0.0

Purpose
-------
Telegram Companion is a separate read-only interface to the existing Omni-CIO Gateway. It does not replace Custom GPT and does not share ChatGPT conversation history. Both interfaces call the same protected gateway.

Architecture
------------
Telegram user -> Telegram Bot API -> telegram_bot.app:app -> Omni-CIO Gateway -> T-Invest API

The Telegram service is deployed separately from the gateway so that a Telegram outage cannot break the main API. Use `render.telegram.yaml`; do not change the gateway start command `app:app`.

Security invariants
-------------------
- Telegram commands are read-only.
- `trading_methods=false`.
- No order placement, replacement, cancellation, stop order, or submission command exists.
- The webhook requires `X-Telegram-Bot-Api-Secret-Token` and compares it with `TELEGRAM_WEBHOOK_SECRET`.
- Only private chats are accepted.
- Only IDs from `TELEGRAM_ALLOWED_USER_IDS` may call the gateway.
- Telegram updates are deduplicated by `update_id`.
- Per-user requests are rate limited.
- Gateway calls use Bearer `OMNI_GATEWAY_API_KEY` and GET only.
- Tokens, API keys, raw Authorization headers, and full account IDs must never be logged or returned.
- Account identifiers are masked again before Telegram output.

Commands
--------
/help
/health
/connection
/portfolio
/cash
/analytics
/operations [days]
/report
/report_status [task_id]

`/report` starts a 31-day official T-Invest report with `wait_seconds=0`. When the gateway returns `pending`, the task ID is cached in memory for convenience and is also shown to the user. `/report_status` reuses the cached task ID or accepts an explicit ID. In-memory task IDs can be lost after a service restart, so the user-visible task ID remains the recovery mechanism.

Automatic setup
---------------
On startup, when configuration is complete and `TELEGRAM_AUTO_CONFIGURE=true`, the service calls Telegram `getMe`, `setMyCommands`, and `setWebhook`. The webhook URL is derived from `TELEGRAM_PUBLIC_BASE_URL` or Render's `RENDER_EXTERNAL_URL`. Setup failures do not expose secrets; `/health` returns a degraded bootstrap status.

Required environment variables
------------------------------
TELEGRAM_BOT_TOKEN
TELEGRAM_WEBHOOK_SECRET
TELEGRAM_ALLOWED_USER_IDS
OMNI_GATEWAY_URL
OMNI_GATEWAY_API_KEY (or fallback GATEWAY_API_KEY)

Optional settings
-----------------
TELEGRAM_AUTO_CONFIGURE
TELEGRAM_PUBLIC_BASE_URL
TELEGRAM_REQUEST_TIMEOUT_SECONDS
TELEGRAM_MAX_RESPONSE_CHARS
TELEGRAM_MIN_REQUEST_INTERVAL_SECONDS

Versioning
----------
System release: v4.0.0 Telegram Companion.
Gateway API component remains v3.9.1 until its own public contract changes.
Telegram service health reports version 4.0.0 and entrypoint `telegram_bot.app:app`.

Testing
-------
Tests must use fake Telegram and gateway clients. No test may contact Telegram, Render, or T-Invest. Required cases: health without secrets, startup webhook setup, invalid webhook secret, unauthorized user, GET-only gateway command, report task reuse, duplicate update suppression, and `trading_methods=false`.
