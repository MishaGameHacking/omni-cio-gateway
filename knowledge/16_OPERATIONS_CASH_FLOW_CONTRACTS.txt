16 — OPERATIONS AND CASH-FLOW CONTRACTS V1

Status: PR-07 implementation rules.

1. Scope

OperationsAnalyticsV1 normalizes the existing read-only operations analytics
response. It does not expose raw brokerage operations, change the current Action
response, or add any broker call.

2. Required safety invariants

- trading_methods must be explicitly false;
- account identifier must already be masked;
- source quality must state read_only=true;
- no_cross_currency_aggregation must be true;
- all timestamps must be timezone-aware and normalized to UTC;
- all money uses finite Decimal values;
- required counters cannot be invented when absent.

3. Category coverage

Every currency summary contains all categories:

deposits, withdrawals, purchases, sales, broker_commissions, service_fees,
margin_fees, other_fees, taxes, coupons, dividends, bond_redemptions and other.

4. Arithmetic

For every category bucket:
- gross_amount = inflow + outflow;
- net_payment = inflow - outflow.

For every currency:
- net_external_flow = deposits - withdrawals;
- turnover = purchases + sales.

Category reconciliation:
- difference = categories_net_payment - operations_net_payment;
- zero difference requires status=passed;
- non-zero difference requires status=failed and aggregate status=warning.

5. Completeness

VERIFIED / COMPLETE requires:
- source status ok;
- source complete=true;
- pagination complete;
- reconciliation confirmed;
- zero invalid date rows;
- zero invalid money rows;
- no warning or error DataIssue.

Informational issues such as removed exact duplicates do not downgrade verified
data. Unknown types, unstable instrument identity or truncated activity downgrade
to partial. Invalid money, invalid dates, pagination truncation, reconciliation
failure or component errors downgrade to degraded/incomplete.

6. Double-count controls

Commission protection must remain applied. Canonical cash totals use only
executed top-level operation.payment. Nested commission values, embedded child
operations and embedded trades are diagnostics and are never added again.

7. Privacy

The normalized contract may contain aggregate instrument activity already
present in the read-only response, but it must never contain:
- API tokens or headers;
- full account identifiers;
- raw upstream exception messages;
- raw component error payloads;
- hidden cross-currency conversions.

8. Runtime compatibility

PR-07 is contracts plus adapter only. Runtime shadow integration, if needed,
requires a separate reviewed change. Existing GPT Actions, OpenAPI schemas,
Gateway version and app:app entrypoint remain unchanged.

9. Next step

PR-08 builds advanced portfolio analytics on verified normalized contracts. Any
actionable calculation must first pass the PR-06 portfolio decision-quality
gate and must abstain when required inputs are missing or degraded.
