### Асинхронный цикл отчёта

1. Первый вызов `getBrokerReportReconciliation` выполняется без `task_id`.
2. При `wait_seconds=0` шлюз запускает формирование и сразу возвращает `pending` и настоящий `task_id`.
3. Следующий вызов передаёт тот же `task_id`.
4. Пока T-Invest возвращает `30058`, состояние остаётся `pending`.
5. После готовности загружаются страницы отчёта и выполняется сверка.
6. `complete=true` допустим только после успешной загрузки и проверок качества.

Официальный API принимает период отчёта не более 31 дня, поэтому `days` ограничен `1..31`.

## 6. Денежные расчёты

- Все суммы считать отдельно по каждой валюте.
- Не складывать валюты без подтверждённого курса и времени FX-оценки.
- Использовать безопасную десятичную арифметику.
- Не складывать повторно `operation.payment`, nested commission, child operations и embedded trades.
- Брокерские, биржевые, клиринговые и сервисные комиссии хранить раздельно, если источник их различает.
- Для облигаций учитывать номинал, цену в процентах номинала и НКД.
- Количество инструментов и количество лотов не путать.

## 7. Планы по HTML-отчётам СберИнвестиций

Для веб-кабинета запланирован безопасный импорт официального HTML-отчёта брокера.

### Обязательные требования

- Удалить фото, скриншоты и OCR из основного сценария.
- Принимать только официальный HTML-файл отчёта.
- Не исполнять HTML, JavaScript или CSS из файла.
- Проверять MIME, кодировку, размер, обязательные разделы и структуру таблиц.
- Считать SHA-256 и предотвращать повторный импорт.
- Автоматически определять произвольный период.
- Показывать preview и предупреждения до построения аналитики.
- Требовать подтверждение пользователя после проверки.
- Маскировать номер счёта.
- Не логировать позиции, суммы, номера сделок и персональные данные.
- По возможности разбирать файл в браузере.
- Если используется сервер, получить согласие, не хранить исходный файл после обработки и дать полное удаление данных.

### Статусы распознавания

- `Формат брокера распознан`;
- `Формат распознан частично`;
- `Файл не поддерживается`;
- `Подлинность подтверждена электронной подписью` — только после реальной криптографической проверки.

### Источник истины

HTML-отчёт брокера является источником истины для состава портфеля на конец периода, денежных остатков, сделок, комиссий, купонов, дивидендов и периода. MOEX ISS применяется только для отдельной текущей рыночной оценки.

Нужно явно разделять:

- `По данным брокера на конец отчётного периода`;
- `Текущая рыночная оценка`.

## 8. Нормализованная модель отчёта

### Метаданные

- брокер;
- тип счёта;
- маскированный ID счёта;
- дата начала и конца;
- торговая площадка;
- дата формирования.

### Денежное движение

- начальный остаток;
- пополнения;
- выводы;
- расчёты по сделкам;
- брокерская комиссия;
- биржевая комиссия;
- налоги и удержания;
- купоны и дивиденды;
- конечный остаток;
- валюта.

### Портфель ценных бумаг

- название;
- ISIN;
- код или тикер;
- эмитент;
- тип;
- валюта;
- количество, цена, стоимость и НКД в начале и конце периода;
- плановые зачисления и списания.

Первичный идентификатор — ISIN, затем код инструмента, название только как резерв.

### Сделки

- дата и время сделки;
- дата расчётов;
- инструмент и код;
- валюта;
- покупка или продажа;
- количество;
- цена;
- сумма;
- НКД;
- брокерская и биржевая комиссия;
- номер сделки;
- статус исполнения.

## 9. Формулы и показатели веб-кабинета

- стоимость позиции = количество × цена;
- стоимость облигации = количество × номинал × цена в процентах / 100;
- полная стоимость облигации = рыночная стоимость + НКД;
- чистый внешний поток = пополнения − выводы;
- результат периода = стоимость на конец − стоимость на начало − чистый внешний поток.

Показывать источник строк, формулу, значение брокера и рассчитанное значение.

Не рассчитывать точную среднюю цену покупки, реализованную или нереализованную прибыль и точную доходность, если данных выбранного периода недостаточно. Вместо догадки показывать: `Недостаточно данных в выбранном отчёте` и указывать, какой предыдущий отчёт нужен.
