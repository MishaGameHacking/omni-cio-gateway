Политика обработки персональных данных

OmniCIO Personal · omnicio.ru · версия 2026-10-05-v8

1. Оператор и область действия

Оператор: __OMNICIO_OPERATOR_NAME__.

Контакт по вопросам персональных данных: __OMNICIO_OPERATOR_EMAIL__.

Политика применяется к обработке персональных данных пользователей сайта omnicio.ru и приложения OmniCIO Personal. Система технически поддерживает несколько изолированных пользователей. Создание новых аккаунтов допускается только когда серверная регистрация явно включена; текущий временный live-test лимит — два пользовательских аккаунта. Каждый новый пользователь, успешно прошедший VK ID и принявший актуальные документы, занимает один доступный слот. После заполнения лимита новые аккаунты не создаются; уже зарегистрированные пользователи продолжают входить через свои VK ID.

2. Принципы и правовые основания

Обработка выполняется для конкретных заранее определённых целей, в объёме, необходимом для работы сервиса, с соблюдением Федерального закона от 27.07.2006 № 152-ФЗ «О персональных данных». В применимой части основаниями являются согласие субъекта персональных данных и обработка, необходимая для заключения и исполнения пользовательского соглашения по инициативе пользователя.

Согласие на обработку персональных данных оформляется отдельно от иных документов. Отказ от обязательной для входа обработки означает невозможность создать или использовать аккаунт, поскольку без подтверждённой VK ID identity и защищённой сессии сервис не может определить пользователя и изолировать его данные.

3. Какие данные обрабатываются

  • подтверждённый идентификатор VK ID, полученный сервером после OAuth 2.1 Authorization Code flow с PKCE;
  • внутренний UUID и девятизначный ID профиля, статус аккаунта и роль user;
  • технические сведения сессии: digest сессионного токена, время создания, последней активности, истечения и отзыва;
  • защищённый HMAC/хеш сетевого адреса запроса, используемый для безопасности, аудита и фиксации согласий;
  • версии юридических документов, факт и время их принятия;
  • при добровольном подключении T-Invest — выбранный контур, идентификатор и отображаемое имя брокерского счёта, а также API credential в зашифрованном виде;
  • полученные через read-only T-Invest API сведения о портфеле, денежных остатках, блокировках, инструментах и внутренние наблюдения по истории операций, необходимые для сверки и доказательной аналитики;
  • добровольно заданные пользователем параметры инвестиционного профиля: резерв, планируемые снятия, горизонт, допустимая просадка, требование к ликвидности и разрешение либо запрет рассматривать инструменты ниже инвестиционного уровня;
  • минимальные технические журналы безопасности и диагностики.

Для входа OmniCIO не запрашивает паспорт, СНИЛС, ИНН, банковскую карту, биометрические данные, данные о здоровье или пароль от VK.

4. Цели обработки

  • регистрация и аутентификация пользователя через VK ID;
  • создание и поддержание защищённой пользовательской сессии;
  • изоляция данных одного пользователя от данных других пользователей при последующем увеличении лимита;
  • исполнение пользовательских правил, обработка обращений, блокирование и удаление аккаунта;
  • защита от злоупотреблений, расследование инцидентов и диагностика;
  • по отдельному действию пользователя — подключение его собственного брокерского счёта через T-Invest API, отображение полученных от провайдера данных и ежедневное read-only сохранение доказательных снимков для сверки изменений;
  • хранение версий инвестиционных ограничений, заданных самим пользователем, для последующих аналитических сценариев без предоставления системе торговых полномочий.

5. Внешние сервисы и порученная обработка

  • Timeweb Cloud — инфраструктура приложения и PostgreSQL. Производственная база выбирается в российском регионе; первичная запись, систематизация, накопление, хранение, уточнение и извлечение персональных данных граждан РФ выполняются с использованием базы данных на территории РФ.
  • VK ID — внешний поставщик аутентификации. OmniCIO получает подтверждённый идентификатор аккаунта через защищённый OAuth/PKCE flow. Пароль VK в OmniCIO не передаётся; access/refresh tokens VK ID не используются как сессия OmniCIO и не сохраняются после завершения входа.
  • T-Bank / T-Invest API — используется только если пользователь самостоятельно подключает свой API credential. Credential проверяется у провайдера и затем хранится только в зашифрованном виде; сохранённое значение не возвращается браузеру.

OmniCIO не продаёт персональные данные, не использует их для сторонней рекламы и не предоставляет одному пользователю данные другого пользователя.

6. Безопасность

Сайт работает по HTTPS. OAuth state и PKCE verifier помещаются в краткоживущий зашифрованный Secure/HttpOnly/SameSite cookie. Пользовательская сессия хранится у клиента в Secure/HttpOnly cookie, а в базе — только digest токена. Чувствительный T-Invest credential шифруется отдельным серверным ключом. Сервер не принимает от браузера user_id как источник полномочий: пользователь определяется по действующей серверной сессии.

Для новых аккаунтов действует серверный лимит регистрации и атомарная проверка capacity в транзакции базы данных. Роль пользовательского аккаунта ограничена значением user; публичная авторизация не предоставляет административные права и не предоставляет право исполнять торговые операции.

7. Сроки хранения

OAuth/PKCE flow хранится только в течение короткого срока, установленного серверной конфигурацией, и удаляется после callback. Сессии имеют ограниченный срок, могут продлеваться при активности и немедленно отзываются при выходе или защитном действии.

T-Invest credential и производные read-only сведения о подключённом брокерском счёте хранятся до отключения интеграции или удаления пользовательского аккаунта; при отключении T-Invest удаляются сохранённый credential, внутренние снимки портфеля, наблюдения истории операций, состояние синхронизации и журналы соответствующих ежедневных задач. Версии инвестиционного профиля не зависят от подключения брокера и хранятся до удаления аккаунта либо до возникновения иного законного основания для их удаления.

При самостоятельном удалении аккаунта через настройки OmniCIO в одной серверной транзакции удаляются профиль пользователя и связанные с ним привязка VK ID, пользовательские сессии, записи согласий, версии инвестиционного профиля и подключение T-Invest вместе с производными пользовательскими финансовыми данными.

Минимальный технический факт удаления может сохраняться в журнале безопасности без идентификатора пользователя, VK ID, IP-адреса, брокерских данных или иных данных, позволяющих продолжить использование удалённого аккаунта. Иные журналы безопасности хранятся только в объёме и сроки, необходимые для защиты сервиса и выполнения применимых обязанностей, после чего удаляются или обезличиваются.

Для восстановления работы после сбоя создаются физические резервные копии базы данных в Timeweb Cloud. Настроено ежедневное копирование с ротацией семи последних копий; при исправном расписании это примерно неделя истории. Дополнительно сохраняются до четырёх последних недельных копий. Недельная история заполняется постепенно; пропущенные недели задним числом не восстанавливаются. Старая недельная копия удаляется только после подтверждения новой. Первая контрольная копия удаляется после подтверждения более новой автоматической копии. Сбой копирования может увеличить срок хранения прежних копий; состояние расписания, даты последних копий и число подтверждённых недельных копий показаны в настройках сайта.

Удаление аккаунта или отключение интеграции немедленно удаляет соответствующие сведения из рабочей базы, но их прежнее состояние может оставаться в резервных копиях до ротации. Копии не используются для обычной работы сайта или восстановления аккаунта по желанию пользователя. Перед возобновлением сервиса из аварийной копии оператор обязан повторно применить удаления, совершённые после её создания. Доступ к копиям ограничен оператором и средствами инфраструктуры; проверка восстановления рабочей копии пока не завершена.

8. Права пользователя

Пользователь вправе получать сведения об обработке своих персональных данных, требовать их уточнения, блокирования или уничтожения при наличии предусмотренных законом оснований, отозвать согласие и обратиться по адресу __OMNICIO_OPERATOR_EMAIL__. Отзыв согласия не затрагивает обработку, которую закон разрешает продолжать на ином основании.

Запрос рассматривается с соблюдением сроков и требований, установленных Федеральным законом № 152-ФЗ. Пользователь также может самостоятельно удалить аккаунт в разделе «Настройки». Для защиты от случайного удаления система требует повторно ввести текущий девятизначный ID профиля и отдельно подтвердить необратимость операции. После успешного удаления текущая сессия прекращается, пользовательский слот освобождается, а восстановление удалённого аккаунта невозможно.

9. Изменения политики

При изменении целей, состава данных, числа доступных аккаунтов, провайдеров или финансового функционала публикуется новая версия документа. Если изменение требует нового согласия, прежнее согласие не считается автоматически распространяющимся на новую цель обработки.
