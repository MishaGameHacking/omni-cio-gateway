# Omni-CIO Portfolio GPT — reset scope v1

Дата: 2026-08-01
Статус: текущая обязательная продуктовая спецификация

## 1. Единственный продукт

Omni-CIO — это существующий Custom GPT в разделе ChatGPT «Мои GPT».

Единственный пользовательский интерфейс — диалог с этим GPT внутри ChatGPT.

В текущий продукт не входят:

- отдельный сайт или web-кабинет;
- мобильное приложение;
- собственная языковая модель;
- Telegram-бот, Telegram-публикации и Telegram API;
- публичный сервис для других пользователей;
- автономное управление деньгами;
- создание, изменение или отмена заявок.

GitHub используется как источник истины для Instructions, Knowledge, OpenAPI, Gateway, тестов и документации. Gateway остаётся минимальным защищённым API-слоем между Custom GPT и T-Invest.

## 2. Цель первой завершённой версии

По команде владельца Omni-CIO должен:

1. Получать фактический портфель, позиции, деньги и операции через существующие read-only Actions.
2. Проверять свежесть, полноту, валюту, идентификаторы, лоты и качество данных.
3. Анализировать структуру портфеля, концентрацию, диверсификацию, ликвидность и основные риски.
4. Проверять свежие новости и корпоративные события по активам портфеля.
5. Учитывать кредитные рейтинги и долговые риски облигаций.
6. Находить кандидатов для размещения свободных денег среди доступных в T-Invest инструментов.
7. Предлагать действия: держать, ждать, сократить, продать, увеличить или купить.
8. Всегда рассматривать вариант «ничего не делать».
9. Показывать расчёт предполагаемого объёма, лотов, комиссии, остатка денег и влияния на структуру.
10. Отделять факты, расчёты, выводы и сценарии.
11. Работать только по командам пользователя, без фонового и автономного исполнения.

## 3. Неприкосновенные ограничения

- `trading_methods=false`.
- Пользовательские Gateway Actions остаются GET-only.
- `app:app` остаётся стабильным entrypoint.
- Запрещены order create, replace, cancel, stop-order, cash transfer, securities transfer и withdrawal.
- Секреты не хранятся в GitHub, Instructions, Knowledge, логах или ответах.
- Полный account ID не выводится.
- Нельзя выдавать stale, partial, contradictory или truncated данные за надёжную основу рекомендации.
- Нельзя обещать доходность, сохранность капитала, дивиденды или отсутствие дефолта.
- Одна новость, один рейтинг или технический сигнал не являются достаточным основанием для сделки.
- Деривативы, маржинальные позиции и short не используются в обычных рекомендациях.

## 4. Компоненты продукта

```text
Пользователь
  -> существующий Custom GPT Omni-CIO
       -> строгие Instructions
       -> минимальный набор Knowledge
       -> Web Search для свежих публичных фактов
       -> Data Analysis для расчётов
       -> GPT Actions
       -> защищённый Gateway
       -> T-Invest и разрешённые официальные источники
```

### Custom GPT

Отвечает за:

- понимание команды;
- выбор минимально необходимого Action;
- последовательность анализа;
- объяснение результата;
- сравнение альтернатив;
- формирование рекомендации с ограничениями и условиями отмены.

### Gateway

Отвечает за:

- авторизацию;
- получение приватных брокерских данных;
- маскирование account ID;
- нормализацию и точные денежные расчёты;
- quality/freshness checks;
- server-side allowlist;
- отсутствие write methods.

### GitHub

Хранит:

- `gpt/INSTRUCTIONS_COMPACT.md` — текст для GPT Editor;
- `gpt/INSTRUCTIONS.md` — расширенную каноническую версию;
- `gpt/CONFIGURATION.md` — имя, описание, capabilities и starters;
- `gpt/ACTIONS_CATALOG.md` — фактические Actions;
- `gpt/PERSONAL_PORTFOLIO_POLICY_TEMPLATE.md` — профиль владельца;
- `gpt/PORTFOLIO_GPT_ACCEPTANCE_V1.md` — end-to-end приёмку;
- Gateway, OpenAPI, тесты и документацию.

## 5. Основные пользовательские режимы

### 5.1. Полный анализ портфеля

Команда: «Проанализируй мой портфель».

Результат:

- качество и время данных;
- стоимость по валютам;
- свободные деньги;
- доли активов и классов;
- крупнейшие позиции;
- концентрация по эмитентам и секторам;
- облигационные и кредитные риски;
- новости по существенным позициям;
- три варианта действий;
- конкретный план наблюдения.

### 5.2. Размещение свободных денег

Команда: «У меня свободно N рублей. Что разумно купить?».

До поиска кандидатов GPT обязан проверить портфель, свободные деньги, целевую структуру, лимиты и уже имеющиеся риски.

Кандидаты сравниваются по:

- роли в портфеле;
- качеству эмитента;
- кредитному рейтингу;
- ликвидности и spread;
- сроку и процентному риску;
- оценке/доходности;
- новостям и корпоративным событиям;
- диверсификационному эффекту;
- размеру лота и доступной сумме.

### 5.3. Проверка позиции

Команда: «Что делать с [активом]?».

Ответ обязан содержать:

- фактическое состояние позиции;
- роль в текущем портфеле;
- свежие новости;
- основные финансовые/кредитные риски;
- альтернативы hold/reduce/sell/wait;
- условия пересмотра;
- уровень уверенности.

### 5.4. Ребалансировка

Команда: «Настрой диверсификацию».

GPT сравнивает текущую структуру с личной политикой владельца и показывает:

- отклонения;
- приоритеты исправления;
- минимальный вариант;
- умеренный вариант;
- более глубокую перестройку;
- ожидаемую структуру после каждого варианта.

### 5.5. Новости и риски

Команда: «Проверь новости по моему портфелю».

GPT рассматривает только релевантные позиции и события, отделяет факт от мнения, указывает дату, источник, горизонт влияния и необходимость действия.

## 6. Обязательный алгоритм ответа

1. Классифицировать задачу.
2. Определить минимально необходимый набор Actions.
3. Получить приватные данные через Gateway.
4. Проверить freshness, completeness, currency, identity, pagination и component errors.
5. При недостаточном качестве остановить рекомендацию и перечислить недостающие данные.
6. Выполнить deterministic calculations.
7. При необходимости получить свежие публичные сведения через Web Search.
8. Проверить релевантные рейтинги, новости и корпоративные события.
9. Сравнить минимум три варианта: ничего не делать, ограниченное изменение, более существенное изменение.
10. Применить личные лимиты и риск-фильтры.
11. Сформировать ясный вывод и конкретные следующие действия.
12. Указать дату данных, источники, ограничения и условия пересмотра.

## 7. Формат рекомендации

- **Краткий вывод**.
- **Качество данных**.
- **Что происходит в портфеле**.
- **Главные риски**.
- **Что хорошо**.
- **Что требует внимания**.
- **Вариант 1 — ничего не делать**.
- **Вариант 2 — ограниченное изменение**.
- **Вариант 3 — более существенная ребалансировка**.
- **Покупки/продажи с расчётом**, если данных достаточно.
- **Что отменит рекомендацию**.
- **Дата и источники**.

## 8. Личная политика владельца

До выдачи точных sizing-рекомендаций GPT должен использовать заполненный файл `gpt/PERSONAL_PORTFOLIO_POLICY_TEMPLATE.md` или получить недостающие параметры у владельца.

Критические поля:

- цели;
- горизонт;
- допустимая просадка;
- минимальный денежный резерв;
- лимит одного эмитента;
- лимит сектора;
- целевые доли классов активов;
- минимальный кредитный рейтинг;
- допустимая доля высокорисковых активов;
- ограничения по валюте;
- запрещённые инструменты.

Пока критические поля не заполнены, GPT может делать диагностику и сценарный анализ, но не должен выдавать точный целевой размер позиции как персональный норматив.

## 9. Минимальный набор Knowledge

В production GPT загружаются только файлы, которые непосредственно улучшают работу с портфелем:

1. Личная политика владельца.
2. Правила анализа портфеля и диверсификации.
3. Правила анализа акций, облигаций и фондов.
4. Правила качества данных, новостей и кредитных рейтингов.
5. Формат рекомендаций и стиль ответа.

Проектные roadmap, CI runbooks, Telegram history и внутренние release-документы в GPT Knowledge не загружаются.

## 10. Acceptance первой версии

Версия считается готовой, когда существующий GPT в Preview успешно выполняет все сценарии из `gpt/PORTFOLIO_GPT_ACCEPTANCE_V1.md`, включая:

- полную проверку портфеля;
- анализ концентрации;
- проверку новостей;
- анализ облигационного риска;
- подбор кандидатов для свободных денег;
- расчёт доступного объёма;
- рекомендацию «ничего не делать»;
- отказ от рекомендации на stale/partial данных;
- отсутствие придуманных цифр и write Actions.

## 11. Следующий порядок работ

1. Принять этот scope в GitHub.
2. Переписать Instructions и Configuration существующего GPT.
3. Утвердить минимальный Knowledge manifest.
4. Заполнить личную политику владельца.
5. Проверить фактические 14 read-only Actions и убрать из GPT workflow ненужные внутренние цепочки.
6. Выполнить Preview acceptance.
7. Исправить обнаруженные gaps в Gateway только там, где они мешают реальному пользовательскому сценарию.

Любые торговые права, broker-authoritative order preview и confirm-before-trade являются отдельной будущей программой и не входят в текущий scope.
