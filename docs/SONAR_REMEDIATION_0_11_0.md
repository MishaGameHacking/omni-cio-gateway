# 0.11.0 — исправление 12 замечаний Sonar, 19.10.2026

Связанный пункт плана: F22. Ветка: `codex/spectrum-3d-100`, PR #880.
Исходный проверенный SHA: `7f090caea9cdaa587f8f753450256823860d6e3e`.
На нём Sonar сообщил Quality Gate passed и одновременно 12 новых замечаний.
Статус success сам по себе не является подтверждением отсутствия замечаний.

## Изменения

| Группа | Количество | Исправление |
|---|---:|---|
| Cognitive Complexity | 3 | Разделены сбор каталога и метаданных восстановления; проверка кандидатов отделена от проверки инструмента и общих риск-лимитов. |
| Избыточные классы исключений | 5 | URLError/TimeoutError не дублируют OSError; UnicodeError не дублирует ValueError. HTTPError по-прежнему обрабатывается раньше OSError и сохраняет фиксированный код статуса без тела ответа. |
| Повторный литерал | 1 | Общий NO_STORE сохраняет прежний Cache-Control во всех четырёх ответах owner_app. |
| Неоднозначный тест исключения | 3 | Подготовка OwnerIdentity, даты и TestClient вынесена за assertRaises; исключение ожидается от единственного проверяемого вызова. |

Дополнительно выявлен конфликт метаданных одинакового instrument_uid между
счетами: различный размер лота/валюта теперь запрещают формирование черновика.
Некорректные типы валюты и стороны сделки дают контролируемый ValueError.
Неожиданный ответ каталога больше не выводится целиком; сохраняются только
разрешённые поля и фиксированные коды диагностики.

## Проверки до отправки

Локально выполнены 40 тестов / 535 subtests исправляемых компонентов, включая
500 сравнений количества лотов с полным перебором. Выполнены compileall,
проверка YAML и 24 проверки нового JavaScript-ограничителя Sonar.
Это не полный backend, не эмулятор и не измерение покрытия строк.
Полный backend и Sonar должны подтвердить уже новый коммит в GitHub Actions.

## Защита от повторения

В PR шаг Backend CI `Read exact-head Sonar findings for remediation` теперь
завершает job ошибкой, если результат Sonar не получен, относится к другому SHA,
не прошёл Quality Gate, содержит аннотации либо не подтверждает ноль новых и
ноль принятых замечаний. Выбирается последний анализ официального приложения
Sonar, в том числе ещё не завершённый: старый successful-анализ не заменяет новый.
Все страницы аннотаций читаются до проверки. Изменённый/неоднозначный формат
сводки не трактуется как ноль. Сам ограничитель проверяется в том же CI-шаге.

Порог сложности, правила, исключения файлов и quality profile Sonar не менялись.
Замечания не принимаются и не подавляются. Формулы расходов, резерв,
проверка владельца и запрет автоматических брокерских заявок сохранены.

Timeweb, серверный APK и канал обновления не развёртываются этим изменением.
Android-сборка/эмулятор и переход на API37 остаются самостоятельными проверками;
исправление Sonar не объявляет весь 0.11.0 готовым.

Официальное описание различия rating-based Quality Gate и zero-issues условия:
https://docs.sonarsource.com/sonarqube-cloud/standards/managing-quality-gates/introduction-to-quality-gates
