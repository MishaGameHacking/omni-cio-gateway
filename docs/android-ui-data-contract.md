# Android → Timeweb: контракт данных, версия 1

Редакция 11.10.2026 заменяет контракт UI-06 fixtures/local-first.

## Authority и хранение

Android обращается только к `https://omnicio.ru/api/…` через HTTPS. Сессия — memory-only cookie jar, отдельный для текущего пользователя. Cookie не помещается в URL, логи, SavedState, SharedPreferences или файлы. Origin, `X-Omnicio-Profile` и `X-Omnicio-Client-Build` сохраняют действующие серверные проверки. Ответы API имеют `Cache-Control: private, no-store`; Android отключает HTTP cache и редиректы.

На устройстве сохраняются только `dark_theme` и `amounts_hidden`. Старое fixture-хранилище очищается. Финансовые DTO не сериализуются при recreation/process death. Android backup выключен. FLAG_SECURE защищает экран с персональными данными.

## Точки интеграции

| Операция | API |
|---|---|
| Конфигурация входа и legal versions | GET `/api/auth/config` |
| Вход / регистрация / код | POST `/api/auth/email/login`, `/register`, `/verify`, `/resend` |
| Восстановление пароля | POST `/api/auth/email/password-reset/request`, `/confirm` |
| Проверка и явное обновление согласий | GET / POST `/api/auth/legal` |
| Мобильные данные | GET `/api/mobile/workspace` |
| Запрос и проверка обновления | POST / GET `/api/workspace/refresh` |
| Проверка счетов и подключение | POST `/api/broker/tbank/accounts`, PUT `/api/broker/tbank` |
| Отключение | DELETE `/api/broker/tbank` |
| События | GET `/api/events`, POST `/api/events/read` |
| Создание цели | POST `/api/goals` |
| Выход | POST `/api/auth/logout` |

## Вход и согласия

Длина почтового кода берётся из `email_code_digits`; срок и задержка повторной отправки — из ответа challenge. До истечения серверной задержки повторная отправка недоступна. Истёкший код не подтверждается. Доступность регистрации и восстановления берётся из конфигурации, без фиктивно работающих кнопок.

Перед чтением workspace клиент проверяет текущие версии документов. При необходимости показывает отдельные пустые отметки подтверждения. Смена версий сбрасывает прежние отметки и при регистрации, и при обновлении согласий. POST передаёт именно показанные версии; сервер проверяет Origin, владельца действующей сессии, профиль и версии до атомарной записи. Повторное подтверждение идемпотентно. При отказе от согласия доступен выход. Выход сразу очищает клиент даже при недоступном сервере; ответы предыдущего поколения сессии не возвращают данные.

## Мобильный ответ

- `contract_version`: 1; несовместимая версия не отображается;
- `public_id`: должен совпасть с текущей подтверждённой сессией;
- `connection`: безопасные status/account_name/verified_at, без credential;
- `portfolio`: `status`, `latest`, `history` из существующего PortfolioStore;
- `events`: items, next_cursor и прочие существующие поля ленты;
- `goals`: существующий серверный список целей.

Сервер повторно проверяет сессию и подключение после чтения. Снимок другого счёта/environment не выдаётся. Decimal сериализуется точной строкой, не float. Нет новых миграций и отдельного хранилища мобильного портфеля.

## Значения и график

`null` означает отсутствие значения, в том числе у денег и истории. Подтверждённый ноль остаётся нулём. Некорректный decimal/JSON/contract приводит к состоянию ошибки, не к дефолтным цифрам. Валюта оценки портфеля — RUB по текущему серверному контракту; исходная цена позиции имеет свою валюту.

График строится в Compose из серверных наблюдений с их реальными timestamps. Неполные точки не соединяются через разрыв. Периоды фильтруют полученную историю; API отдаёт до 365 последних наблюдений, не обещает полную историю счёта. Slider и список позволяют прочитать значение и время. Изменение стоимости не является инвестиционным результатом.

Источник берётся из сохранённого `evidence.sources`, время — из captured_at/retrieved_at. Серверный статус свежести сохраняется; при отсутствии источников это показывается явно. Данные загружаются при входе/возврате, раз в минуту только пока экран активен и по явному запросу. Это не обещание обновления рынка раз в минуту.

## Ошибки

- 401 / смена профиля: очистить финансовое состояние и вернуться ко входу;
- 409: показать изменение контекста/условий, не повторять mutation автоматически;
- 429: предложить повтор позже;
- таймаут / сеть / неподдерживаемый ответ: очистить финансовое состояние и показать ошибку;
- отсутствие подключения/истории/источника: явное пустое состояние.

Никакой ошибки не соответствует переход в demo. Broker token вводится в memory-only поле, передаётся только серверу после отдельного согласия и очищается из поля после отправки подключения. Полномочия ограничены чтением существующим серверным adapter.
