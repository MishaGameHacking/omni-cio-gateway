## Непрерывный системный жест «Назад»

Старый тест запускал отдельный `input touchscreen motionevent` для каждого
DOWN/MOVE/CANCEL. AOSP InputShellCommand задаёт новый `now` одновременно как
`downTime` и `eventTime` при каждом таком вызове; запуск shell также разрывает
темп первых движений. Это некорректная имитация одного непрерывного указателя.

Отдельный существующий test-only UiAutomation driver теперь выполняет ограниченную
последовательность с одним pointer ID и общим downTime. MOVE генерируются внутри
процесса; после удержания читаются настоящие progress и PNG приложения. CANCEL
должен оставить экран открытым и счётчик равным нулю; следующий завершённый
жест должен увеличить его ровно один раз и сбросить progress. Не вызываются
callback приложения, KEYCODE_BACK или поддельные события прогресса.

Действия ограничены точным видимым synthetic spatial fixture в активном окне
Analyst AI. Протокол сохраняет аутентификацию, монотонные номера и ограничения
размера/времени; подтверждение инъекции не принимается за доказательство UI.
При ошибке/закрытии driver отменяет удерживаемый указатель. Восстановление
настроек пытается выполнить все действия и не скрывает исходный отказ.

Локально для нового исправления: **15 Python-тестов прошли**, включая исполняемые
**5 Java-сценариев** последовательности указателя и **8 Node-сценариев** хранения
приватного APK. Это регрессии кода, не доказательство проверки эмулятора.
Окончательный Android build/lint/runtime и Sonar должны подтвердить новый SHA.

## Отдельный APK без обновления сервера

Android CI после всех существующих обязательных проверок может сохранить APK
и `apk-verification.json` в **неопубликованном приватном GitHub draft**. Требуется
явный маркер `[private-apk]` в проверяемом head, приватный same-repository PR,
неизменённые head/base, зелёные exact-head Sonar и Backend CI. Существующий
`validate_distribution.py` должен уже подтвердить полный API35/API36 результат.
Хранятся именно проверенные байты с прежними package, versionCode и сертификатом;
загрузка проверяется обратным скачиванием и сравнением размера/SHA-256.

Draft не публикуется и не становится latest; release/deploy dispatch не вызывается.
Timeweb не затрагивается. Физический телефон, ARM, живой брокер и платные модели
не объявляются проверенными по synthetic x86_64 UI-прогону.

Обязательная запись диагностических PNG/JSON в Git blobs остаётся `always()`.
Необязательная дублирующая загрузка в Actions Artifacts теперь включается только
явной repository variable `RETAIN_DUPLICATE_UI_ARTIFACTS=true`: квота уже исчерпана,
а копирование одних и тех же снимков не должно создавать повторные ложные тревоги.
Исторические артефакты не удаляются, лимиты проверки не меняются.

## Личное использование и границы

Один сервер Timeweb обслуживает до пяти пользователей: сбор данных, расчёты,
очередь ИИ и учёт расходов выполняются там; телефон отображает нативный интерфейс.
Изоляция портфелей, защита ключей и бюджет сохраняются. Брокер read-only;
поручение подтверждает пользователь в Т-Инвестициях. Полный рекомендательный
конвейер, калибровка вероятности дефолта и оптимизатор реинвестирования этим
исправлением не завершаются. Опубликованная серверная линия остаётся 0.10.0 / 34.
