## A1. Тестовый файл без зарегистрированных тестов

`require_clean_sonar.test.cjs` выполнял ручные проверки через runTests(), но
не объявлял тесты средствами тестового раннера. Sonar S2187 требовал добавить
тесты. Backend сначала проходил собственные проверки, затем закономерно
завершался отказом строгого Sonar gate. Подавлять замечание или ослаблять gate
не требовалось.

Коммит `6ddfb7c68037be732ea9c96191922f3e19064643` регистрирует 34 именованных
node:test случая; runTests() синхронно выполняет тот же набор для существующих
github-script вызовов. Python integration test запускает Node с явным TAP
reporter, требует ненулевой набор без failure/skip/todo/cancel и сверяет число
проверок с runTests(). Production require_clean_sonar.cjs не изменён.
Локально: 34 Node + 1 Python integration passed. Sonar на этом SHA подтвердил
0 новых/принятых замечаний и 0 annotations; Backend CI success. Это не результат
последующего SHA и не полный Android runtime pass.

## A2. Повторяющееся местное время ошибочно считалось свежим

Allocation PlanContext/Candidate принимали любой aware datetime, но сравнивали
его с наблюдением и временем истечения без нормализации. Python при одинаковом
tzinfo игнорирует fold. В воспроизведении наблюдение 02:30 fold=0 и срок 02:30:30
fold=0 ошибочно остаются свежими в 02:30:15 fold=1, фактически через час.
Также проверка lifetime прибавлением к datetime.max могла давать OverflowError.

Исправление: единая проверка/нормализация входных моментов в UTC до сравнения,
проверка длительности вычитанием, строгие прежние TTL 60/300 секунд. Граница
истечения остаётся исключающей. Непредставимый в UTC момент даёт ValueError,
а не переполнение из внутренней арифметики.

12 новых тестов воспроизводят expired/future snapshot и quote в повторном
часе, реальный 20-секундный переход через откат часов, скрытый лишний час,
эквивалентность UTC и другого смещения, крайние даты и точную границу TTL.
До исправления: 8 failures, 2 errors, 2 passes. После: 12 passed. Вместе с
неизменёнными прежними тестами allocation: 36 passed, включая существующее
сравнение с полным перебором на 500 псевдослучайных наборах с фиксированным seed.
Это проверка чистого расчётного ядра, не live-брокер или рекомендация с
подтверждённой пригодностью. Сохраняются state=draft, automatic_order=false,
suitability_complete=false, requires_fresh_broker_validation=true.

## Main и незавершённые границы

На указанном main summary последней доступной Sonar-проверки сообщает
77 New issues при Quality Gate passed. Это не 77 доказанных критических
уязвимостей и не ноль замечаний. Ноль annotations не заменяет счётчик issues.
Результат PR относится к новому коду относительно main и не закрывает его
исторические замечания. Требуются поэлементный разбор основного кода и проверка
обратных переносов без слияния незавершённого 0.11.0.

Просмотрены вход владельца, авторизация браузера, резервы бюджета, расчёт
распределения и CI. Эти чтения не являются полным security-аудитом всех routes,
зависимостей, фоновых задач и Android. В частности, обработку некорректного
Unicode nonce следует проверить отдельно на основном и персональном entrypoint.
Полный новый Android runtime, API37-миграция и физический телефон не объявлены
проверенными. Существующие отдельные ошибки эмулятора не исправляются этим
рефакторингом и не скрываются изменением матрицы.

## Воспроизведение

```sh
node --test --test-reporter=tap .github/scripts/require_clean_sonar.test.cjs
python -m unittest discover -s .github/scripts/tests -p test_sonar_gate_runner.py -v
python -m unittest discover -s backend/tests -p 'test_allocation*.py' -v
```

Локальная копия calculation и прежних tests сверена с Git blob SHA; использован
целевой набор исходников, не полный клон. Полный Backend CI выполняет GitHub.
Запуски проверки Node и allocation выполнялись параллельно в разных процессах.
