| Без вымышленных фактов | Неизвестное остаётся неизвестным. Неактуальные данные блокируют конкретную покупку, но не отключают наблюдение за имеющимся портфелем. |
| Один результат | Для исполнения показывается один согласованный план с очерёдностью. Набор из трёх конкурирующих советов пользователю не предлагается. |
| Закрытый круг | Вход только по списку приглашённых. Максимум пять активных пользователей; производительность проверяется с запасом, регистрация для остальных закрыта. |

### Границы обещаний

Система уменьшает управляемые риски и ускоряет реакцию на подтверждённые события. Она не гарантирует отсутствие дефолта, прибыль каждый день, точный прогноз цены или возможность выйти из бумаги перед падением. Длительное владение не делает плохую компанию безопасной.

Чтение документа: текущее приложение и вход - стр. 3-7; инвестиционные правила - 8-20; ИИ и интерфейс - 21-25; сервер, бюджет и выпуск - 26-33; долгосрочная логика и источники - 34-38. Основание: [R01-R05], [S01-S07].

## 04. Как работает вход сейчас

_04 / АВТОРИЗАЦИЯ: КОМПОНЕНТЫ И ПОТОК · Страница 5 исходного PDF._

В проекте сохранены два серверных пути Telegram. app.py содержит обмен authorization code через сервер Telegram с PKCE. telegram_browser_app.py заменяет начальную страницу входа и принимает подписанный ID token из браузерной библиотеки Telegram. Документ инцидента предписывает запуск второго варианта; фактическая конфигурация службы в этой сессии не проверялась.

| Шаг | Компонент и запрос | Что происходит |
| --- | --- | --- |
| 1 | Android → GET /auth/telegram/start | Открывается браузер. Сервер создаёт случайные state и nonce. Транзакция входа живёт 10 минут. |
| 2 | Telegram Login в браузере | Пользователь подтверждает личность. Пароль Telegram приложению и backend не передаётся. |
| 3 | POST /auth/telegram/complete | Браузер отправляет state и id_token. Проверяются подпись RS256, kid, issuer, audience, exp, iat и nonce; транзакция расходуется один раз. |
| 4 | analystai://auth?code=… | Backend создаёт случайный одноразовый код на 5 минут. В базе хранится его SHA-256. В ссылку не попадает токен Т-Инвестиций. |
| 5 | BootstrapActivity → MainActivity | Внешняя Activity пропускает документированный возврат auth. MainActivity передаёт код через POST /auth/session. |
| 6 | /auth/session → AuthSessionStore | Выдаётся случайный непрозрачный access_token на 30 дней; Android шифрует и сохраняет его. Это собственный сеанс Analyst AI, не Telegram JWT. |
| 7 | GET /me и пользовательские API | Android отправляет Authorization: Bearer. Backend ищет хеш сеанса, определяет user_id и проверяет доступ к данным. |

### Почему возникал возврат с ошибкой

Документ инцидента 15.10.2026 связывает telegram_unavailable с недоступностью oauth.telegram.org с московского сервера, а не с телефоном. Браузерный путь переносит получение подтверждения в браузер пользователя и проверяет подпись локально. Это зафиксированная диагностика прошлого инцидента, не доказательство отсутствия других причин сегодня.

Код и документ: [R02], [R04], [R05]. Официальная схема Telegram: [S08].

## 05. Где находятся ключи и токены

_05 / АВТОРИЗАЦИЯ: ХРАНЕНИЕ · Страница 6 исходного PDF._

| Данные | Хранение и использование |
| --- | --- |
| Пароль Telegram | Не хранится в Analyst AI. Подтверждение выполняет Telegram. |
| Telegram ID token | Принимается при входе и проверяется. Не служит постоянным ключом доступа к вашему портфелю. |
| Одноразовый код возврата | В URL только краткоживущий код; в SQLite - его SHA-256, срок и признак использования. |
| Сеанс Analyst AI | Android: AES-256-GCM, случайный IV и ключ в Android Keystore. Сервер: SHA-256 токена, user_id и срок действия. |
| Данные профиля на телефоне | Кеш имени, Telegram ID и других полей хранится в обычных приватных SharedPreferences. Шифрование токена не означает шифрование всего профиля. |
| Токен Т-Инвестиций | Передаётся через HTTPS в POST /tinvest/token; проверяется GetAccounts; шифруется Fernet и сохраняется у пользователя в SQLite. После сохранения клиенту не возвращается. |
| Ключи сервера | FERNET_KEY, Telegram client secret и ключи Timeweb находятся в серверной конфигурации. Облачный административный токен и токен вызова моделей имеют разные назначения. |

### Фрагменты, определяющие поведение

```text
SESSION_TTL = 30 * 24 * 60 * 60
hashlib.sha256(value.encode()).hexdigest()
encrypted = FERNET.encrypt(token.encode())
Cipher.getInstance("AES/GCM/NoPadding")
```

При запуске Android расшифровывает сеанс и вызывает /me. При временной сетевой ошибке допускается вход в интерфейс с кешированным профилем; это не создаёт действующую серверную авторизацию. При неповторяемой ошибке локальная сессия очищается. 426 «нужно обновление» уже считается повторяемой ошибкой.

Обычный выход сейчас очищает данные сеанса на телефоне. Серверный отзыв этого токена не найден. Refresh-token протокола тоже нет: сохранённый сеанс не продлевается бессрочно. Старый локальный токен Т-Инвестиций предусмотрен только для миграции на сервер и удаляется после успешного переноса.

Основание: [R02-R04]. Успешный GetAccounts доказывает работоспособность токена, но сам по себе не доказывает, что токен имеет только права чтения. Read-only выбирается при выпуске у брокера. [S09]

## 06. Как укрепить авторизацию

_06 / ЦЕЛЕВОЙ КОНТРАКТ ВХОДА · Страница 7 исходного PDF._

Пользователь входит один раз, а приложение восстанавливает сеанс после закрытия, перезапуска и обновления поверх прежней версии. Сбой сети, источника или ИИ не разлогинивает пользователя. Реальный отзыв доступа, истечение разрешённого срока или удаление приложения требуют нового входа.

| Доработка | Конкретное поведение |
| --- | --- |
| Приглашения | Разрешены только идентичности, добавленные владельцем. Проверка выполняется до создания пользователя; ограничение пяти аккаунтов остаётся дополнительной защитой. |
| Возврат в приложение | Основной путь - проверенная HTTPS App Link с assetlinks.json и сертификатом установленной линии. Custom scheme временно сохраняется как совместимый переход. |
| Привязка к начавшему вход устройству | Android создаёт секрет обмена; backend связывает код с его проверочным значением. Перехваченной ссылки недостаточно для получения сеанса. |
| Однократный обмен | Погашение кода и создание сеанса - одна атомарная транзакция с проверкой, что код ещё не использован. Конкурентный обмен покрывается тестом. |
| Продление | Целевой протокол: короткий access-сеанс и вращаемый refresh-токен устройства, с явным сроком и отзывом. Плановые значения 15 минут / 30 дней бездействия / 90 дней до нового входа настраиваются сервером. |
| Выход и отзыв | Выход отзывает серверный сеанс устройства. Есть «Выйти на всех устройствах». Отзыв токена брокера отдельно отключает связь и фоновые задания этого пользователя. |
| Ключи Telegram | Кеш доверенных JWKS с контролируемым обновлением и предупреждением о неизвестном kid. Нельзя принимать неподписанное подтверждение ради доступности. |
| Сохранность | База, Fernet-ключ и резервные копии сохраняются между релизами; ключ шифрования хранится отдельно от копии базы. |

В текущем /auth/session сначала читается неиспользованный код, затем отдельно меняется used. Явной защитной транзакции, как в браузерном обработчике, здесь нет. Это место требует проверки конкурентных запросов. Отдельно проверяются лимиты попыток входа и серверный отзыв; наличие защиты на reverse proxy по исходникам не установлено.

Предлагаемая доработка, не утверждение о завершённом исправлении. Основание: [R02-R05], [S08], [S10]. Никакие действующие ключи не читались и не менялись.

## 08. Рейтинги: единое правило допуска

_08 / КРЕДИТНОЕ КАЧЕСТВО · Страница 9 исходного PDF._

По данным Банка России в реестр внесены четыре агентства. Храним агентство, шкалу, субъект рейтинга, исходное обозначение, прогноз и даты. Для интерфейса снимаем только оформление российской национальной шкалы; методологии агентств не объявляем одинаковыми.

| Агентство | Пример нижнего допуска | В интерфейсе |
| --- | --- | --- |
| АКРА | BBB-(RU) | BBB- |
| Эксперт РА | ruBBB- | BBB- |
| НКР | BBB-.ru | BBB- |
| НРА | BBB-\|ru\| | BBB- |

Разрешённый набор по умолчанию: **AAA; AA+, AA, AA-; A+, A, A-; BBB+, BBB, BBB-**. Каждая ступень отключается отдельно. Ни пользовательский переключатель, ни чат, ни ИИ не могут разрешить BB+ и ниже в этом продукте.

### Несколько рейтингов

Для каждой пары «агентство + субъект» используется последнее действующее событие. Средний рейтинг не вычисляется. Проектная осторожная политика: если хотя бы одно действующее сопоставимое мнение по компании ниже порога, новые покупки запрещены; для лимита доли применяется самый строгий допустимый уровень. Это наше правило риска, а не утверждение об абсолютной эквивалентности шкал.

### Компания и конкретный выпуск

Рейтинг компании определяет предел общей доли. Дополнительно проверяется рейтинг выпуска и положение долга в очереди погашения. Более низкий рейтинг выпуска запрещает этот выпуск даже при высоком рейтинге компании. Отсутствующий рейтинг выпуска нельзя автоматически заменить рейтингом эмитента. Для обычного старшего долга такое использование допускается лишь по отдельно проверенной применимости методологии; иначе бумага исключается из новых покупок.

Для акций рейтинг оценивает долговую устойчивость компании, но не цену акции и не вероятность её роста. Рейтинг фонда или управляющей компании не заменяет анализ активов фонда. ОФЗ рассматриваются отдельным государственным классом, разрешаемым стратегией: им не присваивается выдуманный корпоративный AAA.

Национальные шкалы относительны внутри страны. BBB- здесь - выбранная граница продукта, а не универсальная гарантия «инвестиционного качества» во всех нормативных задачах. [S01-S05], [R07]


<a id="plan-09"></a>

## 09. Что происходит при изменении рейтинга

_09 / СОБЫТИЯ И РЕАКЦИЯ · Страница 10 исходного PDF._

| Событие | Действие системы |
| --- | --- |
| Рейтинг ниже BBB- | Немедленно запрещаются докупки. Создаётся приоритетное действие на выход из затронутых бумаг; проверяются торги, доступное количество и ликвидность. Подбор замены готовится условно до продажи. |
| AA понижен до A | Пересчитывается совокупная доля компании и её новый предел. Если доля уже укладывается - продажи нет. Иначе выбирается сокращение или исправление новыми поступлениями с учётом риска и срока. |
| Негативный прогноз / пересмотр | Усиливается наблюдение; уменьшается разрешённый запас риска по правилам стратегии. Сам прогноз не равен снижению буквенного рейтинга. |
| Рейтинг повышен | Расширяется допустимый предел. Автоматического приказа докупить нет: бумага конкурирует с другими по цене, риску и пользе для портфеля. |
| Рейтинг отозван / приостановлен | Новые покупки остановлены. Причина проверяется: отзыв не объявляется дефолтом. Для имеющейся позиции формируется отдельное решение о сохранении или сокращении. |
| Источник не отвечает | Последнее наблюдение остаётся в истории с отметкой свежести. Пропажа страницы не заменяется ни хорошим рейтингом, ни сигналом «дефолт». |
| Противоречие в данных | Спорные записи изолируются. Покупки не выдаются до проверки, действующие риски продолжают наблюдаться. |

### Правило продажи ниже порога

Сигнал должен быть однозначным: «Продать доступные бумаги компании: её рейтинг ниже вашего минимального уровня». Однако программа не предлагает рыночную продажу по любой цене и не утверждает, что продажа возможна при блокировке. Если торгов нет, показывается «Выход ожидает возобновления торгов» с одним актуальным статусом.

При сильном расхождении цены и проверенной оценки ликвидности план предусматривает лимитную цену, поэтапное уменьшение или пересмотр условий. Выбор не маскирует исключение из стратегии: позиция остаётся отмеченной как требующая выхода. Финальный риск цены исполнения принимает пользователь в брокерском приложении.

Даты присвоения рейтинга, вступления события в силу, обнаружения и последней проверки хранятся раздельно. Старая положительная публикация не «воскрешает» рейтинг после более нового отзыва. Возврат к покупкам требует нового подтверждённого состояния.

Это целевые правила продукта. Источники рейтингов и доказательств: [S01-S05], [R07-R08].


<a id="plan-10"></a>

## 10. Диверсификация по реальному риску

_10 / КОМПАНИИ И ГРУППЫ · Страница 11 исходного PDF._

Все выпуски облигаций и акции одной компании складываются в общую долю по всем счетам пользователя. Затем складываются связанные компании: материнская структура, дочерние заёмщики, общие гарантии и существенная зависимость от одного бизнеса. Десять выпусков одного должника не считаются десятью независимыми вложениями.

Основной знаменатель долей - сопоставимая стоимость всего выбранного инвестиционного портфеля, включая деньги. Для контроля дополнительно считается доля в доступной для операций части. Неоценённая заблокированная позиция не принимается за ноль: точная общая доля временно неизвестна, покупки проверяются на консервативном сценарии оценки.

| Категория компании | Стартовый верхний предел от всего портфеля |
| --- | --- |
| AAA | 5% на компанию |
| AA+, AA, AA- | 4% на компанию |
| A+, A, A- | 3% на компанию |
| BBB+, BBB, BBB- | 1,5% на компанию; вся категория BBB вместе - не более 10% |
| Связанная группа | Не более 8%; применяется одновременно с лимитами отдельных компаний |
| Отрасль | Не более 20%; сквозные вложения фондов учитываются, когда раскрыты |
| Прямой государственный долг | Отдельный предел стратегии; в базовом долговом профиле до 40%, без фиктивного деления на независимые компании |

**Это исходные проектные ограничения для проверки, а не рыночные факты и не доказанные оптимальные проценты.** Перед вводом они проверяются на выполнимость для доступного рынка и выбранного капитала. Версия стратегии хранит значения и причину их изменения. Лимит означает «не больше», а не обязательство заполнить долю.

Число компаний с одним рейтингом или в одной отрасли не ограничивается искусственно. Есть ограничения риска, стоимости обслуживания и ликвидности. Выбор ещё одной компании полезен, только если она снижает зависимость портфеля и её качество достаточно. Покупать BBB- лишь ради заполнения категории запрещено.

Показываем эффективное число независимых долей: 1 / сумма квадратов долей компаний. Отдельно учитываем корреляцию и общие сценарии: даже сотни российских эмитентов сохраняют общий страновой риск. Обычная формула концентрации сама по себе эту зависимость не измеряет.

Принципы и математическая основа: [S15-S17], [R09]. Проектные пределы будут уточняться проверкой; в этой сессии они не применялись к реальному портфелю.

## 11. Стратегия и размер капитала

_11 / МОИ СТРАТЕГИИ · Страница 12 исходного PDF._

В «Портфель → Мои стратегии» хранится один активный согласованный набор правил на выбранные счета. Он задаёт цель, срок, денежный резерв, потребность в выплатах, допустимую просадку, рынки, рейтинги и валютную зависимость. Смена стратегии создаёт новую версию и предварительно показывает влияние на портфель.

| Готовая стратегия | Как управляется портфель |
| --- | --- |
| Сохранение и доход | Долговая основа, лестница погашений, короткая и средняя чувствительность к ставкам; доля акций по умолчанию нулевая. Валютные и инфляционные инструменты включаются только после проверки условий. |
| Накопление капитала | Все поступления реинвестируются; акции допускаются в согласованном пределе при длинном горизонте и способности пережить снижение. Высокий дивиденд не заменяет качество бизнеса. |
| Регулярные выплаты | Резерв финансирует выводы между купонами. Календарь поступлений сопоставляется с нужной суммой, сроком и налогами. Если цель не обеспечивается капиталом, программа меняет план, а не повышает риск скрыто. |

До выбора стратегии приложение наблюдает портфель, но не подставляет агрессивность по возрасту, размеру счёта или догадке ИИ. Для старта нужен короткий набор явных ответов: цель, срок, резерв вне инвестиций, допустимое снижение и нужны ли регулярные выводы.

| Ситуация | Готовое поведение |
| --- | --- |
| Капитал 0 ₽ | Мониторинг подключения и плана. Нет деления на ноль, процента защиты и выдуманного списка покупок. Сообщение: «После пополнения рассчитаю первую покупку». |
| Деньги 0 ₽, бумаги есть | Продолжаются все проверки имеющихся активов. Новые покупки не оптимизируются без повода; обязательный выход и условная замена остаются возможны. |
| Малый капитал | Не ослаблять BBB- и не обходить лимит компании. Если лот слишком велик, ждать накопления либо использовать разрешённый фонд с проверенным составом / государственный инструмент. |
| Большой капитал | Проверять глубину рынка и разделять исполнение на части. Большая сумма не требует отдельного сервера; нагрузку определяют число позиций, источников и задач. |

Существующие шаблоны профиля будут заменены этим контрактом, но настройки и история пользователя сохранятся. Никакая стратегия не считается выбранной только из-за значения по умолчанию в коде. [R06], [S15]


<a id="plan-12"></a>

## 12. Доход, инфляция и валюта

_12 / ЭКОНОМИЧЕСКИЙ СМЫСЛ · Страница 13 исходного PDF._

«Умная ежедневная доходность» означает ежедневный контроль накопления результата и своевременное использование поступлений. Купоны и дивиденды приходят в установленные даты; рыночная стоимость может снижаться. Ежедневное увеличение баланса и гарантированные выплаты каждый день не обещаются.

### Что именно растёт

Отдельно показываются внесённые деньги, полученные выплаты, изменение стоимости и итог после расходов. Погашение номинала облигации - возврат капитала, не купонный доход. Дивиденд не бесплатная добавка: после отсечки цена может скорректироваться. НКД при покупке уже накоплен продавцом и входит в стоимость приобретения.

### Как строится поток выплат

Подбор распределяет сроки погашений, купонные даты, типы ставки и источники дохода. Приоритет имеют качество, чистая доходность и ликвидность. Не покупаем слабую или дорогую бумагу только ради красивого календаря. Резерв сглаживает выплаты; накопление дохода на бумаге не тратится до фактического зачисления.

### Защита покупательной способности

Фиксированные облигации дают определённые условия потока, но чувствительны к ставкам и инфляции. Флоатеры частично уменьшают риск изменения ставок, однако их купон может снизиться. ОФЗ-ИН индексируют номинал по официальной инфляции с условиями конкретного выпуска; личная инфляция и цена продажи могут отличаться. Акции участвуют в росте бизнеса, но способны долго падать.

### Валютная привязка при выплате рублей

Замещающая облигация может иметь валютный номинал и рублёвые выплаты через российскую инфраструктуру. Для каждого выпуска читаются валюта обязательства, формула пересчёта, дата фиксации курса, валюта расчётов и правовые условия. Это не обязательно курс в момент сделки. Долларовая надпись на бумаге не означает долларовый остаток на счёте.

Такая конструкция уменьшает отдельные риски зарубежной платёжной цепочки, но сохраняет риск эмитента, ликвидности, изменения правил и ограничений. Рублёвая выплата не делает санкции невозможными. При укреплении рубля рублёвая стоимость валютной позиции может уменьшиться.

Валютные доли выбираются по будущим расходам и риску стратегии; отображение суммы в USD или EUR не меняет экономическую валютную зависимость портфеля. Политический и страновой риск нельзя устранить одним набором российских бумаг.

Источники: [S18-S21]. Это описание механизмов, не рекомендация конкретного выпуска Газпрома или другого эмитента.

## 13. Как рассчитываются деньги

_13 / ПРОВЕРЯЕМАЯ МАТЕМАТИКА · Страница 14 исходного PDF._

| Величина | Правило расчёта |
| --- | --- |
| Доступно на покупку | Деньги, доступные для сделки у брокера, минус уже зарезервированное, выбранный денежный резерв и подтверждённые предстоящие расходы. Кредитное плечо не учитывается как собственные деньги. |
| Стоимость облигации | Чистая цена в процентах × действующий номинал / 100 + НКД. Затем учитываются количество бумаг в лоте, валютный пересчёт по правилам выпуска и комиссии. |
| Количество | Целое число лотов, ограниченное одновременно деньгами, долей компании и группы, отраслью, валютой, рейтингом и ликвидностью. |
| Доходность облигации | Расчёт по всем денежным потокам, амортизации, офертам и срокам. Купонная ставка, доходность к погашению и реализованный результат показываются как разные величины. |
| Реальная доходность | (1 + доходность после издержек) / (1 + инфляция за тот же период) - 1. Сравниваем одинаковые периоды, валюты и базу. |
| Результат пользователя | Для эффекта стратегии - доходность без влияния пополнений; для личного опыта - доходность с учётом дат пополнений и выводов. При недостатке истории результат не восстанавливается выдуманными точками. |

### Условный проверочный пример, не рыночная рекомендация

Номинал 1 000 ₽, цена 97%, НКД 12 ₽, лот 1 бумага, комиссия 0,05%. Один лот стоит примерно **982,49 ₽**. При 5 000 ₽ денег и резерве 1 000 ₽ денег хватает на 4 лота. Но если предел компании 2% от портфеля 100 000 ₽ и позиции ещё нет, допустимы только **2 лота**. Итог определяется самым строгим ограничением, а не только балансом.

Округление проверяется после каждой операции и после округления до лотов. Денежный учёт выполняется Decimal или целыми минимальными единицами валюты. Float допустим для статистической модели, но не для суммы поручения и остатка.

Налоги рассчитываются с учётом резидентства, типа счёта, стоимости приобретения, льгот и уже удержанных сумм. Приложение не знает другие доходы человека автоматически. Если точный налог неизвестен, расчёт помечается оценочным и использует осторожный резерв. Для резидентов базовые ставки по соответствующим инвестиционным доходам 13% / 15% не заменяют проверку конкретной налоговой базы.

Налоги и данные: [S22], [S09], [S12-S13]. Формулы и пример - расчёт автора; ставки и правила не фиксируются навсегда в коде.


<a id="plan-14"></a>

## 14. Как получается команда «купить»

_14 / ПЛАНИРОВЩИК ПОКУПОК · Страница 15 исходного PDF._

Общий каталог обновляется для всех пользователей. Персональный дорогой поиск запускается при появлении доступных денег, смене стратегии или необходимости заменить исключённую позицию. При отсутствии денег и таких событий повторный глубокий подбор не выполняется.

| Этап | Результат |
| --- | --- |
| 1. Зафиксировать состояние | Один согласованный снимок позиций, доступных денег, действующих ограничений, версии стратегии и времени источников. |
| 2. Отсечь недопустимое | Площадка, права, блокировки, рейтинги, тип выпуска, идентичность, свежесть и минимальная ликвидность. |
| 3. Сравнить компании | Общая долговая устойчивость, сценарии потерь, отрасль и уже занятая доля. Один анализ компании используется для всех её выпусков. |
| 4. Сравнить выпуски | Цена, чистая ожидаемая доходность на выбранном сроке, НКД, дата погашения, оферты, ликвидность, валюта и условия выплат. |
| 5. Собрать целые лоты | Выбрать набор, который улучшает портфель при всех ограничениях. Отдельно считать докупку имеющейся бумаги и новую позицию. |
| 6. Проверить выгоду | Учитывать комиссии, спред, налоги и устойчивость результата к ошибке прогноза. «Не покупать» - допустимый лучший результат. |
| 7. Проверить перед показом | Повторно сверить деньги, цену и ограничения. План получает срок актуальности и идентификаторы исходных данных. |
| 8. Показать одну инструкцию | Актив, ISIN, количество лотов и штук, предельная цена, оценочная сумма, одна причина и переход к брокеру. |

Оптимизация сначала соблюдает жёсткие правила, затем уменьшает наиболее опасную концентрацию и несоответствие срокам, и лишь после этого улучшает ожидаемый результат после издержек. Не объединяем все эти задачи в произвольный «балл ИИ», который способен компенсировать недопустимый риск высокой доходностью.

Для небольшого бюджета используется понятный жадный подбор по полезности следующего лота с проверкой альтернатив. Для сложного портфеля - ограниченная оптимизация с целыми лотами и временем решения. Результат всегда проходит отдельный валидатор; при отсутствии допустимого решения деньги сохраняются.

План может включать несколько последовательных действий, но не несколько взаимоисключающих вариантов на выбор. В интерфейсе первой показывается операция с наибольшей пользой и готовностью к исполнению; остальные раскрываются по запросу.

Математический подход к ограничениям и издержкам: [S16-S17]. Готового рыночного планировщика в проверенном коде нет; существующие заготовки: [R09-R10].


<a id="plan-15"></a>

## 15. Когда продавать и как не переплачивать

_15 / РЕБАЛАНСИРОВКА · Страница 16 исходного PDF._

Недостаток денег на новую интересную бумагу сам по себе не является причиной продажи. План сначала использует свободные деньги, купоны, дивиденды, погашения и пополнения. Продажа обосновывается отдельным риском, выходом за существенный предел, нуждой в деньгах по стратегии или подтверждённым улучшением после всех издержек.

### Мягкое и обязательное изменение

Для небольшого отклонения от целевой доли вводится коридор бездействия: его ширина зависит от лота, волатильности, ликвидности и стоимости сделки. Повторный пересчёт цены не создаёт новое поручение. Для рейтинга ниже BBB-, подтверждённого недопуска или опасной концентрации действует отдельное обязательное правило риска.

Снижение AA → A означает пересчёт лимита, а не механическую продажу. Если превышение небольшое и поступление скоро исправит долю, план может использовать новые деньги. При существенном превышении формируется сокращение. Разрешённый временный срок исправления хранится в стратегии и не продлевается бесконечно.

### Сравнение «держать» и «заменить»

Программа сравнивает денежные потоки на одном горизонте в сценариях ставок и кредитного риска. Из эффекта замены вычитаются две комиссии, оба спреда, налоговый эффект, НКД и риск ожидания исполнения. Замена по доходности проходит только при запасе выгоды над издержками и неопределённостью. Для обязательного выхода экономия комиссии не отменяет нарушение допустимости.

| Состояние действия | Что происходит дальше |
| --- | --- |
| Рассчитано | Пользователь видит актуальные параметры и причину. |
| Открыто у брокера | Фиксируется только переход. Сделка ещё не считается совершённой. |
| Ожидается подтверждение | Сервер читает операции, заявки и позиции; учитывает частичное исполнение. |
| Исполнено / частично | Количество и доступные деньги сверяются с брокером. Только после этого создаётся финансируемая покупка замены. |
| Устарело / отменено | Изменились цена, баланс, рейтинг или стратегия. Старая инструкция больше не исполняется из приложения. |

Даже после продажи расчётная сумма выручки не становится автоматически свободным балансом. Окончательное количество замены определяется фактически доступными для покупки деньгами брокера, с учётом расчётов и резервов. Один и тот же денежный остаток не используется в двух параллельных планах.

Основа: [S15-S17], [R09-R10]. Приложение не отменяет чужие заявки и не отправляет торговые поручения.

## 16. Наблюдение работает круглосуточно

_16 / РАСПИСАНИЕ СЕРВЕРА · Страница 17 исходного PDF._

Наблюдение выполняет Timeweb, а не телефон. Закрытие приложения, погасший экран и окончание сеанса Android не останавливают проверку подключённого портфеля. Основания остановки - отзыв разрешения, отключение токена, отключение пользователя владельцем или отказ самого источника с явным статусом.

| Данные / задача | Начальный режим, затем корректируется по измерениям |
| --- | --- |
| Позиции и доступные деньги | События брокера при поддержке; резервная сверка примерно каждые 5 минут в активное время. Вне торгов - реже, но с учётом выплат и операций. |
| События рейтингов | Общий поток агентств проверяется каждые 5-15 минут, если условия источника позволяют. Новое событие распределяется всем затронутым пользователям. |
| Новости компаний | BBB и проблемные компании - 15-30 минут; A - около часа; устойчивые AA/AAA - несколько часов. Срочные официальные события получают одинаковый высокий приоритет. |
| Отчётность | Проверка календаря ежедневно; загрузка и анализ после публикации. Один и тот же отчёт не перечитывается моделью каждый час. |
| Каталог и права | Полная сверка ежедневно; изменения блокировок, допусков и статусов - по событиям и перед каждым действием. |
| Расчёт риска | Быстрые правила по событиям; полная оценка раз в сутки и после существенного изменения. |
| Поиск покупок | Только при доступном бюджете, смене правил или обязательной замене. Перед показом - свежая цена и остаток. |

Интервалы не являются обещанием предсказать дефолт за 15 минут до его наступления. Скорость ограничена публикацией информации, доступностью источника, временем проверки и доставкой на телефон. Внутренний показатель задержки считается от получения проверенного события, а не от неизвестного момента возникновения проблемы.

Для пяти пользователей источник о компании читается один раз, а влияние рассчитывается отдельно. Кеш общих публичных фактов отделён от личных счетов и разрешений. Сроки торгов, праздники и технические перерывы берутся из источников, а не из предположения «биржа работает по будням».

2000 бумаг обрабатываются пакетами без потери хвоста списка. Планировщик отмечает полноту прохода и возраст каждой позиции. Очередь умеет продолжить работу после перезапуска; один медленный источник не блокирует остальные портфели.

Существующий цикл и ограничения: [R06], [R11]. Возможности и лимиты брокера: [S23-S24]. Указанные интервалы - проектные стартовые настройки.

## 17. Что анализируется в компании

_17 / ОТЧЁТНОСТЬ И БИЗНЕС · Страница 18 исходного PDF._

Сначала устанавливается юридический эмитент, связанная группа, гаранты и источник погашения долга. Затем собирается минимальный набор показателей, способный изменить решение. Красивое описание компании без связи с долгом, денежным потоком или ценой не увеличивает её инвестиционную привлекательность.

| Объект | Основные вопросы |
| --- | --- |
| Обычная компания | Хватает ли операционного денежного потока на проценты, инвестиции и погашения? Как меняются долг, свободные деньги, маржа и выручка? Есть ли крупное рефинансирование в ближайшие сроки? |
| Банк | Достаточность капитала, качество кредитов, резервы, ликвидность и структура фондирования. Показатель долг/EBITDA к банку механически не применяется. |
| Страховщик / финансовая группа | Капитал, страховые обязательства, резервы, качество активов и специальные требования сектора. |
| Облигационный выпуск | Очередность долга, обеспечение, гарантии, ковенанты, амортизация, оферта, право досрочного погашения, неизвестные будущие купоны. |
| Акция | Прибыль и свободный денежный поток на акцию, оценка бизнеса, долговая устойчивость, размытие капитала, дивидендная политика и качество управления. |
| Фонд | Состав и доли активов, комиссии, ликвидность, инфраструктура, отклонение от стоимости активов. Вложения проходят сквозные лимиты эмитентов и групп. |

Сначала используется консолидированная МСФО, где она доступна и уместна; РСБУ отдельного заёмщика дополняет её. Нельзя смешивать квартал и год, рубли и тысячи рублей, индивидуальную и консолидированную отчётность или разные даты. Отрицательная EBITDA не превращается в «хороший маленький» коэффициент долга.

ИИ извлекает факты из сложного текста или таблицы вместе со страницей, единицей и периодом. Код проверяет структуру, равенства, знак и согласованность сумм. Нераспознанная таблица или противоречие блокирует использование показателя. Пропуск раскрытия сам по себе не доказывает дефолт, но повышает неопределённость и может закрыть покупки.

API GetAssetFundamentals предоставляет показатели брокера; GetAssetReports - расписание публикаций, а не полный текст финансового отчёта. Для глубокого анализа нужны сами раскрытия компании и история исправлений. Календарь не выдаётся за прочитанную отчётность.

Источники и действующий анализ: [S12-S13], [S25], [R07-R10]. Состав показателей - проектное решение, различающее отраслевые модели.

## 18. Что математика может предсказать

_18 / ВЕРОЯТНОСТИ И СЦЕНАРИИ · Страница 19 исходного PDF._

Программа оценивает распределение возможных результатов и ранние признаки ухудшения. Она не вычисляет точный день дефолта. Рейтинг - порядковое мнение о кредитном качестве; автоматически назначать каждой букве постоянный процент вероятности нельзя.

| Расчёт | Для какого решения он нужен |
| --- | --- |
| Концентрация и общий фактор | Показать, насколько капитал зависит от одной группы, отрасли, ставки, валюты и страны. |
| Чувствительность облигаций | Оценить изменение цены и потока при изменении ставок, кредитной премии и инфляции; отличить риск цены от риска невыплаты. |
| Тяжёлые сценарии | Одновременные проблемы отрасли, падение рубля, рост ставок, исчезновение ликвидности, задержки выплат. Проверяется и сочетание событий. |
| Ожидаемый кредитный убыток | Сумма: размер требований × вероятность дефолта на заданном горизонте × доля потерь при дефолте. Только при обоснованных исходных оценках. |
| Худшая часть распределения | Expected Shortfall описывает среднюю потерю в тяжёлом хвосте выбранной модели. Это не максимальный возможный убыток. |
| Устойчивость решения | Проверить, останется ли покупка разумной при ошибках входных оценок; предпочесть устойчивое решение точному на вид прогнозу. |

В существующем коде уже есть ковариация, исторические оценки хвостового риска и совместная блочная пересборка истории. Частота потери в этих сценариях не является вероятностью банкротства в реальном мире. Старый сценарный порог 80% капитала не подменяет выбранную пользователем допустимую потерю.

Все выпуски компании связаны одним риском должника; группы и отрасли могут дефолтовать совместно. Сумма ожидаемых потерь не требует независимости, а вероятность «хотя бы одного дефолта» и тяжёлые совместные потери требуют модели зависимости. Дробление капитала снижает размер отдельного ущерба, но не обязательно вероятность встретить хотя бы один проблемный эмитент.

Собственная модель дефолта допускается после накопления достаточной истории, включая исчезнувшие компании и дефолты. Проверка идёт по времени, с данными, известными тогда: точность вероятностей, доля пропущенных событий и ложных тревог. Нельзя учить и проверять на одной истории или переносить старую американскую формулу на российские банки без проверки.

Модели и неопределённость: [S16-S17], [S26-S28], [R09]. Если вероятность не откалибрована, пользователю показывается качественный сигнал и причина, а не ложное число «0,3%».


<a id="plan-19"></a>

## 19. Новости, политика и интернет

_19 / ТОЛЬКО ЗНАЧИМЫЕ СВЯЗИ · Страница 20 исходного PDF._

Новость оценивается по цепочке: **событие → денежный поток или доступность → конкретная компания → доля в портфеле → действие**. Тональность заголовка сама по себе не является приказом купить или продать.

Ключевая ставка, курсы, инфляция, рейтинги и баланс поступают из актуальных источников. Фиксируются правила проверки, дата действия и версия, а не значения навсегда. Параметры стратегии - отдельная настраиваемая политика. [S31-S32]

| Нужно обрабатывать | Можно не обрабатывать глубоко |
| --- | --- |
| Санкции и изменения расчётной инфраструктуры, если они затрагивают должника, гаранта или выпуск. | Каждую политическую новость без установленной связи с активами или значимым сценарием. |
| Решения по ставкам, налогам, валютным правилам, отраслевым тарифам и лицензиям. | Повторения одной новости на десятках сайтов и общий эмоциональный фон. |
| Срыв платежа, ковенанты, рефинансирование, аудит, существенные судебные и корпоративные события. | Минутные свечи, технические фигуры и попытки угадать краткосрочный импульс для стратегии удержания. |
| Экспортные цены, выручка в валюте и критичные поставки для соответствующих компаний. | Цены всех товаров мира без измеримой чувствительности выбранных бизнесов. |

Официальный документ имеет приоритет над пересказом. Для ключевого факта сохраняются первичный URL, дата публикации, дата события, полученный фрагмент и время проверки. Неофициальная информация может инициировать проверку, но не становится подтверждённым рейтингом или основанием для точной сделки.

ИИ имеет доступ к поиску и чтению публичных источников через контролируемые серверные инструменты. «Полный интернет» не означает доступ к закрытым кабинетам, платным данным без договора или произвольному запуску кода. Внешний документ рассматривается как данные: команды внутри страницы не могут изменить стратегию, раскрыть токен или вызвать операцию со счётом.

### Как это укладывается в Timeweb

Обычные API и официальные ленты читает наш backend. Для сложного поиска используется отдельный Timeweb AI-агент с веб-поиском; затем backend проверяет найденные первоисточники. Сам вызов модели через AI Gateway не доказывает наличие интернета. Поиск отделён от финансового расчёта и от чата с личными данными.

У Timeweb веб-поиск оплачивается отдельно; модель может выполнить несколько запросов, а принудительное включение или запрет поиска на отдельный запрос не гарантируется текущим контрактом. Поэтому для финансовых событий используются заранее заданные источники, а поиск служит дополнением. Строгий лимит расходов на поиск требует отдельной технической проверки тарификации и контроля провайдера.

Источники: [S29-S31], [S38-S39]. Причинная цепочка - проектный подход; корреляция новости и движения цены не объявляется доказанной причиной.

## 20. Что делает код, а что делает ИИ

_20 / РАЗДЕЛЕНИЕ ОТВЕТСТВЕННОСТИ · Страница 21 исходного PDF._

| Задача | Исполнитель | Почему |
| --- | --- | --- |
| Счета, позиции, цены, деньги | Код и официальный API | Точные значения нельзя получать из памяти модели. |
| Порог BBB-, блокировки, права | Код | Это обязательные запреты, их нельзя отменить рассуждением. |
| Доли, лоты, доходности, налоговый резерв | Код | Расчёт воспроизводим и проверяется независимо. |
| Чтение сложной отчётности | Парсер, затем ИИ при необходимости | ИИ извлекает текстовые факты, код проверяет числа и привязку к документу. |
| Новость и её смысл для бизнеса | ИИ с первоисточником | Нужны понимание контекста и связи; факты сохраняются отдельно от гипотез. |
| Сценарии и оптимизация портфеля | Код | ИИ может объяснить предпосылки, но не подставляет произвольные цены и вероятности. |
| Понятное объяснение и диалог | ИИ | Нужен естественный язык, адаптированный к вопросу пользователя. |
| Проверка готового действия | Отдельный программный валидатор | Даже правильный текст модели не доказывает допустимость покупки. |
| Уведомление о критическом событии | Код и шаблон | Сигнал не должен ждать ответа модели или наличия платного лимита. |

### Общий контракт

Каждый результат ИИ ссылается на факты из конкретного снимка: источник, дата, объект, подтверждённое значение и степень неопределённости. Вывод без доказательства не записывается как факт. Числовые параметры действий заполняются сервером из результата расчёта, а не извлекаются из красивого текста.

Алгоритм формирует объект действия: счёт, инструмент, сторона, количество лотов, предельная цена, бюджет, причина, сроки и версия источников. ИИ переводит его на простой русский язык. При несовпадении числа в тексте и объекте публикуется проверенный шаблон.

Структурированный JSON и разрешённый source_id уже проверяются в проекте. Но это только проверка формы и существования ссылки, а не истинности экономического утверждения. Нужен контроль соответствия утверждения конкретному месту источника и числовая сверка.

При недоступном ИИ продолжаются сбор данных, лимиты, обязательные запреты и шаблонные инструкции. Система и ИИ дополняют друг друга, но базовая защита не зависит от платного ответа модели.

Существующие механизмы: [R06], [R12-R14]. Новое разделение расширяет их; не требуется постоянный «совет» из нескольких моделей на каждую бумагу.

| --- | --- | --- |
| Без ИИ | Опрос API, сортировка, кеш, лимиты, расчёты, дедупликация, стандартная тревога. | Бесплатные для LLM детерминированные функции. |
| Быстрый | Классификация новости, краткий ответ, извлечение простого фрагмента, команда интерфейса. | Небольшая модель из каталога Timeweb; кандидат GPT-4.1 Mini или доступная Flash-модель после проверки качества. |
| Основной | Объяснение портфеля, анализ отчёта средней сложности, связывание подтверждённых событий. | Модель общего назначения. Публичный калькулятор на дату проверки показывает GPT-6.1 Sol; точный ID и доступность подтверждаются в аккаунте. |
| Углублённый | Сложные противоречия, реструктуризация, неоднозначные условия выпуска, проверка важного вывода. | Сильная reasoning-модель из актуального каталога, например GPT-6 Astra; только по обоснованному событию. |

Названия - стартовые кандидаты, а не утверждение о подключённых моделях. Выбор выполняется на наборе русскоязычных реальных документов с эталонными ответами. Меньшая цена оправдана только при нужной точности извлечения и корректном отказе при нехватке данных.

### Правила экономии

Один отчёт компании анализируется один раз на версию. Общие выводы повторно используются для всех пользователей, а личное влияние пересчитывается отдельно. В модель передаётся нужный фрагмент и компактный снимок, а не весь архив. Чат использует краткое резюме истории с возможностью проверить исходный диалог.

Глубокое рассуждение включается для сложности, а не по цене портфеля или эмоциональному заголовку. Второй независимый разбор допустим для спорного критического факта; постоянное голосование трёх моделей не нужно. У критического события сначала публикуется безопасный проверенный сигнал, затем уточнение.

### Ограничители

Лимиты по пользователю, проекту, дню и месяцу; отдельный резерв на важные события. Перед запросом резервируется стоимость входа, выхода и возможных платных инструментов. Неизвестное списание не повторяется автоматически. Смена модели или тарифа требует обновления привязки цены. Цена из публичной страницы не подменяет счёт провайдера.

Доступные параметры reasoning, кеширования и пакетной обработки проверяются для конкретного маршрута Timeweb. Нельзя молча отправлять неподдерживаемый режим или рассчитывать бюджет по скидке, которую этот маршрут не предоставляет.

Каталог, тарифы и ограничения: [S29-S30], [S36-S37], [S43-S44]. Действующие механизмы резервирования: [R12-R14].

## 22. Чат как рабочее место пользователя

_22 / АССИСТЕНТ · Страница 23 исходного PDF._

Чат поддерживает обычный разговор, вопросы о финансах, текущем портфеле, выбранной стратегии и устройстве приложения. Он не ограничивается автоматическими сообщениями. При вопросе о личных деньгах сначала получает фактический снимок через разрешённый инструмент, а затем отвечает.

| Просьба | Как выполняется |
| --- | --- |
| «Смени тему на светлую» | Ассистент вызывает только разрешённую команду смены темы и сообщает результат. Откат доступен сразу. |
| «Что мне делать сейчас?» | Показывается существующий актуальный план действий; новый расчёт запускается только при изменениях. |
| «Почему снизился портфель?» | Отделяются пополнения, выводы, выплаты, переоценка и валюта. Влияние новости называется подтверждённым только при наличии основания. |
| «Убери BBB из стратегии» | Показывается точное изменение правил и его последствия. После подтверждения создаётся новая версия стратегии; запрет BBB- остаётся нижней границей. |
| «Подготовь пост за месяц» | Создаётся текст с нужным стилем и эмодзи по реальным операциям и итогам периода. Публикация в Telegram автоматически не выполняется. |
| Общий вопрос вне портфеля | Ответ обычного ассистента. Актуальные факты проверяются поиском; личные счета для такого запроса не передаются. |

Настройки, меняющие риск, резерв, рынки и режим реинвестирования, требуют короткого подтверждения точной правки. Это не выбор из трёх инвестиционных идей, а защита от неверного понимания команды. Простые обратимые настройки интерфейса выполняются сразу.

Чат не получает произвольный SQL, shell, торговый токен или административный ключ Timeweb. Набор инструментов ограничен чтением своего портфеля, подготовкой плана, изменением разрешённых настроек и созданием черновиков. user_id определяется серверной сессией, не текстом сообщения.

При недостатке данных ответ остаётся коротким и практичным: «Сейчас сохраняем деньги. Повторю расчёт после обновления котировки» или «Обновите подключение Т-Инвестиций». Полная причина и источник раскрываются по нажатию. Отсутствие сведений не заполняется вымышленным результатом.

Диалоги изолированы по пользователям; период хранения настраивается. В модели не передаются токены, Telegram ID и номера счетов. Для объяснения обычно хватает обезличенных сумм, долей и разрешённых фактов. Общие документы компании кешируются отдельно от личной переписки.

Свободный чат - новая функция. Прежнее правило проекта «пользователь не отправляет промпты» заменяется этим запросом владельца при будущей реализации. [R01], [R12-R14]

## 24. Уведомления без спама

_24 / ДОСТАВКА И ДЕЙСТВИЯ · Страница 25 исходного PDF._

Под «SMS от приложения» в этом плане понимается системное Android-уведомление, которое раскрывается в подробную карточку и ведёт в нужное место. Настоящее операторское SMS требует отдельного сервиса и тарифа; в базовой схеме оно не используется.

Событие и карточка сохраняются одной транзакцией с заданием доставки. Уведомление имеет ключ «пользователь + событие + действие»: повторная проверка обновляет его, а не создаёт десять одинаковых сообщений. Устаревшее действие автоматически закрывается. Нажатие заново проверяет право доступа и актуальность плана.

| Приоритет | Поведение |
| --- | --- |
| Срочно | Подтверждённое падение ниже BBB-, недоступность значимой позиции или потеря наблюдения, требующая вмешательства. Одно сообщение при переходе состояния, затем только существенное изменение или настроенное напоминание. |
| Нужно действие | Появились деньги и готова покупка; требуется значимое выравнивание. Объединять близкие события в один план. |
| Информационно | Итоги, обычные новости и успешные проверки не отправляются по умолчанию. Доступны в приложении и по запросу чата. |

### Ограничение «только приложение и Timeweb»

На сервере можно надёжно сохранять события 24/7. На телефоне WorkManager имеет минимальный период 15 минут и может откладываться системой. Постоянный WebSocket обычного приложения не гарантирует работу в Doze, после принудительной остановки или без сети. Скрытый непрерывный сервис не является надёжной заменой push.

**Базовая версия при вашем ограничении:** полный серверный центр уведомлений, обновление при открытии приложения и фоновая проверка по возможностям Android. Срочная доставка в произвольный момент не гарантируется. Это ограничение нужно сохранить в описании продукта, а не маскировать настройкой таймера.

Если позже потребуется быстрая фоновая доставка, нужен разрешённый внешний транспорт push, например FCM для совместимых устройств, либо другой подтверждённый канал. FCM может быть бесплатным транспортом, но это всё равно дополнительная зависимость. Он также не даёт абсолютной гарантии доставки. Подключение такого канала не выполнялось и не считается согласованным этим документом.

Тихие часы настраиваются; срочные исключения выбирает пользователь. На экране блокировки по умолчанию скрыты суммы и состав портфеля. Обычный ежедневный отчёт не превращается в push, если действий нет.

Официальные ограничения: [S34-S35]. Гарантия существования события на сервере отделена от своевременного прочтения человеком.

## 25. Серверная архитектура на Timeweb

_25 / ПРОСТАЯ СИСТЕМА · Страница 26 исходного PDF._

Остаётся один модульный backend приложения: HTTP API, существующий планировщик и ограниченные обработчики задач. SQLite сохраняется на первом этапе; сетевой брокер очередей, Kubernetes, отдельная база на каждого человека и GPU не нужны. Тяжёлое ИИ-вычисление оплачивается по API.

| Модуль | Ответственность |
| --- | --- |
| Доступ и подключения | Пользователи по приглашениям, устройства, сеансы и шифрование токенов. |
| Общие рыночные данные | Компании, группы, инструменты, рейтинги, отчёты, события и применимость источников. |
| Личный портфель | Счета, позиции, операции, остатки, история и ограничения каждого пользователя. |
| Правила и планировщик | Версии стратегий, проверки допуска, сценарии, расчёт лотов и состояние исполнения действий. |
| ИИ | Маршрутизация задач, разрешённые инструменты, контроль доказательств и расхода. |
| Уведомления и аудит | Журнал причин, доставка, прочтение, исполнение и восстановление после сбоев. |

Все личные записи и кеши включают user_id; права проверяются при каждом запросе. Общая таблица публичных фактов не содержит личных денег. Одна и та же компания обрабатывается один раз, а воздействие на разные портфели - независимо.

### Начальная мощность и запас

Сначала измеряется уже имеющийся сервер. Для первого запуска ориентир - 2 vCPU и 4 ГБ памяти, если текущей машины достаточно и не выполняется тяжёлый локальный OCR. Это оценка, не заказ нового тарифа. Пиковые задачи ограничены очередью; OCR и глубокие симуляции не выполняются одновременно без необходимости.

Производительность проверяется на пяти активных пользователях, удвоенном кратком всплеске запросов и до 2000 позиций на человека. Это испытание запаса, а не разрешение регистрации дополнительных людей. Ограничение пользователей не связано с числом процессов или размером капитала.

SQLite требует коротких транзакций, индексов, контроля блокировок и согласованных резервных копий. Переход на другую СУБД рассматривается только при измеренных задержках, необходимости нескольких записывающих узлов или требовании высокой доступности. Старую PostgreSQL-архитектуру из истории проекта не восстанавливаем.

Нагрузка определяется количеством данных и задач. 100 млн ₽ на счёте с 30 позициями не тяжелее 100 тыс. ₽ с 2000 позициями. Основа текущей архитектуры: [R02], [R06], [R08], [R14].

## 26. Качество данных и восстановление

_26 / НАДЁЖНОСТЬ · Страница 27 исходного PDF._

Каждый факт имеет объект, единицу, валюту, период, источник, время публикации, время получения и срок допустимой свежести. Сохраняются версия исходного документа и причина исправления. Изменение записи создаёт новую версию, а не незаметно переписывает прошлое.

| Ситуация | Поведение |
| --- | --- |
| Источник временно недоступен | Ограниченные повторы с увеличением интервала. Старые сведения помечаются; новые покупки по зависимым данным приостанавливаются. |
| Разные источники расходятся | Фиксируется конфликт. Последний ответ API не объявляется правильным только потому, что пришёл позже. |
| Изменился профиль во время расчёта | Результат старой версии не публикуется как действующий; выполняется пересчёт. |
| Не все позиции оценены | Не показывается фиктивная полная стоимость и точная «защищённость». Проверяемая часть и неполнота учитываются отдельно. |
| Ошибка платного запроса ИИ | Неопределённое списание остаётся зарезервированным до сверки. Повтор не маскируется под бесплатную попытку. |
| Падение backend | Задания восстанавливаются из базы, повторные эффекты подавляются ключами идемпотентности; сохранённые действия сверяются с текущими данными. |

### Резервные копии

Ежедневная копия приложения и согласованный архив SQLite; более частая копия важных данных по целевому RPO до одного часа. База, настройки, история фактов и журнал действий сохраняются в отдельном хранилище Timeweb S3. Fernet-ключ резервируется отдельно с ограниченным доступом. Копия без ключа не восстановит токены.

Плановое время восстановления до четырёх часов проверяется учебным восстановлением; это цель эксплуатации, не уже достигнутая гарантия. Переустановка приложения не должна уничтожать серверную историю. Раз в месяц проверяется реальное восстановление из копии, а не только наличие файла.

### Наблюдение за самой системой

Измеряются возраст последней успешной проверки, заполненность очереди, доступность источников, доля охваченных позиций, ошибки валидации, длительность расчёта и расход рублей. Технический сбой, лишающий пользователя наблюдения, может требовать одного отдельного уведомления.

Один сервер не обеспечивает непрерывность при любой аварии. 24/7 означает постоянный режим работы; высокая доступность и независимый резерв в другой зоне - отдельное увеличение стоимости после измерений и согласования. Дешёвая конфигурация не должна называться безотказной.

Существующие механизмы: [R08], [R11-R14]. Копии и отдельное хранение: [S41-S42].

| Два обмена одним кодом / чужой Telegram | Сеанс получает только один корректный запрос; неприглашённый пользователь отклонён. |
| ИИ выдумал цифру или ссылку | Ответ не попадает в действие; используется проверенный расчёт или отказ. |
| Таймаут ИИ и исчерпанный бюджет | Нет бесконтрольного повтора или дорогого переключения; базовые предупреждения работают. |
| Один риск проверен десять раз | Одна актуальная карточка, без спама; исполнение и отмена меняют её состояние. |
| Обновление и восстановление из копии | Сохраняются аккаунт, история и расшифровка токена; APK подписан правильным сертификатом. |

Это спецификация будущих проверок, а не отчёт об их прохождении. Дополнительно проверяются недоступные источники, скрытые инструкции в веб-страницах, изменения стратегии во время расчёта, реальные App Links и брокерские переходы.

## 33. Доход за время: правильная цель

_33 / ДОЛГОСРОЧНЫЙ РЕЗУЛЬТАТ · Страница 34 исходного PDF._

Инвестирование - обмен текущих денег на будущие денежные потоки и изменение стоимости с риском. Преимущество вашей системы должно заключаться в дисциплине: регулярно вкладывать доступные средства, сохранять качественные активы, реинвестировать доход и не переплачивать за ненужные действия.

У Баффета полезны внимание к бизнесу, долгому сроку и издержкам; у индексного подхода Vanguard, связанного с Джоном Боглом, - широкое распределение и низкая стоимость. Их нельзя переносить как готовые доли американского рынка на российский. В приложении используются принципы, а не копирование сделок знаменитого инвестора.

### Что даёт сложный процент

Если выплаты реинвестируются, будущий доход начисляется и на ранее заработанное. При изъятии всех купонов эта часть эффекта исчезает. Пополнение - вклад пользователя, не инвестиционная прибыль. Высокая номинальная сумма через десятилетия оценивается в покупательной способности, а не только в рублях будущего года.

| Условный сценарий на 30 лет | Итог в сегодняшних рублях |
| --- | --- |
| 10 000 ₽ ежемесячно; реальная чистая доходность 0% | 3,60 млн ₽ |
| Те же взносы; реальная чистая доходность 2% | Около 4,91 млн ₽ |
| Те же взносы; реальная чистая доходность 4% | Около 6,85 млн ₽ |

Это математические сценарии, не прогноз. Стартовый капитал 0, взносы в конце месяца, их номинал индексируется для сохранения 10 000 ₽ покупательной способности. Доходность постоянная, уже после инфляции, налогов и издержек; реальные результаты могут быть хуже, включая убытки. Расчёт: месячная ставка = (1 + годовая)^(1/12) - 1; сумма 360 взносов с начислением.

### Новичок и опытный инвестор

Разница не в доступе к максимальному риску, а в понимании цели, горизонта, качества данных, издержек и собственной способности выдержать снижение. Приложение одинаково защищает новичка и опытного пользователя от концентрации, заёмных покупок, погони за купоном и уверенности в единственном прогнозе.

Ликвидность означает возможность выполнить нужный объём по приемлемой цене, а не просто наличие последней сделки. Высокий купон может компенсировать повышенный риск. Держать до погашения полезно для планирования потока, но только если должник платит и пользователю не нужны деньги раньше.

Стать миллионером при долгом накоплении математически возможно. Достижение конкретной суммы определяется взносами, сроком, расходами, реальной доходностью и неблагоприятными сценариями. План строится от этих условий, а не от обещания «лучшая компания всегда вырастет».

## 34. Итоговый контракт разработки

_34 / ЧТО СЧИТАЕТСЯ РЕЗУЛЬТАТОМ · Страница 35 исходного PDF._

Готовая программа - персональная система контроля капитала с доказуемым источником каждого существенного числа, версионируемыми правилами и одним исполнимым планом. Телефон показывает компактный результат; Timeweb собирает сведения и наблюдает портфель постоянно.

| Вопрос из постановки | Зафиксированное решение |
| --- | --- |
| «Сама инвестирует» или кнопка брокера? | Автоматизирован анализ и выбор действия; торговая операция подтверждается пользователем в Т-Инвестициях. |
| Ежедневная доходность? | Ежедневный контроль результата и реинвестирование фактических поступлений; ежедневная прибыль не гарантируется. |
| Рейтинг и разнообразие? | Жёсткий диапазон AAA - BBB-, дополнительные запреты пользователя, лимиты компании и группы, не число тикеров. |
| Нет денег? | Наблюдать имеющееся, ждать поступления; не продавать только ради новой покупки. При обязательном выходе заранее готовить условную замену. |
| Один или пять пользователей? | Одна инфраструктура, общие публичные факты, полная изоляция личных данных, закрытые приглашения и проверенный запас нагрузки. |
| Только Timeweb? | Backend, копии, ИИ и поиск в рамках Timeweb; внешние источники данных остаются необходимыми. Быстрый push требует отдельного разрешённого транспорта. |
| Минимум терминов? | Понятное действие и короткая причина на первом экране; расчёт, источники и неопределённость доступны в деталях. |

### Условия реального, а не демонстрационного запуска

Нужны разрешённые и технически проверенные источники рейтингов/отчётности, действующий брокерский доступ, подтверждённый бюджет моделей и проверенное восстановление. Если какой-то источник не покрывает рынок, охват считается и показывается честно; обещание «проанализированы все компании» не выводится.

Для личного использования инструмент остаётся помощником владельца. Доступ даже четырёх знакомых и конкретные персональные указания требуют отдельной проверки применимости правил об инвестиционном консультировании и обработке данных. Название «готовое решение, а не совет» не меняет правовую сущность функции; этот вопрос решается до расширения доступа, не отказом от подготовки программы.

Для пяти человек нельзя оправдать собственную большую модель, круглосуточное чтение всего интернета или дорогую распределённую инфраструктуру. Нельзя экономить на полноте позиций, источниках критических фактов и проверке денег. Самый полезный первый выпуск после укрепления основы - точные лимиты риска и готовый план на реальные поступления.
