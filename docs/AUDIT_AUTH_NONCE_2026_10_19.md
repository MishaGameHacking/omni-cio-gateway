# F06 / F23 — проверка nonce входа, 19.10.2026

## Область и причина

Проверенный `backend/telegram_browser_app.py` имеет одинаковый Git blob
`73dbb9db8ff1263a8e776bbd899fee071c39e863` на main
`12b5b1fb4f536ae44ddbb01b74e1e9401ccace26` и на срезе 0.11.0
`20f43530f071fc5b351e39e941c77406f2e582a4`.

Проверка подписи уже выполнялась до сравнения nonce, но secrets.compare_digest
принимает только ASCII для аргументов str. Подписанный nonce с Unicode вызывал
TypeError, который не перехватывается как TelegramTokenError. Это дефект
обработки недействительного входа, а не доказанный обход подписи или захват
аккаунта. Для воспроизведения использованы локальные временные RSA-ключи;
доступа к настоящему подписывающему ключу Telegram нет и не требуется.

Исправление проверяет тип, непустое значение и ASCII обоих nonce до сравнения.
Приложение генерирует nonce через token_urlsafe. Регистр сохраняется; нет
str-приведения неверного типа, нормализации или принятия отсутствующего nonce.
Валидатор возвращает штатный TelegramTokenError, который существующий endpoint
преобразует в отказ 401. Подпись RS256, pinned JWKS, issuer, audience, exp/iat,
обязательные claims и прежние ограничения срока не ослаблены.

## Регрессия

12 тестовых методов с реальными RS256 подписью/проверкой и временным JWKS:
верный nonce; Unicode и surrogate; неверный тип; пустой/неверный expected;
регистр; чужая подпись, issuer/audience и просроченный токен. До исправления
на целевом наборе: 1 failure и 11 errors, включая подслучаи. После: 12 методов
прошли без пропуска. Исходный файл локально сверён по полному Git blob SHA;
тест компилирует реальные определения валидатора из исходника, не импортируя
сервер с его маршрутами, секретами и планировщиком. jwt.decode не подменяется.
Это тест валидатора, не live Telegram или сквозной HTTP/device сценарий.

```sh
python -m unittest discover -s backend/tests -p test_telegram_nonce_boundaries.py -v
```

Изменение подготовлено как для 0.11.0, так и отдельным обратным переносом на
основную линию: без merge всей разработки. Main, сервер, APK, версия SDK,
сохранённые секреты и канал обновлений этим действием не меняются. Полный CI
каждого нового SHA остаётся обязательным. Общий аудит старых замечаний main
не закрывается этим локальным исправлением.
