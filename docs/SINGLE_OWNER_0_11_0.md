# Analyst AI 0.11.0 — единственный владелец и конкретный план действий

## Решение OWNER 19.10.2026

Один владелец; только его подтверждённая Telegram-личность, портфели, счета,
задания и бюджет. Несколько его устройств и брокерских счетов сохраняются.
Это заменяет прежние требования «до пяти аккаунтов». Пользователь сообщил,
что удалил ресурсы Timeweb; восстанавливать чужие/старые пользовательские данные
не требуется. Источник восстановления приложения — исходный код GitHub,
а не резервная копия персональных данных.

Android 17+ (API37), Galaxy S25 Ultra с указанными владельцем Android17/One UI9.
Номера телефона, IMEI и серийный номер не нужны и в репозитории не сохраняются.
3D/Filament, нативный ввод, доступность и инвестиционная логика сохраняются.
Главный экран — капитал, существенные риски и конкретные действия/ожидание;
графики преимущественно внутри подробностей, не копия брокерского терминала.

## Что реализовано в этом срезе — F02/F15/F16/F20/F22/F23

`backend/owner_access.py` связывает установку с явно настроенным
`ANALYST_OWNER_TELEGRAM_SUB`. Значение берётся из защищённой конфигурации нового
сервера и сравнивается с `telegram_sub`, который существующая авторизация
получает из проверенного подписанного ID-токена Telegram. Ник, имя,
«первый вошедший», данные телефона или профиль GitHub не выбирают владельца.
Отсутствие значения не открывает регистрацию: запуск прекращается.

`backend/owner_app.py` — новый ASGI factory:

```
uvicorn owner_app:create_app --factory --host 127.0.0.1 --port 8080 --workers 1
```

Factory сохраняет существующие проверку подписи/nonce, одноразовый code exchange,
сессии и scheduler. Owner-binding проверяется до его запуска и после миграций.
SQLite-триггеры запрещают другого пользователя, подмену ID/subject,
INSERT OR REPLACE владельца, перепривязку installation registry и записи
чужого/null user_id в таблицах с такой колонкой. Другие существующие аккаунты
или осиротевшие записи останавливают старт; ничего не удаляется и не присваивается.
Сохраняются несколько сессий владельца. Новые user_id-таблицы защищаются при
следующей инициализации. HTTP с отключённым lifespan получает 503, не bypass.

`deploy/analyst-ai-owner.service` — единичный systemd-процесс без root,
с обязательным EnvironmentFile, writable /var/lib/analyst-ai и без реплик.
Это шаблон для новой установки: его добавление не создаёт сервер и не запускает
вторую службу. Старый миграционный deploy для удалённого сервера нельзя запускать
как установщик нового. Действующий старый entrypoint — внутренний код совместных
маршрутов; новая одиночная установка обязана использовать owner_app factory.

`backend/allocation_plan.py` — вычислительное ядро черновика распределения:
целые лоты, заданная целевая стоимость, резерв, комиссия с округлением вверх,
доступные собственные лоты, видимая ликвидность, общие ограничения концентрации
для разных счетов. Один денежный остаток списывается только один раз.
Неподтверждённая продажа не финансирует покупку и не освобождает риск-лимит.
Непроверенная валюта, противоположные действия для одного инструмента,
дубли и просроченный снимок отклоняются. При недоступном лоте — «ждать».

Порядок кандидатов: приоритет подтверждённой стратегии, счёт, instrument UID.
Это детерминированный приоритетный расчёт, НЕ доказательство глобального оптимума
или будущей доходности. Targets, приоритеты и риск-лимиты должны поступать из
ещё интегрируемого проверенного профиля/исследования. Цена ядра — денежная цена
одной бумаги, НЕ процентная цена облигации и НЕ параметр PostOrder.
Комиссия — оценка по заданной формуле, не квитанция брокера. Перед действующей
рекомендацией обязательны новая проверка GetOrderPrice/GetMaxLots/стакана,
пригодность актива, общий резерв плана и контроль версии/срока внутри транзакции.

Результат намеренно содержит `state=draft`, `suitability_complete=false`,
`optimality_claimed=false`, `automatic_order=false`,
`requires_fresh_broker_validation=true`. Ядро не опубликовано отдельным
непроверенным HTTP endpoint и пока не связано с экраном рекомендаций.
Фактическую сделку подтверждает владелец в Т-Инвестициях; PostOrder не добавлен.

## Проверки и границы

Локально: 45 тестов / 537 subtests, включая 500 seeded случаев сравнения
расчёта доступных лотов с полным перебором, реальный SQLite с параллельными
соединениями и изолированный ASGI lifecycle. Синтаксис новых Python-файлов
проверен. Это не полный backend, не живой Telegram/брокер и не эмулятор.

Дополнительный CI integration test запускает настоящий owner factory и
существующий Telegram browser/session код в отдельном процессе/пустой БД
с синтетическим RSA-ключом: владелец с двух устройств, replay code и другой
пользователь с тем же отображаемым именем. Его результат проверяется в CI;
наличие файла само по себе не означает успех теста.

Остаются: инфраструктура Timeweb с измеренными ресурсами; привязка фактического
Telegram subject владельца; подключение ядра к подтверждённым данным и UI;
полный риск-профиль и источниковое исследование; миграция SDK/CI/доказательств на
API37; упрощение главного экрана; полный прогон APK и проверка на телефоне.
Существующий minSdk35/target36 этим серверным изменением не изменён.

Новый сервер/APK/канал не объявляются развёрнутыми. Автоматической покупки
ресурсов, удаления, восстановления пользовательских данных и merge нет.

## Ресурсы Timeweb

Один сервер и один backend worker; модели по API, без локального GPU, Kubernetes,
балансировщика, реплик и отдельной БД ради одного человека. Объём выбирается
после проверки доступного тарифа, ОС, зависимостей, логов, SQLite WAL и места
для обновления. Размер приложения 2,7–3 ГБ не равен полному требованию диска.
Вычислять необходимое рабочее пространство, а не резерв на будущих пользователей.
Основной диск Timeweb нельзя уменьшить на месте; рост — по измеренной потребности.
