# OMNICIO — канонический план системы

Основание: уточнение владельца от 11.10.2026 — только Telegram и VK ID, персональные торговые поручения и ИИ-чат; продажа подписок исключена из текущего продукта. Серверная аналитика обслуживает один Android-клиент. Презентационный сайт отменён последним поручением владельца; личная работа выполняется в приложении. omnicio.ru пока остаётся техническим HTTPS origin API, OAuth callbacks и документов. Все долговременные финансовые/персональные записи — в существующем tenant-isolated PostgreSQL Timeweb. Android держит ответы и секреты только в памяти. Нет деморежима или ненужных постоянных дубликатов серверов и рабочей базы. Резервные архивы и временная проверка восстановления разрешены владельцем; использовать существующую инфраструктуру.

## Целевая работа

Уточнение OWNER от 11.10.2026 20:08 МСК: OMNICIO на основе портфеля пользователя и реальных данных из интернета выдаёт пользователю персональные торговые поручения. План должен содержать конкретное действие, инструмент и рассчитанный объём, основания, источники и время актуальности. Общая аналитика и чат не заменяют этот результат. Текущая реализация и её готовность описываются отдельно от цели.

Система сопоставляет реальный портфель с подтверждённой целью и ограничениями, замечает существенные изменения, готовит один согласованный план только при достаточных данных. Общий анализ эмитента выполняется один раз; изменение общего факта направляется только затронутым портфелям. Деньги, лоты, расходы, ограничения и последовательность считает код. ИИ извлекает факты из документов и помогает объяснять подтверждённые причины. Навигация и повторное чтение сохранённого ответа не вызывают LLM. Новый вопрос в чате запускает ограниченный серверный запрос с проверенным контекстом пользователя.

## Минимальная архитектура

Сохраняем существующий API, PostgreSQL и фоновые задания на том же VDS. Это модули одной системы; отдельные серверы, Kafka, отдельная векторная БД и микросервисы для первого выпуска не нужны. Масштабирование допускается после измерения нагрузки и отдельного решения владельца.

| Модуль | Ответственность | Основа и разрыв |
|---|---|---|
| Доступ | Telegram/VK ID → подтверждённая серверная сессия → собственный профиль | Social auth и привязка реализованы в ветке; серверный email API и SMTP-зависимость deployer ещё требуют вывода из текущего login-контракта |
| Счёт | Read-only подключение, позиции, деньги, блокировки, поручения, операции | Снимки и свежесть есть; endpoint операций пока возвращает 410. До сбора/сверки потоков историческая доходность недоступна |
| Источники | Официальные сведения об инструментах, отчёты, события и новости с доказательствами | Есть adapters/evidence store; нужны настроенные разрешённые источники и проверенное покрытие |
| Расчёты | Decimal-арифметика, результат, концентрация, резерв, выплаты, сценарии и версии плана | Есть аналитика/guards/drafts; полный денежный учёт и единый актуальный план не завершены |
| Помощник | Фоновая обработка общих фактов, персональные события, чат с контекстом | Есть server assistant/store и контекст портфеля, текущий адаптер использует Ollama. В Android пока только лента. Нужны нативный чат, серверная конфигурация выбранной модели и проверка разрешённого маршрута данных |

Android показывает результаты и отправляет действия только через HTTPS API OMNICIO. Долговременная история чата, условия и результаты хранятся на сервере с разделением пользователей; устройство хранит ответы только в памяти. Без сети вход, новый расчёт и ответ ИИ недоступны: приложение показывает это явно. При ошибке текущий клиент очищает финансовый экран; никакого перехода на фиктивные цифры нет.

## Как сервер получает инвестиционные факты

1. Каталог связывает инструмент с UID/ISIN/тикером и эмитентом. Поиск по названию помогает обнаружить материал, но не доказывает соответствие бумаги.
2. Серверные adapters получают разрешённые данные биржи, Банка России, раскрытия эмитентов и рейтинговых агентств. Интернет-поиск служит обнаружению первоисточника; поисковый сниппет и перепечатка не становятся финансовым фактом.
3. Документ сохраняется с URL первоисточника, датой публикации, временем получения, отчётным периодом и хешем содержимого. Повторы объединяются; исправления сохраняют версии. Свежесть определяется отдельно для котировки, отчёта и новости.
4. Парсеры и ИИ извлекают структурированные сведения. Код проверяет единицы, даты, идентификаторы, ссылки на фрагменты и противоречия. Непроверенный результат не публикуется как факт.
5. Изменение связывается с затронутыми инструментами и портфелями; пересчитываются зависимые показатели, затем создаётся одно существенное событие.

Начальный охват: реальные позиции пользователей и ограниченный проверенный набор доступных кандидатов, а не весь интернет. Пользовательский брокерский токен не используется для общей ретрансляции рынка. Разрешение на доступ/использование источника подтверждается до включения.

## Как ИИ знает портфель

Перед ответом сервер выбирает пользователя исключительно по действующей сессии, читает разрешённый счёт, последний согласованный снимок, условия, рассчитанные показатели и относящиеся к вопросу проверенные факты. Контекст содержит версии и время, а не весь архив без разбора. История чата сама по себе не является достоверной текущей позицией или ценой.

Модель объясняет причины и сравнивает сценарии. Деньги, проценты, комиссии и лоты считаются кодом; ответ с финансовыми числами проверяется относительно расчётных результатов. При недостатке/устаревании данных помощник сообщает ограничение. Ответ хранит источники и версию использованного снимка; при смене счёта или обновлении контекста запоздалый результат не выдаётся за актуальный.

Чат имеет поле ввода, состояние отправки/ответа, отмену и повтор после ошибки, историю на сервере и явную отметку актуальности. Повтор одного request ID не должен создавать второй платный вызов. Ошибка модели не скрывает доступные подтверждённые показатели. Открытие вкладки не вызывает модель.

Разрешённые операции помощника ограничены чтением подтверждённого контекста и вызовом детерминированных расчётов. Внешние тексты считаются данными, не инструкциями: они не могут менять системные правила, отправлять секреты или открывать произвольные внутренние URL. Изменение условий требует явного подтверждения пользователя. Целевой результат включает выдачу персонального торгового поручения пользователю; отправка заявки брокеру не входит в read-only интеграцию. Перед выдачей проверяются данные, расчёты и условия выпуска из раздела «Аналитика и риски».

## Деньги и сверка

Позиции, денежные остатки, блокировки, доступные собственные средства, поручения и операции — отдельные факты с идентификаторами и временем. Противоречие или частичное обновление блокирует зависимый расчёт. Отсутствующее значение не становится нулём. Один повтор брокерского события не создаёт второй приход. Исправление операции пересчитывает зависимые показатели.

Бюджет = max(0, доступные собственные деньги − подтверждённый резерв − запас на расходы). Если брокерский остаток уже учитывает блокировки, повторно их не вычитать. Не подтверждённые продажи, ожидаемые купоны/дивиденды и номинал погашения не признаются фактической прибылью/свободным бюджетом.

Сначала подтверждённая продажа, затем проверка реально доступных денег, затем расчёт возможной покупки. Частичное исполнение и самостоятельные операции у брокера инвалидируют зависимые суммы. Ссылка «Открыть в Т-Инвестициях» не меняет исполнение; нужны проверенные UID/тикер/ISIN/лот и допустимая ссылка.

## Версии и условия

Профиль содержит цель, срок потребности, резерв, подтверждённую способность/готовность к потерям, валюту цели, использование выплат и известные обязательства. Не угадывать личные обстоятельства. Изменения принимаются с expected_version; конфликт сохраняет правку и предлагает перечитать состояние. Нельзя молча увеличивать риск или срок цели.

План ссылается на пользователя/счёт, версию условий, снимок, рыночные наблюдения, бюджет и фактическое исполнение. Существенное изменение любого входа требует нового расчёта. Состояния: требуется информация, готовится, подходящего действия нет, актуален, неактуален, ожидается подтверждение, исполнен частично, подтверждён. Не показывать старые суммы как действующие.

## Аналитика и риски

Приоритет: имеющиеся позиции, реальные кандидаты и связанные факторы. Оцениваются эмитент/группа, отрасль, ставки, сроки, валюты, кредитное качество, пересечение фондов и ликвидность. Для разных отраслей отдельные методы. Доступные деньги/финансирование сопоставляются с обязательствами и качеством денежных потоков. Источник и неопределённость остаются рядом с выводом. Вероятность банкротства не придумывается моделью.

Общие состояния риска: наблюдение, проверка, подтверждённое ухудшение, несоответствие условиям. Конкретные персональные BUY/SELL/HOLD, количества и замены входят в целевой продукт; их production-активация остаётся за действующим regulated gate. Активация требует отдельного принятого правового/методического evidence; дисклеймер или отсутствие автоторговли не заменяют этот gate.

Одинаковые документы/перепечатки не усиливают сигнал. Существенное официальное событие может запустить внеочередную проверку. Прогнозы не гарантируют предотвращение дефолта/убытка. Качество проверяется по ложным предупреждениям, пропускам, своевременности, исполнимости и полной стоимости перестроек, включая восстановившихся эмитентов.

## Фон и ИИ

Целевое расписание пилота: 09:15 и 19:10 Europe/Moscow в подходящий торговый день, плюс события счёта и существенные факты; еженедельная сверка. Торговое расписание зависит от рынка/инструмента и источника, не кодируется предположением об окончании торгов. Нагрузка/сроки подтверждаются на реальной инфраструктуре.

Фоновые задания используют существующее durable-хранилище: повтор после сбоя, ограничение частоты источника, уникальный идентификатор работы и запрет публикации старого результата поверх нового. LLM обрабатывает изменившийся общий документ один раз. Чат работает по запросу пользователя независимо от планового обзора. Лимиты затрат/таймауты/наблюдение задаёт оператор, а не экран продажи подписок.

Timeweb AI Gateway предоставляет модель, но не готовый поиск, RAG или память портфеля: их обеспечивает API OMNICIO. Выбирается фактически доступная модель после проверки качества на наших задачах; названия и цены из старого плана не являются конфигурацией.

Брокерские токены, cookies, контакты и другие секреты не входят в контекст модели. Сам портфель и текст вопроса могут быть персональными данными даже без ФИО. Для личного чата до активации необходимо подтвердить разрешённое место и маршрут обработки: размещённая в нашем контуре модель либо согласованный провайдер с минимальным необходимым контекстом и актуальными согласиями. Нельзя утверждать, что вызов внешней модели через Timeweb оставляет всю обработку только на наших серверах. Пока это не определено, внешний ИИ получает только публичные документы.

## Текущий выпуск без продажи подписок

Тарифы, покупка, paywall, платёжный SDK и реклама подписки исключены из продукта. Старые цены из проектного обсуждения больше не являются требованием. В Android платёжного экрана/SDK нет; оставшееся объявление будущих тарифов на сайте удалено. Legacy server billing не включается и не считается частью нового продукта; исторические записи и принятые миграции не уничтожаются ради удаления интерфейса.

## Последовательность реализации

1. Закончить два способа входа: вывести серверный email API и SMTP-зависимость из выпуска, сохранить идентичности, проверить оба входа/привязку на устройстве.
2. Получать и сверять реальные позиции, деньги и операции. Проверить пополнения, выплаты, покупки и частичное исполнение; затем открыть корректные показатели результата.
3. Подключить разрешённые источники и фоновые задания для имеющихся активов. Проверить свежесть, повторы и ссылки на первоисточник. Существенные события доставлять нативным push без постоянного опроса телефона. Текущий Web Push не обслуживает нативный APK; нужны проект провайдера, привязка устройства к сессии, отзыв, разрешение Android и проверка доставки при закрытом приложении. Тяжёлая работа остаётся на Timeweb.
4. Подключить нативный чат к существующему assistant API; завершить разрешённый маршрут модели и контроль контекста/цифр/расходов.
5. Проверить цель/резерв, сценарии и события. Конкретные персональные рекомендации открываются только в предусмотренной модели инвестиционного консультирования.
6. Проверить восстановление, оба OAuth callback, подписанную сборку и реальные сценарии на телефоне; публиковать только принятый выпуск.

## Контрольные сценарии полной приёмки

1. Пополнение меняет бюджет, но не прибыль; повтор не удваивает деньги.
2. Купон отражается после подтверждения; ожидаемая выплата отдельно.
3. Самостоятельная покупка пересчитывает позиции и зависимый план.
4. Частичная продажа позволяет использовать только доступные подтверждённые средства.
5. Изменение резерва/цели немедленно делает старый план неприменимым.
6. Подтверждённое изменение эмитента обновляет только затронутые планы.
7. Неполный счёт не выдаётся за полный общий капитал.
8. Недостаток истории не подменяет доходность изменением NAV.
9. Повторное открытие экрана не вызывает новый LLM-запрос.
10. Сбой брокера/модели, рестарт, конфликт/запоздалый ответ, смена аккаунта не раскрывают чужие данные и не создают вымышленных результатов.

Первый полный выпуск должен доказать распределение пополнения, обнаружение существенного ухудшения и исполнимую замену при разрешённой модели. Наличие базовой оболочки этого не доказывает. Merge, развёртывание, подпись APK, установка и готовность всех сценариев фиксируются отдельно.

## Только Telegram и VK ID — уточнение 11.10.2026

Android предоставляет два способа входа. Telegram использует OIDC Code + PKCE и проверку подписи RS256, issuer, audience, времени и nonce; VK ID использует Code + PKCE, state, device_id и проверку идентификатора через официальный API. Cookie приложения не передаётся в браузер; callback не создаёт сессию в браузере. Новый аккаунт создаётся после явного подтверждения текущих согласий, существующий пользователь получает свой профиль.

Второй провайдер привязывается из профиля после недавнего входа. Совпадение имени, телефона или почты провайдера не объединяет аккаунты. Существующие записи сохраняются; удаление почтового входа не является разрешением удалить аккаунт или портфель. Презентационный сайт больше не требуется; техническая страница возврата OAuth только открывает приложение и пока остаётся действующим consumer домена.

Статус ветки `feat/mobile-multi-provider-auth`: почтовые формы, challenge-state и email-загрузчики Android удалены; на сервере старые email routes и SMTP-gate deployer пока остаются и требуют отдельной согласованной замены перед приёмкой. Миграция 0031 добавляет социальные потоки, не переписывая 0029–0030. Production не обновлён: необходимы проверяемое восстановление БД, приёмка провайдеров и подписанной Android-сборки. Нативный чат подключён к существующим API: отправка вопроса с investment-контекстом после явного согласия, история и источники, GET-проверка результата без повторного model request. Конфигурация ASSISTANT_PROVIDER позволяет операторскому соединению использовать существующий openai_compatible adapter. Production-модель и маршрут обработки пока не активированы и не проверены. OWNER определил три подхода: сбалансированный, купоны/дивиденды и долгосрочное накопление, плюс собственная настройка. Каталог 1.1.0 и Android-конструктор используют существующий versioned draft API; ранее сохранённые подходы остаются читаемыми без изменения их условий. Массовый сбор всего рынка и персональные торговые планы не объявляются готовыми.

## Timeweb без презентационного сайта — уточнение 11.10.2026

Оставить существующие VDS/API/worker, PostgreSQL, защищённые настройки Telegram/VK, разрешённый доступ к модели и источникам, мониторинг и проверяемое восстановление. Одна инсталляция обслуживает приложение; отдельные VDS для лендинга, модельного шлюза или поиска не требуются без измеренной необходимости.

Домен сейчас нельзя отключать: Android SERVER_ORIGIN и серверный CALLBACK_ROOT используют https://omnicio.ru, приложение открывает там действующие документы согласий. Это инженерные условия исследования, а не оптимальные веса, рассчитанные на истории, и не обещание дохода. Экран показывает именно серверные шаблоны. Сумма долей должна равняться 100%; неизвестные личные суммы остаются null. PUT с expected_version сохраняет рабочий документ; POST account-assessment сравнивает его с реальным счётом и возвращает проверенные, заблокированные и неизвестные условия, время и срок актуальности. Планы сделок этим действием не выпускаются.

В AI Gateway рекомендуем проверить GPT-6 Luna для explain (low), GPT-6 Sol / 6.1 Sol для analyze (medium), GPT-6 Astra для review (high). Это назначение ролей для пилота, не заявление о подключении или превосходстве на непроверенной выборке. Точный model ID и поддержка параметров берутся из каталога конкретного ключа и проверяются оператором. Публичная страница Timeweb перечисляет семейство GPT-6; поддержка reasoning_effort зависит от маршрута. Документы: https://timeweb.cloud/services/ai-gateway и https://timeweb.cloud/docs/ai-agents/api-usage/ai-gateway .

Реализованные маршруты — ответы в чате: краткое объяснение, подробный разбор, проверка противоречий. Маршрутизатор не вызывает LLM для выбора другой LLM, не повышает сложность из текста источника и не переключается на дорогую модель при ошибке. Пользователь явно выбирает задачу среди настроенных сервером вариантов. Навигация и GET-readback бесплатны со стороны model API. Режим задачи входит в fingerprint запроса; повтор UUID не становится новым анализом. Сохраняются фактическая модель, usage, выбранные источники и версия контекста. Деньги/лоты/лимиты считают существующие Decimal-алгоритмы, а не модель.

ASSISTANT_ROUTES — JSON операторской конфигурации (не секрет), ключи explain/analyze/review. explain обязателен, остальные опциональны. Каждый объект строго содержит model, reasoning_effort (low/medium/high), max_output_tokens (256..16384), max_input_chars (4000..128000). Конфигурация допустима только с ASSISTANT_PROVIDER=openai_compatible; общий endpoint и ключ остаются в существующей защищённой настройке. Неверная конфигурация отклоняется при старте. Названия моделей не зашиты в код. Стартовые лимиты пилота: explain 2048 выходных токенов/40000 входных символов; analyze 8192/64000; review 16384/96000. Выходной лимит включает reasoning и может не оставить места для ответа; неполный ответ не выдаётся за завершённый. Это ограничение размера, а не гарантия цены. Дополнительно действует общий дневной лимит запросов пользователя и максимум двух параллельных работ. Для денежного потолка нужен отдельный бюджет/лимит провайдера; локальная стоимость по неподтверждённым тарифам не выдумывается.

Полный фоновый разбор новых документов и масштабный поиск ещё не подключены к маршрутам. Следующий шаг использует существующие evidence/observer/research-хранилища: нормализовать URL и hash документа, повторно использовать результат только при совпадении версии документа/метода, запускать анализ изменившихся фактов, затем пересчитывать затронутые портфели кодом. Личный ответ нельзя кэшировать для другого пользователя. Общими могут быть только разрешённые публичные факты. До активации нужны проверка источников/покрытия, набора контрольных документов, расходов и маршрута персональных данных.
