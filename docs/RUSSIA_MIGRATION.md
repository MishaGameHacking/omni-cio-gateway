# Российское размещение Analyst AI

## Решение владельца от 13.10.2026

Новые серверы, базы, образы и резервные копии проекта размещать только в России. Приоритет — Москва MSK-1 (API ru-3), затем доступная площадка Санкт-Петербурга SPB-3 (ru-1), затем Новосибирск NSK-1 (ru-2). Недоступность российских мощностей не разрешает зарубежный fallback. Предзаказ не считается работающим сервером.

## Начальная конфигурация — план, не выполненный заказ

Один backend: 2 vCPU, 2 ГБ RAM, 40 ГБ NVMe, один публичный IPv4. Не заказывать GPU, Dedicated/High CPU, Kubernetes, балансировщик, отдельную управляемую БД или сервер сборки без подтверждённой потребности. Android собирается существующим GitHub runner, модели вызываются через API, не запускаются на VPS.

Это минимальный стартовый профиль для переноса с сохранением нынешних 2 CPU / 2 ГБ / 40 ГБ, а не измеренная гарантия пропускной способности. 1 CPU / 2 ГБ / 30 ГБ можно оценить позже при отдельном файловом переносе и измерении диска; уменьшение диска не совмещать с региональной миграцией образа. ОС при переносе сохранить, не менять на Ubuntu 26.04 только потому, что она выбрана по умолчанию в форме.

По скриншоту владельца: московский сервер 2/2/40 — 2600 ₽/месяц, IPv4 — 200 ₽/месяц. По документации провайдера одна копия диска стоит 6 ₽/ГБ: для 40 ГБ — 240 ₽. Ориентир с одной копией — 3040 ₽/месяц. Это расчёт, не тариф аккаунта и не счёт. У выбранного на скриншоте минимального 1/1/15 итого1470 ₽; эта конфигурация НЕ выбрана для миграции. В Москве на скриншоте нет свободных ресурсов; наличие нужно проверить перед заказом.

Перед расходами сравнить полную цену (включая IP, все копии, дополнительные диски, налоги/скидки и платные опции) с фактическим текущим платежом. Не переносить московскую цену на другой регион. Пока нет подтверждённого расчёта и наличия, ничего не заказывать. Издержки временной второй VM/образа при миграции учитывать отдельно; после проверки не оставлять лишние платные ресурсы.

## Разделение обновления ПО и миграции

Обычный deploy обновляет ровно один уже существующий analyst-ai-backend. Если сервер отсутствует, имя неоднозначно, список неполон или отсутствует IPv4 — ошибка, а не автоматическая покупка. Старый перебор произвольных preset_id и заказ IP удаляются из этого пути. Временные SSH-ключи доставки остаются, пользовательские секреты и ключ подписи APK не меняются.

Это защита от случайных заказов, НЕ проверка фактического российского размещения. Существующий зарубежный backend пока может получать исправления ПО, чтобы не ломать установленное приложение. Не называть такую доставку кода миграцией в РФ. Реальная миграция — отдельная контролируемая операция.

## Условия переключения

1. Зафиксировать идентификатор исходного сервера, фактический регион, заполненность диска, CPU/RAM, текущую стоимость, целевую площадку и полный расчёт. Выбранный регион и резервные копии должны быть российскими.
2. Получить согласованную резервную копию SQLite через backup API либо остановленные записи; сохранить исходный FERNET_KEY и настройки отдельно в защищённом хранилище. Не копировать работающую SQLite одним файлом без учёта WAL. Проверить восстановление. Не публиковать ключи/DB в Actions, Git или переписке.
3. Развернуть восстановленную систему на новом сервере. Пока старый активен, новый планировщик не должен отправлять повторные уведомления или выполнять двойные фоновые задания.
4. Учесть новый IP и согласованно обновить HTTPS, BACKEND_PUBLIC_URL, адрес в Android и разрешённый Telegram redirect URI. IP переносится только внутри одной зоны. Не оставлять старый IP-привязанный callback после переезда.
5. Проверить health, OIDC с возвратом в приложение, сохранённые сессии, расшифровку T-Invest токенов, реальные read-only запросы, фоновые задания. Затем переключить трафик, завершить проверку отката и только после этого убрать старую VM, ненужные IP/образы. Удаление с Telegram-подтверждением сохраняется.

## Рост

Масштабировать по измерениям, а не по датам или числу регистраций. Первые ориентиры для пересмотра: RAM >80% или CPU >70% на протяжении 15–30 минут при нормальной нагрузке, растущая очередь/задержки, свободный диск <25%. Сначала проверить запросы, кэш и утечки, затем увеличить только дефицитный ресурс. Диск отдельно, поскольку его уменьшение ограничено. Эти ориентиры — план мониторинга, автоматического масштабирования сейчас нет.

Российский VPS сам по себе не гарантирует российскую обработку у внешних AI-провайдеров, Telegram и GitHub. Перед отправкой инвестиционных данных внешней модели отдельно определить допустимые данные и маршрутизацию.
