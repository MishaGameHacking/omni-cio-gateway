# Как войти в Analyst AI

Инструкция для установленной оболочки 55 / 0.19.0-preview и действующего сервера.
Проверка 29.10.2026 в 23:31 МСК показала: личный пароль ещё не создан,
одноразовый ключ на сервере отсутствует. Это объясняет, почему подбор ключа
не давал доступа. Ни общедоступного пароля, ни стандартного ключа нет.

## 1. Задайте свой одноразовый ключ

Откройте [добавление секрета репозитория](https://github.com/MishaGameHacking/omni-cio-gateway/settings/secrets/actions/new).

Если открылась страница списка: Settings → Secrets and variables → Actions →
Repository secrets → New repository secret.

- В поле **Name** вставьте точно: `ANALYST_OWNER_BOOTSTRAP_SECRET`.
- В поле **Secret** вставьте новую случайную строку длиной 32–128 символов.
  Разрешены латинские буквы, цифры, дефис `-` и подчёркивание `_`.
  Пробелов, кавычек, переносов строк и кириллицы быть не должно.
- Сохраните эту строку у себя, например в менеджере паролей: позже она нужна в приложении.
- Нажмите **Add secret**.

Вы задаёте значение самостоятельно один раз. Не используйте значение TIMEWEB_AI_TOKEN,
TIMEWEB_CLOUD_TOKEN, токен T-Invest или пароль от учётной записи GitHub.
Существующие секреты заменять или удалять для этого не нужно.
Если ANALYST_OWNER_BOOTSTRAP_SECRET уже создан, используйте кнопку редактирования
и запомненное вами значение либо новое значение до завершения первого входа.

## 2. Передайте ключ серверу

Откройте [подготовленный запуск «Настроить первый вход Analyst AI»](https://github.com/MishaGameHacking/omni-cio-gateway/actions/runs/40949599130).

1. Вверху справа нажмите **Re-run all jobs** («Повторить все задания»).
2. Если откроется окно подтверждения, нажмите **Re-run jobs**.
3. Дождитесь завершения. На странице результата должна появиться надпись
   **«Ключ готов для первого входа»**.
4. После этого переходите в приложение.

Первый запуск без секрета имеет результат **«Ожидается ваш одноразовый ключ»**:
он только проверил сервер и ничего не менял. Одна зелёная отметка такого запуска
не означает, что ключ установлен. После добавления секрета нужен повторный запуск.

Если снова показано «Ожидается ваш одноразовый ключ», проверьте имя секрета,
тот ли репозиторий открыт, и что секрет добавлен именно в Repository secrets
раздела Actions. Перезапустите задание после сохранения секрета.

Если показано **«Личный пароль уже создан»**, настройка уже закончена:
используйте свой ранее созданный пароль. Этот запуск не сбрасывает пароль.

Официальный порядок повторного запуска:
[GitHub: Re-running workflows and jobs](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/re-run-workflows-and-jobs).
Повтор доступен 30 дней после исходного запуска; для более поздней настройки потребуется новый запуск.
Включать диагностическое логирование для этой операции не требуется.

## 3. Создайте пароль в приложении

Откройте Analyst AI. На экране **«Создайте личный пароль»** заполните:

| Поле | Что вводить |
|---|---|
| Пароль Analyst AI | Новый личный пароль для приложения, минимум 10 символов. Рекомендуется 12 или больше. |
| Повторите пароль | Точно тот же личный пароль. |
| Одноразовый ключ настройки | Точно значение из поля Secret, сохранённое в шаге 1. Не имя ANALYST_OWNER_BOOTSTRAP_SECRET. |

Нажмите **«Сохранить пароль и войти»**.

Логин, почта и Telegram для этого экрана не нужны. Пароль приложения и одноразовый
ключ — разные значения. Ключ нужен только для первой настройки. После успешного
создания пароля сервер повторно его не принимает; данные счёта остаются прежними.

Если поле одноразового ключа отсутствует, а приложение предлагает создать пароль,
оно использует сохранившуюся подтверждённую сессию владельца. Введите и повторите
новый пароль; дополнительный ключ в этом случае не нужен.

## 4. Последующие входы

- На экране **«Открыть систему»** введите свой пароль Analyst AI и нажмите **«Войти»**.
- Если появилась блокировка устройства, нажмите **«Разблокировать»** и подтвердите
  вход отпечатком или обычным кодом блокировки телефона.
- Для входа без биометрии нажмите **«Войти с паролем»**.
- Четырёхзначный PIN телефона используется только в системном окне Android;
  новый пароль Analyst AI должен содержать минимум 10 символов.
- При истечении серверной сессии понадобится пароль Analyst AI ещё раз.

## Если возникла ошибка

| Сообщение | Действие |
|---|---|
| Доступ не подтверждён. Проверьте пароль или ключ настройки. | Проверьте успешный результат подготовки и вставьте само значение Secret без лишних пробелов. Не угадывайте ключ. |
| Пароль должен содержать не менее 10 символов… | Задайте пароль длиной 10 или больше; предельный размер 128 байт UTF-8. Для простого ввода можно использовать латиницу и цифры. |
| Пароль уже настроен. Войдите с сохранённым паролем. | Перейдите к обычному входу. Одноразовый ключ больше не нужен. |
| Слишком много попыток. Подождите перед следующим входом. | Прекратите подбор. После неудачных попыток входа блокировка может действовать 15 минут. |
| Новый вход ещё не доступен на сервере… | Это ошибка доступности маршрута; повторный подбор ключа не поможет. Сообщите текст ошибки. |
| Кнопка «Сохранить пароль и войти» неактивна | Дождитесь проверки сервера; проверьте длину пароля, совпадение повторения и заполнение ключа. При сбое используйте «Повторить подключение». |

После отправки формы поля очищаются, в том числе при ошибке. Перед новой попыткой
значения нужно ввести снова. Пароль и одноразовый ключ не отправляйте в чат или
публичные комментарии GitHub. Достаточно сообщить текст ошибки и результат запуска.
