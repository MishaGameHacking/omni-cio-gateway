# Граничные расчёты и конкуренция — аудит 19.10.2026

Версия 0.11.0, PR #880, F01/F16/F22/F23. База `2c2f0f7`.
Это исправления исходного кода и синтетические испытания, не развёртывание.
Timeweb, опубликованный APK, backend production, main и платёжные настройки не меняются.

## Подтверждённые дефекты

1. `micro_rub`: умножение Decimal на миллион в текущем контексте способно
   удалить дробный остаток ДО ROUND_CEILING. Например,
   `0.0000010000000000000000000000000000001` ранее давало 1 micro-RUB вместо 2.
   При низкой точности контекста могла искажаться и более крупная сумма.
   Исправление сначала quantize до micro-RUB в собственном контексте, затем
   точно переводит в целое. Лимиты, правила резервирования и схема БД сохранены.
2. Свежесть сценариев: вычитание datetime с одним tzinfo игнорирует смену
   смещения и fold. На повторном местном часе будущий или старый снимок мог
   ошибочно пройти. Теперь вычитаются UTC-моменты; отрицательный возраст
   и превышение TTL по-прежнему запрещены, в том числе на границе микросекунды.
3. Каталог AI: byte limit не исключает RecursionError у глубоко вложенного JSON;
   некорректная Unicode-строка могла дать UnicodeEncodeError. Оба случая теперь
   дают контролируемый CatalogError до платного вызова, без fallback к модели.

## Что проверено локально

Новые проверки: 24 денежных/конкурентных, 50 сценарных, 7 JSON = 81 сценарий.
С существующими выбранными тестами этих модулей — **157 passed**.
Отдельные 14 тестов поворота/очистки уже вошли в `2c2f0f7`.
Независимые pytest-процессы запускались параллельно; внутри SQLite-тестов
использовались 8 потоков, каждый со своим соединением и настоящим BEGIN IMMEDIATE.
40 разных запросов при cap=60 и ceiling=7 резервируют ровно 8*7=56,
остальные 32 отклоняются. 16 конкурентных запросов с одним ключом создают
ровно одну запись. Неопределённая стоимость не освобождается после полуночи.
Все суммы и пользователи синтетические; платных API и торговых вызовов нет.

В 40 воспроизводимых наборах совместных сценариев расчёты доходности,
реальной доходности, вероятности убытка, VaR и ES сверены с независимыми
рациональными Fraction-вычислениями. Это проверка арифметики, НЕ доказательство
качества прогнозов или калибровки вероятностей рынка. `orders_allowed=false`.
Даты используют уже имеющуюся зависимость tzdata, включая Windows CI.
Параметры больших JSON имеют короткие pytest IDs, чтобы не повторить ошибку
PYTEST_CURRENT_TEST на Windows. Тесты прежнего файла отдельно воспроизводили
дефекты перед внесением исправлений; проверки не ослаблены.
