# Выбор инфраструктуры CI — 21.10.2026

Относится к F01 / F22 / F23 и проверкам настоящего Filament/GLB-интерфейса
0.11.0 в PR #880. Владелец разрешил Timeweb и потребовал минимальную полную
стоимость без ограничения страны размещения.

## Решение и границы проверки

Первый выбор для Android runtime — стандартный GitHub-hosted `ubuntu-24.04`.
Для этого публичного репозитория дополнительные Linux-вычисления бесплатны.
Сборка и подпись остаются на существующей Windows-машине: её ключ не вывозится,
а сертификат совместимого preview не заменяется. Стоимость существующей машины
в этой проверке не пересчитывалась. Это инфраструктура CI, не круглосуточный
backend приложения.

В [39561653615](https://github.com/MishaGameHacking/omni-cio-gateway/actions/runs/39561653615),
job `119094099320`, фактически проверены:

- 4 CPU, около 16 ГБ RAM, 85,8 ГиБ свободного диска на конкретной машине;
- `/dev/kvm`, API KVM 12 и успешный `emulator -accel-check` от пользователя runner;
- официальный Android CLI с закреплённым SHA-256, SDK/API 37 и build-tools 37;
- оба официальных системных образа для проверки страниц 4096/16384 байт.

Изменение владельца `/dev/kvm` выполняется только на одноразовой GitHub VM.
Реальное свободное место проверяется заново перед запуском. Номинальная
конфигурация и успешная установка SDK ещё не доказывают полный 3D runtime,
обновление APK или работу физического Samsung Galaxy S25 Ultra.

## Приватная передача входных APK

В архив входят только preview, debug, отдельный test-only UI driver и закреплённый
предыдущий APK. Манифест связывает точный исходный SHA, размеры и SHA-256 каждого
файла. Нет экспорта ключей подписи, пользовательских данных или секретов.
Повреждение, подмена коммита, дополнительные ZIP-пути и выход из checkout
останавливают восстановление до записи APK.

Проверка Timeweb S3 standard 1 ГБ / 1 ₽ в месяц остановилась на
`GetBucketAcl: SignatureDoesNotMatch`; настоящие APK туда не передавались.
Оба пустых тестовых бакета (`587153`, `587167`) больше не видны в полной
инвентаризации. Последнее подтверждение отсутствия —
[39564394274](https://github.com/MishaGameHacking/omni-cio-gateway/actions/runs/39564394274),
job `119103070680`, 07:47 UTC. Исходный отказ удаления HTTP 403 не скрыт;
отсутствие подтверждено отдельным чтением. Причина S3-подписи не установлена.
Документированная заглушка `hidden-by-api-key-policy` была учтена в диагностике;
ключи и права не менялись. Неиспользуемый S3-перенос и его зависимости удалены
после подтверждения отсутствия временных бакетов.

Следующий вариант — временный unpublished GitHub draft для передачи CI-архива.
Он проверяется на синтетическом файле до сборки. Требуются `draft=true`, точные
владелец/коммит/run, HTTP 404 без авторизации, повторное скачивание и совпадение
хеша. Отдельный `always` job удаляет только ресурс этого прогона и проверяет
отсутствие. В коде нет перехода draft в published. Старые релизы и артефакты
не удаляются. Пробный run `39564974948` остановился до загрузки из-за неверного
Accept в анонимной проверке; черновик удалён. Формат запроса исправлен. На `97227a4` предварительная проверка
[39565256916](https://github.com/MishaGameHacking/omni-cio-gateway/actions/runs/39565256916),
job `119105877704`, прошла: приватный upload/readback, анонимный HTTP 404 и
подтверждённая очистка. Sonar точного коммита: 0 новых, 0 принятых, 0 hotspots.
Сборка и lint подписанных APK завершились, но повторное создание draft в job
`119105949926` вернуло HTTP 403: к этому моменту ветка ушла с `97227a4`.
GitHub требует дополнительный workflow scope для коммита с изменёнными workflows
без существующего branch/tag ref. Runtime не запускался; cleanup успешен.

Исправлен порядок: preflight создаёт один закрытый draft, проверяет synthetic
upload/readback и удаляет только synthetic asset. Сборка загружает APK в этот же
проверенный пустой draft; повторного создания release после сборки нет. Для PR
release привязан к исходной вершине ветки, а манифест и тело отдельно связывают
фактически тестируемый merge SHA. Позднее продвижение ветки не меняет эти байты.
Полная очистка draft остаётся в обязательном завершающем job. Права не расширены.

Штатный [Android CI](../.github/workflows/android-ci.yml) переведён на схему:
приватный preflight → сборка прежней подписью → Linux runtime обоих профилей →
очистка → обязательный итоговый статус. Промежуточные экспериментальные workflows
удалены, чтобы не запускать вторую сборку того же изменения. Активный прогон
заканчивается вместе с очисткой; новый PR head не прерывает её автоматически.
Старый head не может выдать актуальный device-test APK: проверяется текущий PR.

Матрица установки, обновления, UI, настоящего 3D, подписи и Sonar сохраняется.
Локальные правила проходят: 687 CI tests (3 skip) в 3D-ветке и 398 (1 skip)
в ремонте main; общий Node handoff — 8 tests.
Полный успешный runtime ещё не подтверждён; начатая сборка не считается приёмкой.
Исправлено отдельное условие device-test retention в 3D-ветке: публичность
исходников больше не вызывает безусловный отказ обычного CI. Явно запрошенный
приватный draft возможен только после всех прежних проверок и анонимного HTTP 404.

В 08:27 UTC Windows runner сообщил только 67–74 MB свободного места (Backend
CI runs `39568965272` / `39568965167`). Проверки backend прошли, но общий статус
был остановлен одним новым замечанием Sonar в handoff helper; выражение исправлено.
Очистка воспроизводимых intermediates текущего checkout теперь вызывается через
`always()` и после сбоя сборки. Частичные APK и отчёты сохраняются; хешируются все
существующие APK, проверяются запреты links/reparse points и tracked sources.
Чужие runner-каталоги, SDK и общие caches не являются целями удаления. Очистка
не превращает неудачную сборку в успешную и не ослабляет последующие APK gates.

Backend CI и read-only quality diagnostics также перенесены на стандартный
`ubuntu-24.04`: подпись APK им не нужна. Полный набор прежних сценариев, health,
OpenAPI и exact-head Sonar сохранён. Это устраняет зависимость Python-проверок
от почти полного Windows-диска (45 MB в run `39570303199`); прерванный dev backend
run `39570301888` требует отдельного чтения аннотации, журнал не был доступен.
Диагностика теперь читает отказы и предыдущего, и текущего head. Перенос не
считается успешно проверенным до завершения соответствующего Linux run.

## Первый реальный runtime на бесплатном Linux

Build/sign/upload реально прошли: main repair run `39571155695`, job
`119125460979`, и 3D run `39570299755`, job `119124880047`. После очистки Windows
имел 2,55 и 2,66 GB свободного места; приватные архивы 45,7 и 99,8 MB проверены
повторным скачиванием и анонимным HTTP 404. Ключ подписи не переносился.

На `a256276` / API37 / **16384 байта** успешно выполнены обновление с 0.10.0,
чистая установка, оба запуска кандидата и полный этап `spatial-renderer`.
Filament процесса кандидата: ANGLE + Vulkan + Mesa, GLES 3.2. Подтверждены меши,
контраст, native controls, motion, общий движок диалога, численные 3D-меши,
clipping, 120 прокруток, поворот, шрифт 200%, системное motion/thermal и
predictive-back cancel/commit. Это программный 3D на CPU, а не FPS физического
Samsung. Evidence: runtime job `119131595543`, spatial JSON blob
`3aa2bb97079632e1c1d95af0c0e65d85ebd464a3`.

Полная матрица ещё **не пройдена**. В 3D run следующий `session-context` не
подтвердил восстановление после поворота; workspace виден, `scrollable=false`.
Main API35 установился и прошёл dashboards/workspace/profile-preflight/themes,
но повторное открытие диалога «Безопасность» не показало «Понятно».
Исправляется возможный устаревший/обрезанный tap: стабильные testTag карточки
и кнопок, пересечение с viewport и три свежие одинаковые координаты. Неподвижный
список допускает tap видимой кнопки, но не разрешает жест прокрутки. Контекст и
открытие диалога по-прежнему строго проверяются. При отказе сохраняется исходный
кадр `failure.png`; сбой снимка не заменяет исходную ошибку теста. Причина каждого
UI-отказа считается устранённой только после повторного runtime.

Backend на Linux уже прошёл: `39571150953` (1446 tests / 1382 subtests) и
`39571155963` (819 tests), с health/OpenAPI и нулём Sonar. Диагностика
`39571142780` подтвердила прежний `System.IO.IOException`: Windows worker не
смог записать собственный log из-за заполненного диска. Все временные drafts
завершившихся runtime удалены с проверкой отсутствия. Производственная версия
не публиковалась, main не сливался.
