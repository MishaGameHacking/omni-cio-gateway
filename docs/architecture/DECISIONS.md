# Архитектурные решения

## ADR-001 — Шлюз остаётся read-only

**Статус:** принято.

Публичный gateway не содержит методов создания, отправки, замены или отмены заявок. Причина: проект предназначен для анализа и сверки, а не для автоматической торговли. Контроль выполняют GET-only routes, `trading_methods=false` и Regression Shield.

## ADR-002 — Production entrypoint остаётся `app:app`

**Статус:** принято.

Render и GPT Actions зависят от стабильного FastAPI app. Исторические wrappers пока сохраняются для совместимости. Перенос кода в Python package возможен только через отдельную миграцию с compatibility imports, тестами и production smoke test.

## ADR-003 — GitHub является источником проектной памяти

**Статус:** принято.

Новые чаты не должны восстанавливать архитектуру из старой переписки. Канонические правила находятся в `AGENTS.md`, `knowledge/`, `gpt/`, `docs/` и коде `main`.

## ADR-004 — Секреты и реальные данные остаются вне GitHub

**Статус:** принято.

GitHub хранит воспроизводимую систему, но не `TINVEST_TOKEN`, `GATEWAY_API_KEY`, полный номер счёта, реальные отчёты и финансовые данные. Внешние зависимости перечисляются в asset inventory без значений.

## ADR-005 — Frontend нельзя дублировать до определения источника

**Статус:** принято.

Существующий сайт Omni-CIO должен сохраняться. Пока исходный frontend-проект не найден и не зарегистрирован, запрещено создавать новый сайт вместо него. После обнаружения источник фиксируется в `docs/inventory/PROJECT_ASSETS.md`.

## ADR-006 — Одноразовые workflow не живут в main

**Статус:** принято.

Release-patcher workflow допускаются только во временной ветке. После релиза они удаляются. В `main` остаётся постоянный Regression Shield и необходимые maintenance workflows.
