# Этап 1 — Android-интерфейс OMNICIO

Статус: утверждённый OWNER архитектурный поворот от 10.10.2026; реализация выпусков ещё не принята.
Предыдущий web-клиент не является целевым пользовательским продуктом нового этапа.
Новый клиент: нативное Android-приложение OMNICIO для публикации в RuStore.
Следующий этап: [системная разработка](system-plan.md), только после завершения UI-06.
Процесс разработки, проверки и выпуска: [AGENTS.md](../AGENTS.md).

## Цель этапа

Собрать полностью нативный, компактный и понятный Android-интерфейс инвестиционного помощника без WebView-обёртки и без пользовательского чата с ИИ.

Основной пользовательский опыт:

1. установить OMNICIO из RuStore;
2. открыть приложение без обязательной регистрации OMNICIO;
3. выбрать локальный privacy-режим либо подключить read-only T-Invest;
4. увидеть портфель, деньги, существенные события и общую аналитику;
5. получать только важные сообщения;
6. выполнять сценарные расчёты локально;
7. открывать выбранный пользователем инструмент в Т-Инвестициях/браузере;
8. иметь понятное состояние offline/stale/partial data.

Все персональные портфельные данные в базовом local-first режиме принадлежат устройству пользователя.
Timeweb не является обязательным хранилищем его брокерского токена, позиций, баланса, операций или личной стратегии.

## Технологический контракт UI

- Kotlin + Jetpack Compose.
- Material 3 как техническая основа компонентов, но собственный бренд OMNICIO.
- Unidirectional Data Flow: immutable UI state вниз, события вверх.
- Navigation Compose для маршрутов.
- ViewModel/StateFlow для состояния экранов.
- **Android 13 (API 33)+ — минимально поддерживаемая ОС OMNICIO.** Устройства ниже API 33 не входят в product/support matrix. `minSdk` является жёстким контрактом и не понижается ради охвата старых устройств; `compileSdk`/`targetSdk` поддерживаются на актуальном стабильном уровне, зафиксированном Android build-файлами.
- Package/applicationId: рабочее значение `ru.omnicio.app`; перед первой подписанной release-сборкой проверить доступность и закрепить навсегда.
- Никакого пользовательского WebView как основного UI.
- Светлая и тёмная темы используют одну семантику цветов.
- Визуальный ориентир: компактность, иерархия суммы/позиции/действия и спокойная подача финансовых данных, без копирования бренда, логотипов, иконок или защищённых элементов Т-Банка.

## Разработка, сборка и практическая проверка

Исходники Android создаются и изменяются в этом GitHub-репозитории. Основной инструмент локальной разработки/просмотра — Android Studio; Visual Studio не является канонической IDE проекта.

Рабочий цикл:

1. разработчик создаёт/меняет Kotlin/Compose/Gradle-файлы в feature branch;
2. pull request запускает Android CI;
3. CI использует закреплённый Gradle Wrapper и Android SDK, а не локально установленную случайную версию Gradle;
4. для каждого проверяемого Android head собирается debug APK;
5. APK публикуется только как GitHub Actions artifact конкретного commit SHA;
6. OWNER/команда скачивают этот APK и устанавливают на физический Android-телефон для пользовательской проверки;
7. найденный дефект исправляется новым commit того же PR, после чего собирается новый artifact;
8. release APK/AAB создаётся только из принятого release commit после прохождения обязательных проверок.

Канонические build outputs:

- development/QA: `app-debug.apk` из `assembleDebug`;
- store release: подписанный `.aab` и при необходимости подписанный universal/release `.apk`;
- RuStore получает только release build, а не debug artifact.

Android Studio на ноутбуке OWNER используется для:

- Compose Preview;
- Android Emulator;
- подключения физического телефона по USB debugging;
- интерактивного Logcat/Profiler;
- локального воспроизведения ошибок;
- первоначального создания/управления release/upload signing material.

Ноутбук OWNER не является единственным build environment: обычные проверяемые APK должна уметь воспроизводимо собирать CI.

Секреты:

- T-Invest token вводится только в установленное приложение и не передаётся в GitHub issue/PR/chat;
- release/upload private key и его пароли не передаются в чат и не коммитятся;
- debug signing не используется для RuStore release;
- если release signing автоматизируется в CI, key material хранится только в защищённых GitHub secrets/environment custody.

## Навигация

Три основные вкладки:

- **Обзор** — капитал, деньги, актуальность и одно существенное состояние;
- **Портфель** — все локально известные позиции и их фактические/аналитические свойства;
- **Помощник** — автоматическая лента важных событий и готовых объяснений без поля ввода.

Дополнительные поверхности открываются из профиля/настроек:

- подключение T-Invest;
- privacy/local data;
- цели/резерв;
- подписка;
- уведомления;
- экспорт/удаление локальных данных;
- информация об источниках и версии приложения.

## Дизайн-принципы

- На первом экране пользователь должен за несколько секунд понять: сколько у него капитала, сколько доступно, есть ли важное изменение.
- Одна карточка — одна причина и одно следующее действие.
- Не показывать ноль вместо неизвестного значения.
- Не переименовывать изменение оценки портфеля в доходность без корректного учёта денежных потоков.
- Не дублировать один и тот же факт в пяти виджетах.
- Не показывать общий новостной шум.
- Не генерировать LLM-запрос из-за открытия экрана.
- Размер капитала и число позиций не ограничиваются продуктовой квотой.
- Основные tap targets >= 48dp; состояние не кодируется одним цветом.
- Секреты никогда не отображаются обратно пользователю целиком после сохранения.
- Демо/fixture data всегда явно маркируются и не смешиваются с реальным T-Invest.

## UI-01 — 2.0.0. Android shell и local-first onboarding

**Результат для пользователя:** установить приложение и начать пользоваться базовым интерфейсом без обязательной передачи email, телефона или брокерских данных OMNICIO.

Задачи:

- Создать Android project на Kotlin/Compose.
- Ввести design tokens: типографика, размеры, поверхности, semantic colors, spacing, радиусы, состояния.
- Реализовать splash/startup state без искусственной задержки.
- С первого Android commit использовать современные системные контракты Android 13+: edge-to-edge, predictive back через поддерживаемые AndroidX Navigation API, adaptive layout для разных размеров окна и privacy-safe platform APIs только там, где есть реальный product consumer.
- Первый запуск объясняет три принципа:
  - портфель может храниться локально;
  - общий анализ рынка приходит с Timeweb;
  - подключение брокера выполняется отдельно и добровольно.
- Реализовать два стартовых пути:
  - **Попробовать локально** — без T-Invest и без аккаунта;
  - **Подключить T-Invest read-only** — пока только UI и объяснение прав, без backend реализации до SYS-02.
- Сгенерировать локальный random installation/profile id; он не является публичным логином.
- Не требовать email, телефон, ФИО, дату рождения, пароль или social login для основного local-first режима.
- Экран privacy должен прямо показывать, какие категории данных остаются только на устройстве и какие общие запросы уходят на Timeweb.
- Web-клиент репозитория не считать пользовательским release authority для Android.

Приёмка:

- Приложение запускается на поддерживаемых тестовых устройствах Android.
- Все основные экраны доступны без сети в fixture/demo режиме.
- Поворот/перезапуск процесса не уничтожает UI-state, который должен переживать recreation.
- Нет WebView-обёртки старого сайта.
- Нет скрытой обязательной регистрации.
- Нет сетевой отправки портфельных fixture данных.
- Скринридер видит корректные labels; основные действия доступны клавиатурой/assistive navigation где применимо.
- Release/debug builds имеют различимые application IDs/signatures по утверждённой схеме.

## UI-02 — 2.1.0. Обзор

**Результат:** за несколько секунд понять состояние капитала и требуется ли внимание.

Экран содержит:

- общую оценку портфеля;
- скрытие/показ сумм;
- валюту отображения;
- источник и время последнего обновления;
- доступные деньги отдельно от общей стоимости;
- резерв отдельно от бюджета сценария;
- одну главную карточку состояния;
- ближайшие выплаты с разделением «ожидается» и «получено»;
- состояния: нет подключения, пусто, stale, partial, offline, loading, error.

Главная карточка может быть только одной из типов:

- существенных действий нет;
- появились свободные деньги;
- данные устарели;
- есть важное изменение по позиции;
- расчёт сценария готов;
- требуется повторная синхронизация.

Приёмка:

- Unknown не заменяется нулём.
- Пополнение не считается доходностью.
- Открытие экрана не запускает GPT.
- Demo state невозможно спутать с реальным портфелем.
- Большие суммы, 100 ₽, 100 млн ₽, отрицательные значения и разные валюты не ломают вёрстку.

## UI-03 — 2.2.0. Портфель

**Результат:** видеть весь портфель без искусственного лимита позиций.

Список позиции показывает:

- название;
- тикер/ISIN/UID при наличии;
- количество;
- доступное/заблокированное количество;
- текущую оценку;
- долю;
- состояние цены;
- короткий risk/data status.

Карточка позиции показывает:

- источник цены и время;
- размер лота;
- валюта;
- выплаты;
- подтверждённые общие факты по эмитенту;
- концентрацию в локальном портфеле;
- сценарные действия, выбранные пользователем;
- ссылку/идентификаторы для поиска инструмента в Т-Инвестициях.

Задачи:

- поиск только по своему локальному портфелю;
- виртуализация/пагинация только после измерения реальной необходимости;
- объединение одинакового инструмента по нескольким локально подключённым счетам с раскрытием источников;
- никакого скрытия позиций за подпиской.

Приёмка:

- портфель из 0/1/100/1000 fixture-позиций остаётся функциональным;
- stale price обозначается;
- отсутствующая цена не даёт фиктивную стоимость;
- внешний переход не считается исполненной сделкой.

## UI-04 — 2.3.0. Автоматический помощник без чата

**Результат:** пользователь получает только существенные сообщения, не управляя ИИ вручную.

У помощника нет:

- prompt field;
- истории свободного диалога;
- выбора модели;
- temperature/token settings;
- кнопки «спросить ИИ».

Лента содержит:

- новое существенное событие;
- изменение риска;
- появление выплаты;
- изменение доступных денег;
- результат пользовательского scenario calculator;
- потерю актуальности анализа;
- необходимость синхронизации.

Карточка сообщения:

1. что изменилось;
2. почему это относится к портфелю;
3. числовое влияние, рассчитанное локальным deterministic code;
4. общие источники;
5. дата/время;
6. доступное безопасное действие: открыть источник, открыть позицию, запустить выбранный пользователем сценарий.

Регулируемые auto-selected BUY/SELL/HOLD и конкретные автоматически выбранные лоты не показываются при закрытом regulated feature gate.

Приёмка:

- повторное открытие сообщения не расходует токены;
- одно событие не размножается из-за перепечаток;
- privacy-sensitive portfolio details не уходят в обычный push payload;
- сообщение без достаточных данных не содержит выдуманного действия.

## UI-05 — 2.4.0. Настройки, privacy и тарифные состояния

Разделы:

- **Данные на устройстве** — объём, последнее обновление, удалить/экспортировать;
- **T-Invest** — состояние read-only подключения, переподключить/отключить;
- **Общие источники** — прозрачный список категорий данных;
- **Цели и резерв** — пользовательские параметры для локальных сценариев;
- **Уведомления** — local/background, optional fast alerts;
- **Подписка** — только реально доступные уровни;
- **О приложении** — версия, privacy, документы, источники.

Актуальные уровни UI:

| Уровень | Production при analytics-first |
|---|---|
| Наблюдение | доступен |
| Аналитика | может быть доступен после SYS-10/SYS-11 |
| Персональный план | отображается только как недоступный/не продаётся при закрытом regulated gate |
| Цели и доход | только фактически реализованные аналитические функции |
| Капитал | только фактически реализованные аналитические функции |

Семейного тарифа и связанных аккаунтов нет.

До подключения RuStore Pay SDK экран оплаты работает только на fixtures/test mode.
Не показывать цену функции, которой ещё нет в production.

Приёмка:

- пользователь может локально удалить портфель/T-Invest token;
- удаление не зависит от доступа к Timeweb;
- отключение брокера очищает локальный secret и останавливает зависимые jobs;
- платёжный UI не выдаёт тестовое состояние за активную подписку.

## Практический feedback contract

Команда тестирует приложение как реальные пользователи, а не обязана программировать Android самостоятельно.

Для каждой законченной user-facing capability доступны:

- commit/PR с точным diff;
- CI status;
- устанавливаемый debug APK artifact;
- короткий перечень реализованного поведения и известных ограничений.

Feedback может содержать модель телефона, Android version, точные шаги, ожидаемый/фактический результат и screenshot без секретов. Если проблема воспроизводится только на конкретном устройстве, device-specific fix не должен ломать общий layout.

Физическая проверка обязательна перед первым RuStore release и для функций Keystore, notifications, background work, T-Invest connection и app update.

Задачи:

Приёмка этапа 1:

- шесть выпусков выполнены последовательно;

- серверные регулируемые gates нельзя открыть UI-флагом;
- готов контракт всех данных для этапа 2;
- PR/CI/release evidence сохранены для каждого опубликованного выпуска.

## Что удаляется из старого UI scope

Следующее больше не является целью Android-клиента:

- обязательная web-регистрация OMNICIO;
- email/password/passkey как основной путь;
- SMTP для входа/восстановления;
- старый web workspace как основной кабинет;
- свободный AI chat;
- web PWA/offline shell как пользовательский продукт;
- браузерные strategy/settings экраны старой архитектуры;
- семейный тариф;
- обязательное серверное хранение брокерского токена и портфеля.

Минимальный домен OMNICIO может остаться для API, privacy/terms, status и технической документации, но не является основным личным кабинетом.
