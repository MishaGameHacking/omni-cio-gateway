# Analyst AI — рациональное использование моделей

## Цель

ИИ в Analyst AI не является пользовательским чатом. Он получает только
структурированный контекст, подготовленный алгоритмами приложения, и выпускает
короткие проверяемые карточки: риск, изменение портфеля, утренний/вечерний обзор
или подборка кандидатов при наличии свободных денег.

ИИ не считается источником котировок, балансов и фактов о счёте. Эти данные
приходят из T‑Invest API и других контролируемых источников, сохраняются с
временем получения и версией. Модель объясняет уже собранные факты, но не
подменяет их.

## Три стратегии

### 1. Экономная

- Алгоритмы и правила выполняют почти всю работу.
- Одна недорогая модель вызывается утром, вечером и при критическом событии.
- Глубокая модель не используется автоматически.
- Минимальные расходы, но слабее анализ сложных взаимосвязей и неоднозначных
  событий.

### 2. Сбалансированная — выбранный режим

- Скрипты постоянно обновляют данные, рассчитывают риск, концентрацию,
  ликвидность, валюты, отрасли и изменение портфеля без LLM.
- Быстрая недорогая модель классифицирует только новые существенные события.
- Стандартная reasoning-модель готовит утренний/вечерний вывод, анализ после
  покупки/продажи и персональную подборку при появлении свободных денег.
- Премиальная модель включается только при критическом риске или высокой
  неопределённости, когда дешёвая модель не смогла дать достаточно уверенный
  структурированный ответ.
- Действуют дедупликация, cooldown, кэш, ограничения вывода и дневные лимиты.

### 3. Максимальная глубина

- Несколько моделей независимо анализируют широкий рынок, затем модель-судья
  объединяет ответы.
- Выше полнота исследования, но существенно больше стоимость, задержка и риск
  противоречивых выводов.
- Не подходит как режим по умолчанию; допускается только для редкого ручного
  исследования команды продукта.

## Конвейер выбранного режима

1. **Сбор данных без ИИ.** T‑Invest, котировки, корпоративные события,
   календарь, новости и макроданные попадают в нормализованное хранилище.
2. **Проверка качества.** Источник, время, актуальность, дубликаты и конфликтующие
   значения проверяются до обращения к модели.
3. **Расчёты.** Обычный код считает доли, концентрацию, просадку, изменение
   денежных остатков, чувствительность и факт покупки/продажи.
4. **Decision gate.** `backend/ai_policy.py` возвращает `none`, `fast`,
   `standard` или `premium`. При отсутствии существенного изменения токены не
   расходуются.
5. **Структурированный запрос.** В модель отправляются только изменившиеся факты,
   метрики портфеля и ссылки на источники, без полного необработанного потока.
6. **Структурированный ответ.** Модель обязана вернуть JSON фиксированной схемы:
   важность, факты, неопределённости, действие для пользователя и срок
   актуальности.
7. **Валидация.** Сервер отклоняет ответ без источников, с неизвестными активами,
   некорректными числами или чрезмерной уверенностью.
8. **Доставка.** Пользователь получает только полезную карточку; одинаковый
   вывод повторно не отправляется.

## Триггеры

- Один утренний обзор на торговый день, только если данные изменились.
- Один вечерний итог после завершения торговой активности.
- Покупка, продажа или существенное изменение денежных остатков.
- Рост концентрации, просадка, корпоративное событие или риск по активу,
  который реально есть у пользователя.
- Существенная смена рыночного режима, затрагивающая портфель.
- Восстановление ранее недоступных данных — быстрая перепроверка без уведомления,
  если итог для пользователя не изменился.

Критический риск обходит обычный cooldown. Остальные события объединяются в
один пакет, чтобы не запускать несколько анализов подряд.

## Модельные уровни Timeweb AI Gateway

Конкретные идентификаторы моделей задаются переменными окружения и берутся из
вкладки «Подключение» Timeweb, а не зашиваются в APK:

- `AI_MODEL_FAST` — самая дешёвая быстрая модель для классификации и сжатия.
- `AI_MODEL_STANDARD` — модель среднего уровня для ежедневных обзоров,
  диверсификации и ранжирования кандидатов.
- `AI_MODEL_PREMIUM` — сильная reasoning-модель только для критических и
  неоднозначных случаев.

Так можно менять Gemini, DeepSeek, GPT, Claude или другую доступную модель без
обновления Android-приложения. API-ключ хранится только на backend Timeweb.

### Конфигурация развёртывания

GitHub Actions передаёт настройки только на backend Timeweb:

- секрет `TIMEWEB_AI_TOKEN` — ключ AI Gateway;
- переменная `TIMEWEB_AI_BASE_URL` — обычно `https://api.timeweb.ai/v1`;
- переменные `AI_MODEL_FAST`, `AI_MODEL_STANDARD`, `AI_MODEL_PREMIUM` — точные
  идентификаторы моделей из вкладки «Подключение» Timeweb.

Ключ не должен попадать в Android APK, исходный код, логи, сообщения или
скриншоты. Если ключ или идентификатор нужного уровня отсутствует, AI-вызов
завершается до сетевого запроса и не расходует токены.

## Ограничение расходов

- Жёсткий дневной лимит ключа Timeweb и отдельные лимиты для дорогих моделей.
- Собственный серверный бюджет на пользователя и на весь продукт.
- Максимальный размер входного контекста и ответа для каждого уровня.
- Кэширование результатов по digest входных данных.
- Переход на более дешёвый уровень при исчерпании бюджета; автоматического
  повышения стоимости нет.
- Если бюджет закончился, алгоритмические предупреждения продолжают работать,
  а ИИ-анализ откладывается.

## Безопасность рекомендаций

Analyst AI показывает аналитику и варианты, а не гарантии доходности. До
включения автоматических персональных подборок должны быть определены профиль
риска, горизонт, допустимые валюты/рынки, ограничения по инструментам и правила
объяснения конфликта интересов. Торговые поручения не отправляются через
read-only токен.
